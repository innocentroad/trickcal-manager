# モモ分身の能力継承とDPS接続設計

2026-10-03。設計と部分実装の記録。xlsx・生成データは変更していない。

主人の集約済みダメージを流用せず、供給元を保持した能力・補正から召喚時の分身を組み立てる。既存の独立個体時計と共通命中計算を使い、Workerと同期計算の両方へ同じ純データを渡す。最初の対象はモモのPvE・時間寿命による分身で、他の召喚物を一括移行しない。

## 根拠と暫定条件

[Dotsのモモ報告](https://drive.google.com/file/d/13cigEyshNKZIX2jlxJWWJnh3xBQ7LDkQ/view)と[対応CSV](https://drive.google.com/file/d/1jEWiEfbssjOJRlG99hLlkrP_7-U8MMcQ/view)を再読した。旧nativeと提供更新マスターの解析であり、現行ゲームの完全再現を保証しない。

確認範囲は、主人由来の基礎能力、status/artifact/spell系の複製、statusコピーからのWorldRule・Augment除外、分身自身の基礎攻速150、BuildBaseStat直後の基礎物理・魔法Endが0であること。基礎Endと、実Unitの状態から計算する条件付きEnd枝は分ける。除外種別の存在だけから個々のサイト内効果の種別を推測しない。

当初の合意値は初回行動開始0Fだったが、追補後はraw生成と行動可能時点を分け、開始待ち0.4を明示する方針で実装を進める。モーション58F、行動内命中20F、補正なし周期120Fは維持する。観測121FとA2専用モーションへの流用は別の暫定記録である。時計の変換とサイト仮定は下記の追補実装節を参照。

状態コピーの全条件・寿命・参照先、後続End writer、実機更新順は未確定。これらは実装の穴を0や主人の最終値で埋める理由にはしない。

## 採用する計算経路

1. 計算画面で、育成後の基礎能力と各補正の供給元・適用条件を分離した入力を作る。
2. 実行開始時に入力の版・参照・必要な継承判定を検証する。
3. 各分身の生成イベントで、その時点の有効な主人側補正を確認し、継承可能なものだけ複製する。
4. 分身固有の基礎値・能力係数・複製状態を合成して個体状態を作る。
5. 命中時には分身を攻撃者、現在の敵を被攻撃者として共通命中計算を行う。
6. 終了時は個体を保持したまま自爆・状態付与を処理し、完了後に削除する。

主人側profileは本人の攻撃のために維持する。分身入力の作成元としてコピーしたり、最終期待ダメージから倍率を割り戻したりしない。

## 能力と効果の区分

| 区分 | 分身への扱い |
|---|---|
| 主人由来の基礎攻撃・会心等 | 解析で確認した能力ごとの組立式で取得。現在の主人最終能力と同一とは限らない |
| 分身固有値 | 攻速150などを生成定義から取得。主人の基礎攻速で置換しない |
| コピー対象のstatus | 生成時点で有効な状態を選別し、個体ごとに複製 |
| WorldRule・Augmentのstatus | 主人からの状態コピーから除外。他の直接付与経路まで全面無効化しない |
| artifact・spell | 確認したsnapshot経路に従う。サイトの「遺物」「スペル」という表示分類だけで全効果を継承可能としない |
| 基礎End | 確認した分身組立段階は0。後続入力を0へ消去しない |
| 条件付きEnd | 分身に有効な状態と現在の敵条件から評価。基礎Endと混ぜない |
| 生成後の主人へのバフ | 生存中の分身へ自動で同期しない。次の生成時にはその時点の有効状態を再評価 |
| 分身への直接バフ | 対象・発生時刻が解決できる場合だけ個体状態へ付与 |
| 主人のSP・命中時効果 | 帰属先が主人というだけでは共有しない。根拠を確認したbindingのみ接続 |
| 不明な供給元・寿命・適用条件 | 適用結果を変え得る場合は当該分身構成を未対応とする。不要な不明入力は停止理由にしない |

合成時の小数保持・丸め・攻速capは既存の確認済み計算順に従う。分身専用の未確認capや主人用の固定倍率を追加しない。

## Workerへ送るデータ

既存snapshotへ任意の `summonCalculationInput` を追加する。既存の保存設定そのものを増やすのではなく、毎回生成する計算入力である。以下は提案名で、現在のAPIではない。

- `schemaVersion` と `policyVersion`：入力形式と継承方針の版。
- `ownerBaseStats`：能力名・値・参照段階を持つ主人由来の能力入力。
- `contributions`：効果ID、供給元ID、所有者、補正値、対象、発動条件、native区分との対応根拠、継承区分、寿命方針。
- `definitions`：生成物IDごとの能力組立方針、固有能力、通常攻撃・自爆の効果IDと能力係数、対応するアサイド条件。
- `unresolved`：結果へ影響する未解決項目と停止理由。欠落値を0と区別する。

時間変動する補正は固定値のsnapshotとしてUIで先に確定しない。上記contributionsと既存runtimeEffectsが同じ安定IDを参照し、シミュレーターが生成tickで有効状態を読み取る。既に基礎能力へ取り込んだ補正を二重加算しないよう、各補正は一つの適用段階に所属させる。

継承区分は `copyAtSpawn`、`excludeFromOwnerCopy`、`directToSummon`、`unknown` を区別する。nativeの種別との対応は根拠付きの狭い変換表で管理し、表示名の文字列推測で決定しない。モモの状態コピーを「残り時間コピー」や「通常buffの再開始」と一律に扱わない。原値からの独立保持と、共有参照・条件評価を分ける。旧policy 1のremainingは汎用fixtureの互換境界であり、モモ仕様の根拠ではない。

JSON化・structuredClone可能な数値、文字列、配列、通常オブジェクトだけを使う。関数、DOM、Map、Set、原解析資料やローカルパスは渡さない。

`simulate` 内でこのデータから個体用の供給処理を作る。既存の `resolveSummonUnit` は独立fixture用の境界として残せるが、UI経路はcallbackの転送に依存しない。純データ入力とcallbackが同時指定された場合は曖昧な優先順位を設けず拒否する。simulateManyはseedごとに個体・状態を再作成し、共有入力を書き換えない。

## 実装の責務

| モジュール | 変更内容 |
|---|---|
| formation-damage-calc.js | 集約前の能力・効果内訳を取得し、召喚用入力を作る。createComparableDamageResultの結果だけから継承を復元しない |
| formation-damage-dps-prototype.js | 入力をsingle・aggregate双方へ渡す。入力fingerprintと比較投影にも含める |
| dps-simulator.js | 生成tickの選別・個体snapshot・命中入力・終了処理。既存の個体時計と命中丸めを共用 |
| dps-simulator-worker.js | 同じ純データを同じsimulateへ渡す。独自の継承式を持たない |
| dps-support-registry.js | 入力完備だけでなく、能力組立・終了効果・有効な構成の対応を確認して解除 |

新しい汎用戦闘エンジンや別Workerは作らない。複数スキルAI、PVP、全召喚物の統一仕様も今回作らない。

## 終了時の自爆と感電

現在のモモ定義は通常命中のほか終了時自爆・感電を持つ。既存コードは終了ダメージを分身側へ渡す入口を持つが、非ダメージ状態効果は例外になる。能力継承だけ接続して停止解除すると12秒終了時に失敗するため、同じ実装範囲で対応する。

設計上の終了手順は「通常攻撃の予約を止める→分身入力で自爆を一度計算→感電と持続時間を既存状態異常経路へ渡す→個体を削除」。時間寿命の終端と同tickの通常命中は除外する。自爆は死亡後でも必要な個体snapshotを参照できるよう保持する。終了・削除を二度行わず、敵へ付与済みの状態は個体削除と一緒に消さない。

キャンセル、上書き、被弾による終了を一律に自爆としない。被弾の入力がない計算は時間寿命のみ評価する暫定構成とし、その制限を表示する。被ダメージ回数3を「3回攻撃したら死亡」へ変換しない。自爆のイベント遅延や発動順が未確認の場合、現行xlsxの終了時0Fはサイトの暫定仮定として扱い、必要なら実装前に利用者へ提示する。

通常攻撃の補正分類、自爆の分類、召喚元への集計帰属は別の値で管理する。低学年由来の分身だからという理由だけで、全命中へ低学年専用補正を付けない。A2自爆係数は該当効果IDから取り、通常攻撃まで3倍にしない。

## 保存と比較

追加の手入力・所持データ・継承設定の保存キーは作らない。計算設定を読み込んだ後、現在の育成値・効果・生成定義から召喚入力を再構築する。

実行時の入力fingerprintには召喚入力とpolicyVersionを含める。旧比較結果は同じ版の結果として再利用しない。旧エクスポートに召喚入力がなくても既存設定を読み込めるが、新しい結果は再計算する。丸め版・保存版を無関係に一括変更せず、実装時に影響する結果版と比較契約だけ更新する。

## 実装順序と再開条件

第一段階で、能力組立式と各効果の供給元対応表を作る。主人基礎値、装備snapshot、分身固有値の各欄を区別し、対応が閉じていないものは列挙する。新シートの追加や利用者へnative種別の入力を求める前に、既存マスター・効果行から取得できる範囲を確認する。

第二段階で純データ入力・生成tickでの選別・Worker接続を実装し、独立fixtureで通常命中を検証する。この段階ではモモの実画面対応を解除しない。

第三段階で自爆・感電・比較・画面を接続し、PvEの時間寿命構成を暫定対応として解除する。生存中の継承状態の条件・寿命、能力組立式、必要なダメージ分類が解決できない構成は未対応のまま。全設定を一括解除しない。

優先検証は次のとおり。

- 同時生成個体の状態を分離し、後から主人だけへ加えたバフが生存個体へ移らないこと。次の生成では有効状態を取得すること。
- WorldRule/Augmentのコピー除外と、分身への独立した直接付与を混同しないこと。
- 基礎攻速150・58F・20F・初回0Fで20/140/260Fに命中し、121F観測や主人の攻速を周期へ混ぜないこと。
- 生成時点で失効したバフ、同tickの発動・生成、途中の分身への加速、捕捉済み待機の保持を明示した順序で検証すること。同tick順序はサイト側モデルと実機未確認を区別すること。
- 基礎End0と条件付きEndを区別し、現在の敵防御・被ダメージ状態を命中時に評価すること。
- 自爆は一度だけ、通常命中は寿命終端に出ず、感電が個体削除後も定義された期限まで残ること。
- Workerとfile://同期経路で同一seed・同一入力の結果が一致し、複数seed間に状態が漏れないこと。
- 入力の欠落、不明供給元、旧比較版で誤った数値を表示せず、他使徒のDPS・既存保存に回帰がないこと。

## xlsxの扱い

現在の時刻・モーション入力は足りている。初期実装のために追加シートや列を利用者へ要求しない。能力組立の参照元や既存効果の分類が不足していると判明した場合だけ、不足セルに限定したTSV案を別途作る。設計のためにxlsx、生成器、生成JSを変更しない。

## 設計時点で残る確認

この文書は入力と責務の設計を確定するもので、能力ごとの係数や全効果のnative種別対応を確定したものではない。実装前に、Dotsの命令根拠とアプリの効果内訳を照合した対応表が必要になる。状態寿命、通常攻撃・自爆の補正分類、終了ダメージ遅延の未確認部分を隠して実装しない。

## 2026-10-03の実装結果

最初の実装では第二段階の純データ入力、個体ごとの継承状態、Workerへの転送、比較入力への組み込みをローカル実装した。終了時の自爆と、継続ダメージを伴わない状態付与も接続した。この時点のシミュレーター版は30で、後述の追補対応により31へ更新した。保存キー・xlsx・生成器・生成データは変更していない。

実装した入力はschemaVersion 1／policyVersion 1で、定義ごとに `assemblyMode=resolved-hit-v1`、独立した命中入力、速度、根拠付きの補正内訳を要求する。この段階の命中入力は**能力を組み立て済みの独立入力**であり、nativeの能力組立式を実装したという意味ではない。補正内訳で扱えるのはdamageRate・endCorrection・additionalCoefficientとattackSpeedPの解決済み差分に限る。

旧policy 1の独立fixtureでは生成時に有効なcopyAtSpawnだけを個体へ取り込み、残り期限を保持した。これは追補で判明したモモの状態保持規則とは異なるため、モモ用policy 2では原値・独立保持の指定を要求する。WorldRule/Augmentは主人からのコピーを拒否し、分身への直接付与とは区別する。directToSummonの明示的な時刻指定は評価できるが、既存runtimeEffectsとのID接続・未解決の発動条件は未対応として拒否する。

終了時は独立命中入力で自爆を計算し、非継続の状態付与を既存状態異常処理へ渡す。寿命終端の通常命中は出さず、自爆は通常命中と別の命中IDで扱う。終了後に遅延する効果と分身自身を攻撃者とする継続ダメージは未対応として実行前に止める。

計算画面は選択中の補正内訳を重複除去して診断用入力を作り、未確定の継承をunknownとして保持する。主人の表示能力やダメージprofileで分身の能力を埋めていない。このため**実マスターのモモはDPS未対応のまま**で、全面実装完了とは扱わない。

残作業は次の2点である。

- 主人基礎値・装備snapshot・分身固有値から各能力を組み立てる係数と参照元の確定。
- 現アプリの各補正とnative種別・継承条件・寿命の対応、および実行中runtimeEffectsとの接続。

感電を継続ダメージとして残課題に挙げた記述は誤りだったため訂正する。現シミュレーターも感電をKNOWN_NON_DAMAGE_STATUSESに分類しており、DOT_STATUS_MULTIPLIERSには含めていない。モモの生成データは感電付与と持続時間2秒を持つ。感電は敵の攻撃速度を低下させる非ダメージのデバフとして扱い、付与・期限の保持と、敵の行動時計へ攻速低下を反映する処理の保証は区別する。後者は今回確認していない。感電ダメージの能力入力は不要で、継続ダメージ未接続を理由にモモを止めない。一般の召喚物が継続ダメージを付与する場合の未対応ガードは別件として残す。

現在のモーション・命中時刻のxlsx入力を再編集する必要はない。上記は既存解析の命令根拠と効果データの照合で解決する課題で、未確定値を利用者入力の既定値に置き換えない。

`tools/test-summon-pure-data.js`で入力拒否、コピー除外、状態期限、後付け主人バフの非同期、個体分離、自爆・状態付与、実Workerスクリプトと同期経路の一致、複数seedの分離、実UI入力関数と比較投影を検証した。これは独立fixtureであり、ゲーム実測や実ブラウザ表示の確認ではない。召喚時計・対応判定・既存runtimeEffects・命中丸め・エピカA2・DPS統合・計算画面fixtureも通過した。

編集前のdirtyを含む復元元は `backups/summon-pure-data-20261003-01/SHA256SUMS.tsv`（親trickcal配下）に記録。データ生成・commit・push・公開は行っていない。

## Dots追補の取り込みと追加実装

[追補報告](https://drive.google.com/file/d/1quYg8jB0GEUpNpZJMKRI5L5SAR--qtF4/view)、能力組立CSV、継承規則CSV、終了生成規則CSV、独立計算例を確認した。ZIPの取得は認証／TLSエラーで失敗し、詳細ASMとresearch各節は今回ローカルへ取得できていない。報告を読んだことと証拠ZIP全体の照合を完了したことを区別する。

policyVersion 2とassemblyMode `momo-abilities-v2`を追加した。主人の育成合成済み基礎8能力×分身倍率を入力とし、解決済みの固定・率・共通攻撃／防御補正を合成、小数3桁ToEvenで丸める。HPは分身固定値を整数化して下限1、攻速は分身基礎に対する固定・率補正を合成してRound3後に明示的な上下限へ収める。攻速率を既存speed.attackSpeedPへ重複入力することは拒否する。命中時には分身の魔法攻撃・会心とenemyTimelineの現在値から共通命中入力を作り、主人のダメージprofileは使わない。

copyAtSpawnの状態はvalueStage `origin`／lifetimePolicy `detachedOrigin`を要求する。コピー時の有効性は主人側時刻で選び、選択後は主人の元期限だけでは失効させない。これは解決済み原値の保持モデルであり、全native条件を実装したという意味ではない。スペルの共有値は純データの時刻別sharedValuesを命中時に参照でき、複製時に確定したmultiplierは後から主人のCountへ追随させない。requiresOwnerAliveの枝はownerAliveIntervalsを照会する。他の状態まで主人死亡時に消すことはしない。実runtimeEffectsの共有writerへの接続と、個別遺物handler・procの継承は未完了である。

executionRulesで逐次生成・初動待ち・上限を保持する。生成間隔は `generationIntervalSeconds`／`generationClock=unityScaledSeconds`／`gamePlaySpeed`を明示し、ゲームFへ変換する。個体番号ごとの元の生成時刻と終了イベントを同じ差分だけずらす。寿命は各個体のraw生成から計測し、攻速で短縮しない。初動はinitialDelayFramesで別に保持する。1倍サイトモデルでは0.4を24F、個体間0.2を12Fとして検証したが、初動gateの時計・coroutine量子化を全加速条件で確認したとはしない。通常モーション58F・命中20F・周期120Fは維持する。
