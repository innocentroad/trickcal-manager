# 戦闘シナリオ・比較機能設計

更新日: 2026-08-08
状態: Phase 3の一時基準比較に加え、保存済みダメージ計算・ステータス保存スロット・保存編成の比較元接続を試験実装済み。

現行UIでは、ステータス保存スロットについて「使徒育成」「編成内容」「カード育成」を個別に比較範囲へ指定できる。保存スロット選択時は使徒育成のみを初期選択し、ダメージ計算内だけの一時編成・一時カードはスロットへ含まれないことを案内する。保存編成は編成のみ、保存済み計算は保存時の計算結果一式を比較元とする。戦闘条件・効果設定を任意の比較元から部分適用する機能は今後の拡張対象。

保存スロットには比較再現用として軽量化した現在・予定ステータスを保持する。形式バージョンと固定キー順を持つ数値配列で保存し、ステータス管理・ダメージ計算の読込時に従来のスナップショット構造へ展開する。旧形式スロットは、保存済み育成設定と現行設定が一致する使徒に限り、現行の計算済みステータスから補完する。一致せず補完できない場合は誤った基礎値比較を行わず、再保存を案内する。

### 現在の実装状況

- `combat-scenario.js`に、共通シナリオの生成、正規化、JSON往復、意味内容の指紋生成を実装した。
- 比較対象レイヤーだけを比較元から差し替える`materializeComparison()`を実装した。
- ダメージ計算画面から現在状態を取得する`captureCombatScenario()`を実装した。
- 単発計算スナップショットとDPSスナップショットへ同じ共通シナリオを接続した。
- `sessionStorage`を使った「現在を基準固定」を実装し、同じタブで単発計算からDPS画面へ基準を引き継げるようにした。
- 単発計算では通常、会心、期待値、会心率、防御係数を基準と比較し、DPSでは基準時の行動プロファイルを同じ計測時間・seed群で再評価する。
- DPS画面上部と計算設定内の基準操作は、同じ比較セッションへ保存・解除する。
- ダメージ計算の保存メニューに「比較」を追加し、保存内容を読み込まずに単発比較の基準として使用できるようにした。
- 新しいダメージ計算保存はスナップショットversion 4としてDPS用行動プロファイルも保持し、同じタブでDPS比較へ引き継げるようにした。
- version 3以前の保存は単発比較に使用できる。DPS用行動プロファイルを持たないため、DPS比較は利用不可として扱う。
- 計算保存の既存`view`、`inputs`、`referenceState`は維持し、共通シナリオを重複保存しない。比較時に保存スナップショットから共通シナリオへ変換する。
- ステータス管理スロットと保存編成を比較元にする機能を実装済み。比較詳細ではステータス、使徒育成、編成、カード育成、現在行動の効果差分を表示する。
- 単発比較の選択行動は基準へ固定せず、現在選択中の行動へ追従する。基準側は保存したスキルレベルなどから同じ行動を再評価する。

## 1. 目的

ダメージ計算とDPSシミュレーションで、同じ比較元・比較範囲を利用できる共通基盤を作る。

対象となる主な用途は次のとおり。

- ボードの現在状態と予定状態を比較する。
- ステータス管理の保存スロットと現在状態を比較し、使徒育成による変化を確認する。
- 保存編成と現在編成を比較し、編成、遺物、スペル、教主の権能による変化を確認する。
- ダメージ計算の保存状態と現在設定を比較する。
- 現在の計算状態を一時的な基準として固定し、その後の変更と比較する。
- 同じ比較条件を単発ダメージとDPSの両方で評価する。

比較機能は保存形式ごとに個別実装しない。各保存元を共通の戦闘シナリオへ変換し、比較範囲に応じて基準側シナリオを構築する。

## 2. 非目標

初期実装では次を対象外とする。

- 比較画面から任意のバフを新規作成する機能。
- 「10秒間、攻撃力+20%」のような、datasheetに存在しない仮想効果の挿入。
- 過去バージョンの計算コードやdatasheetを完全に内包した厳密な歴史再現。
- 異なる使徒や異なる行動の結果を、常に同条件比較として扱うこと。
- すべてのDPS時限効果が実装されるまで比較機能全体を停止すること。

バフやデバフは比較入力として直接作成しない。使徒育成、編成、カード、戦闘条件、効果トグルなどの元データから再構築し、その差を比較結果として表示する。

## 3. 用語

### 3.1 戦闘シナリオ

単発ダメージまたはDPSを評価するために必要な、画面から独立した状態の集合。DOM要素への参照を持たず、JSONへ保存可能であることを条件とする。

### 3.2 基準側

変更前として扱うシナリオ。画面上では「基準」と表記する。

### 3.3 変更後側

現在の編集内容を反映したシナリオ。画面上では「現在」または「変更後」と表記する。

### 3.4 比較元

基準側へデータを供給する保存スロット、保存編成、保存計算、ボード現在状態、一時固定状態など。

### 3.5 比較範囲

比較元から基準側へ反映するレイヤー。比較対象外のレイヤーは変更後側と同じ状態を使う。

## 4. 基本方針

比較は次の2軸に分離する。

```text
比較元 × 比較範囲
```

例として、ステータス管理スロット1から「選択使徒の育成」だけを比較する場合、基準側は次のように構築する。

```text
使徒育成       = スロット1
編成・カード   = 現在状態
戦闘条件       = 現在状態
計算上の仮定   = 現在状態
DPS設定        = 現在状態
```

これにより、古い保存スロットに含まれる編成やカード状態が、キャラ成長比較へ意図せず混入することを防ぐ。

### 4.1 比較範囲と評価方針の分離

比較範囲は「どの状態を基準から取得するか」を決め、評価方針は「その状態をどの行動で評価するか」を決める。選択行動と、選択行動から解決された倍率・ダメージ結果を同じ固定データとして扱わない。

一時基準比較の既定方針は次のとおり。

| 評価対象 | 行動の扱い | 基準側で保持するもの |
|---|---|---|
| 単発ダメージ | 現在選択中の行動へ追従 | 使徒育成、スキルレベル、編成、カード、戦闘条件、効果設定 |
| DPS | 基準・現在とも全行動を評価 | 各側のスキルレベルから生成した全行動プロファイル |

単発比較では、基準固定後に低学年から高学年へ切り替えた場合、基準側も高学年へ切り替える。ただし倍率は保存時の解決済み数値を流用せず、基準側のスキルレベルに対応する高学年倍率を使う。

```text
基準固定時: 低学年Slv1 / 高学年Slv1
現在状態:   低学年Slv15 / 高学年Slv15

低学年選択時: 基準Slv1の低学年 → 現在Slv15の低学年
高学年選択時: 基準Slv1の高学年 → 現在Slv15の高学年
```

将来、異なる行動同士を意図的に比較する用途が必要になった場合のみ、評価方針として`fixedBaselineAction`を追加する。初期値は常に`followCandidateAction`とする。

## 6. 推奨データモデル

```js
CombatScenario {

  sourceMeta,

  actors: {
    self,
    enemy
  },

  characterState,
  formationState,
  cardState,
  battleConditions,
  effectAssumptions
}

DpsSimulationOptions {
  durationSeconds,
  seed,
  trials,
  initialActionDelayFrames,
  highSkillMode,
  battleSpeed
}

ComparisonDefinition {
  baselineSource,
  candidateSource,
  scopes,
  actorScope,
  evaluationPolicy,
  evaluationModes,
  dpsOptions
}
```

```js
EvaluationPolicy {
  singleAction: 'followCandidateAction',
  dpsActions: 'all',
  unresolvedAction: 'disableComparison'
}
```

解決済みスキル倍率や単発ダメージは評価キャッシュであり、比較定義の正本ではない。基準側のスキルレベルと安定した行動識別子から再生成する。現段階では再計算済みの全行動プロファイルを基準セッション内にキャッシュし、現在の行動識別子に対応する結果を選ぶ。

`CombatScenario`には表示状態、開閉状態、スクロール位置など、計算結果へ影響しないUI情報を含めない。

## 7. シナリオ生成API

最終的には次の責務へ分離する。

```js
captureCombatScenario()
materializeScenario(source)
applyComparisonScopes(candidateScenario, sourceScenario, scopes)
evaluateSingleAction(scenario)
simulateDps(scenario, simulationOptions)
```

### 7.1 captureCombatScenario

現在画面、ステータス管理状態、編成、カード、計算設定から、変更後側の共通シナリオを生成する。

現行の`createDpsSnapshot()`はこの処理の試作として扱い、DPS専用情報と共通情報を段階的に分離する。

### 7.2 materializeScenario

保存元ごとの形式を共通シナリオへ変換する。保存元そのもののデータ構造を統一する必要はない。

### 7.3 applyComparisonScopes

変更後側を複製し、選択された比較範囲だけを比較元の値で置換して基準側を作る。

```js
const baseline = cloneScenario(candidate);
overlayCharacterGrowth(baseline, source, actorScope);
```

この方式により、比較対象外の条件はA/Bで同一になる。

## 8. 比較元アダプター

```js
scenarioFromPinnedState(snapshot)
scenarioFromStatSlot(slot)
scenarioFromFormationSave(save)
scenarioFromDamageSave(save)
scenarioFromBoardState(current, planned)
```

比較元ごとに利用可能な範囲を定義する。

| 比較元 | 使徒育成 | 編成 | カード | 戦闘条件 | 計算設定 |
|---|---:|---:|---:|---:|---:|
| 一時基準固定 | ○ | ○ | ○ | ○ | ○ |
| ステータス管理スロット | ○ | ○ | ○ | △ | × |
| 保存編成 | × | ○ | ○ | × | × |
| ダメージ計算保存 | ○ | ○ | ○ | ○ | ○ |
| ボード現在／予定 | ボードのみ | × | × | × | × |

保存元に存在しない範囲はUIで無効化する。

## 9. 比較プリセット

初期UIでは次のプリセットを提供する。

### 9.1 キャラ成長

選択使徒の使徒育成レイヤーだけを置換する。編成、カード、戦闘条件、効果トグルは変更後側と共通にする。

対象範囲は将来的に次から選択可能にする。

- 選択中の攻撃使徒
- 防御側使徒
- 攻撃側編成全体
- 両陣営

初期値は「選択中の攻撃使徒」とする。

### 9.2 編成・カード

編成、配置、遺物、スペル、教主の権能を置換する。各使徒の育成状態は変更後側の現在値を使う。

編成変更によって発生するシナジー、編成スキル、カード効果は両シナリオで再構築する。

### 9.3 戦闘条件

敵、行動、ダメージ種別、相性、PvP、追加補正などを置換する。

### 9.4 計算設定

既存効果の手動ON/OFF、スタック数、一時設定などを置換する。

### 9.5 すべて

比較元が保持している全レイヤーを使用する。

### 9.6 詳細設定

各レイヤーを個別に選択する上級者向け設定。初期実装には含めなくてもよい。

## 10. 効果の扱い

最終的なバフ合計や適用済み効果一覧を比較元から直接コピーしない。次の元データから毎回再構築する。

- 使徒とスキルレベル
- アサイド
- 編成と性格シナジー
- 遺物、スペル、愛用カード
- 教主の権能
- 戦闘条件
- 効果トグルとスタック数

これにより、datasheet更新や効果判定修正後も、両シナリオを現行ルールで再評価できる。

効果差は比較入力ではなく分析結果として表示する。

```text
追加された効果
削除された効果
数値が変化した効果
発動条件が変化した効果
DPS上の稼働率が変化した効果
```

## 11. 単発ダメージ評価

```js
evaluateSingleAction(scenario)
```

最低限、次を返す。

```js
SingleActionResult {
  normal,
  critical,
  expected,
  criticalRate,
  defenseRate,
  detail,
  appliedEffects,
  excludedEffects
}
```

現行の`calculateDamage(context)`は画面状態への依存がある。初期段階ではシナリオから一時的な計算コンテキストを生成して既存処理を利用してもよいが、最終的にはDOMを書き換えずに評価できる形へ移行する。

## 12. DPS評価

```js
simulateDps(scenario, simulationOptions)
```

最低限、次を返す。

```js
DpsResult {
  totalExpectedDamage,
  meanDps,
  range,
  byAction,
  actionCounts,
  effectUptimes,
  stackHistory,
  timeline,
  warnings
}
```

### 12.1 同一seed比較

A/Bで同じ開始seedと試行数を使用する。ランダム強化攻撃などの偏りを減らし、設定変更による差を評価する。

### 12.2 DPS設定の固定

キャラ成長、編成、カード、戦闘条件の比較では、計測時間、seed群、高学年モード、初動をA/Bで共通にする。

DPS設定そのものを比較する場合のみ、DPS設定を比較範囲へ含める。

### 12.3 速度データ未登録

速度データがない使徒でも比較機能全体を停止しない。

```text
単発ダメージ比較       利用可能
行動別適用効果比較     利用可能
DPS・発動回数比較      利用不可
タイムライン比較       利用不可
```

利用できない項目には理由を表示する。

### 13.3 差分表示

表示方向は常に次で統一する。

```text
変更前 → 現在
```

```text
期待値 1,100,000 → 1,250,000  +13.64%
```

色は単純な数値の増減だけでなく、攻守視点を考慮する。防御側被ダメージなど、値の減少が有利になる項目では評価色を反転する。

## 14. 比較可能性の判定

比較前に条件差を検査する。

### 同条件

同じ使徒、敵、行動、攻守視点、ダメージ種別で比較する。通常表示とする。

### 一部条件違い

使徒、敵、行動などが異なる。計算は許可するが、結果差に複数要因が含まれることを警告する。

### 計算不能

使徒ID、カードID、敵プリセットなどが現行データで解決できない。保存時結果が存在する場合は参考値として表示し、再計算結果と区別する。

## 15. 保存時結果と再計算結果

保存計算には次の両方を保持する。

- 保存時に記録した結果
- 保存状態を現行コードで再計算した結果

通常の比較には再計算結果を使用する。保存時結果との差がある場合は次を表示する。

```text
保存後のデータまたは計算式変更により、保存時結果と再計算結果が異なります。
```

保存データには将来的に次を追加する。

- シナリオschemaVersion
- datasheetまたは生成データのrevision
- 計算コードのrevision
- 保存時結果

初期段階では、過去の生成済みスキル・カード定義を保存データへ完全複製しない。

## 16. UI案

一時基準比較は計算設定から分離し、結果バー右上の専用フロートとして配置する。通常時は「比較」、開始後は「比較中」と表示し、アイコンだけに依存しない。

```text
[保存] [比較] [計算]
       ↓
変更前と比較
今の育成・編成・計算設定を「変更前」として記録します。
このあと設定を変えるとダメージ差を確認できます。
[現在を変更前として記録]
```

ボード現在／予定切り替えは比較フロートから独立させ、「ボード・追加クレヨン」欄へ配置する。予定を選んだ場合は、予定ボードを反映した最終ステータスを使用するとともに、現在から増減する特殊マスの全体補正率と上級マスの全体加算値を同欄へ表示する。手動入力の追加クレヨンは別項目として維持し、予定値を入力欄へ複写して二重加算しない。

比較開始後は同じフロート内で状態確認、更新、終了を行う。

```text
● 比較中
変更前: アメリア / 低1・高1・パ1
現在選択中の行動を変更前のSlvでも計算します。
[変更前を現在の状態に更新] [比較を終了]
```

通常の結果欄も括弧だけで変更前を示さず、ラベルを明記する。

```text
期待値
16,760
変更前 15,236
+10.00%
```

保存スロットなどを比較元にする将来の詳細設定は、専用比較フロートから次の設定UIへ展開する。

```text
比較元
[ステ管理 スロット1 ▼]

比較内容
[キャラ成長] [編成・カード] [戦闘条件] [計算設定] [すべて]

対象
[選択使徒のみ ▼]

[比較開始]
```

比較開始後はコンパクト表示にする。

```text
比較中
スロット1 → 現在
キャラ成長 / シオン
[設定] [入替] [解除]
```

保存データの「読込」と「比較元として選択」は別操作にする。比較開始だけでは現在画面の設定を変更しない。

「ボード・追加クレヨン」欄の現在／予定切り替えは簡易操作として残し、内部では共通比較基盤を利用する。

比較開始時は選択中のボード状態だけでなく、対象使徒の現在・予定双方の反映後ステータスを基準スナップショットへ保存する。比較中に現在／予定を切り替えても基準側は保存時の選択と数値を維持し、変更後側だけを再評価して差分を表示する。これにより、比較開始後のボード切り替え自体を比較対象として扱える。

## 17. 画面間の引き継ぎ

ダメージ計算とDPSは別HTMLであるため、比較定義を同一タブ内で引き継ぐ。

- 保存された比較元: `localStorage`
- 現在選択中の比較定義: `sessionStorage`
- 一時基準固定シナリオ: `sessionStorage`
- DPS計測条件: DPS側の設定または比較定義

`sessionStorage`を使うことで、同じタブでHTML遷移した場合は比較を維持し、別タブの作業状態とは分離する。

保存スロットの共有・競合管理は[複数タブ状態管理設計](multi-tab-state-design.md)に従う。比較機能は保存スロットを読み取り専用で参照し、比較開始時にスロットを上書きしない。

## 18. 実装段階

### Phase 1: 共通シナリオ

1. 現行`createDpsSnapshot()`の共通部分とDPS固有部分を整理する。
2. `captureCombatScenario()`を定義する。
3. 現行単発計算とシナリオ経由計算の結果一致を確認する。
4. シナリオのJSON往復で結果が変わらないことを確認する。

### Phase 2: DPS接続

1. DPSシミュレーターへ共通シナリオを渡す。
2. 静的な行動別適用効果を共通シナリオから生成する。
3. 速度データ未登録時の部分評価を維持する。

### Phase 3: 一時基準比較

1. 現在状態を基準固定する。
2. 単発ダメージをA/B評価する。
3. DPSを同一seed群でA/B評価する。
4. 主要な設定差と効果差を表示する。

### Phase 4: 保存元接続

1. ボード現在／予定を共通比較へ移す。
2. ステータス管理スロットを接続する。
3. 保存編成を接続する。
4. ダメージ計算保存を接続する。

### Phase 5: 時系列効果

1. 持続バフの発動と終了を評価する。
2. 効果稼働率を比較する。
3. スタック推移を比較する。
4. SP、CT、攻撃速度変化による行動回数差を表示する。

## 19. 初期受け入れ条件

- 比較開始で現在の入力状態が書き換わらない。
- 一時基準固定後に行動を変更すると、基準側も同じ行動へ追従する。
- 行動追従時の基準倍率は保存時の選択倍率ではなく、基準側スキルレベルから解決される。
- 基準固定後にスキルレベルを変更しても、基準側のスキルレベルは変化しない。
- 比較解除で通常表示へ完全に戻る。
- ボード現在／予定の既存計算結果と共通比較化後の結果が一致する。
- 同一シナリオ同士の比較結果がすべて差分0になる。
- 選択使徒のキャラ成長比較で、編成、カード、敵、手動トグルがA/B共通になる。
- 編成・カード比較で、使徒の育成状態がA/B共通になる。
- 編成変更によるバフ差が元データから再構築される。
- DPS比較でA/Bへ同じseed群が使用される。
- 速度データがなくても単発比較と行動別効果比較が表示される。
- 保存元に存在しない比較範囲を選択できない。
- 別タブの一時比較状態と混線しない。
