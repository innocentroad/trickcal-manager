## 目的・範囲・権限

目的はC1（保存台帳の正確性）とC2の変更前挙動基準の不足を閉じ、Gate A/Bへ事実を渡すこと。保存動作の改善ではない。一人のLunaで実施する。

- 変更可能: tools配下の保存検出器、保存基準テスト、隔離fixture、保存台帳、関連文書。検証依存の追加は必要性・lock・再現手順を記録する。
- 禁止: アプリ保存コード、datasheet、生成物、公開・配信設定の変更。S2、commit/push、自動実行Goalの有効化も行わない。
- 着手時のdirty一覧と対象ファイルの差分／ハッシュを記録する。終了時はHEADとの差分だけでなく着手時と比較し、既存の利用者変更と今回の変更を区別する。広範囲の復元や削除は禁止。
- 本書作成時点では文書のみ変更。新しい実装・ブラウザ検証は未実施。

## 固定する判断

### D1: 呼出し列挙ではなく、認識した参照の全用途を分類する

storage参照と登録済み保存helper参照について、スコープのbindingを識別し、各利用を「解決済みアクセス」「追跡済み別名」「契約照合済み引渡し」「保存に無関係と根拠付きで判定した用途」「未対応」に分類する。未分類・未対応の参照が一つでも残れば検査全体を失敗させる。

- 現行のスコープ解析・静的解決を再利用する。一般JSの完全なデータフロー解析は作らない。
- rootはlocalStorage/sessionStorage、既存対応のwindow/globalThis経由・computed・optional形式、および契約のstorage引数／保存helper。shadowingされた同名変数をrootへ誤認しない。
- 追跡可能な単純別名は追跡する。宣言後代入や再代入で領域が確定しなければ未解決にする。引数名やメソッド名だけで任意オブジェクトをstorage認定しない。
- 未登録関数へstorageを渡す場合は引渡し地点で失敗させてよい。関数間解析を完成させる必要はない。既存の登録helperは引数位置・キー・領域の契約を検査する。
- オブジェクト／配列格納、分割代入、return、export、spread、未知関数への引渡し、helperのcall/apply/bind、storageメソッドの切出しは、正しく追跡する既存経路がなければその参照地点で未対応エラーにする。構文の追加ごとに後続アクセスまで追跡しない。
- export defaultはASTのdeclaration、returnはargumentなど実際のnode構造に従う。定義名文字列だけのhelper照合をしない。
- 存在確認など本番に必要な非アクセス用途は、AST形と理由を限定して認める。ファイル全体・名前全体を免除しない。反例を通すための例外登録は禁止。
- エラーにはfile、位置、式、理由を含める。可能なら固定診断コードを使い、テストを文章の一部だけに依存させない。

### D2: 本番と反例で検査入口を共通にする

`test-storage-baseline.js`の探索→解析→参照用途検査→helper契約→キー／領域／reader／writer／operation／failureMatrix／Pages照合を、共通実行入口から呼べるようにする。既存検査項目を落とさない。本番検査と反例で異なる簡略validatorを使わない。

本番ROOTは読取専用。ソースoverlayで既存ファイルの変異を渡してよいが、実ファイル探索と候補集合の合成を共通入口で行う。新規候補ファイルの検出は隔離一時ROOTへの実ファイル追加で別途確認する。一時fixtureも同じ公開候補探索を使い、全体検査のエラー結果／CLI非0終了まで確認する。自己テストが反例から再帰起動しないよう検査本体とテストrunnerを分離する。

反例は元の正規呼出しを残した追加変異とする。未使用契約エラーやfixture不足による偶然の失敗は不合格。元fixtureが成功し、狙った位置・理由の診断が出ることをassertする。

最低限の追加反例:

```js
function f(s) { s.clear(); } f(localStorage);
unknownConsumer(localStorage);
const box = { store: localStorage }; box.store.setItem('unknown', 'x');
// 以下は実image-preload.jsの既存正規呼出しを残して追加
const box = { read: readJson }; box.read('unknown');
const escaped = readJson; escaped.call(null, 'unknown');
// return / named export / default exportは適切な構文単位で個別検査
```

前設計のoptional/computed/template、連結、再代入、helper動的キー、領域違い、新writer、HTML、コメント、新規本番ファイルなども維持する。追加で配列格納・メソッド切出し・apply/bindを未対応として拒否し、無関係な同名オブジェクト／コメント／通常文字列を誤検出しないことを確認する。参照漏れを検証する反例は未知キーだけでなく既知キーでも試し、キー違反で隠さない。

### D3: イベントの結果と、経路の証明を分離する

ブラウザ実行前に必要なbrowser skillを読む。利用可能な機構が許す範囲で隔離ブラウザ環境／未使用ローカルOriginを使う。既存利用者OriginのStorage、Service Worker、キャッシュを消さない。

- storage event: 本番コードの起動前に隔離環境だけBroadcastChannelを利用不可にし、実際のStorage書込から別タブへ届くnative eventと本番clean更新／dirty保持を確認する。無効化が有効である証拠を残す。合成storage eventで代用しない。
- focus/visibility: 制御テストで実ハンドラーの判断と保存結果を確認し、さらに実タブ切替でnative eventと対応する本番結果を観測する。両タブvisibleのままなら実イベント確認は未達。
- pagehide: 制御テストでは実ハンドラーと実保存関数を使い、仮想時計でdebounce前のpending状態からflush、残存値、二重保存なしを確認する。実ブラウザではpending状態・イベント・書込順が観測できる場合のみpagehide経路を達成とする。通常保存やbeforeunloadが先に完了した離脱復元は統合結果としてのみ記録する。
- 観測用wrapperはテスト環境だけに置き、実ハンドラーへ委譲して例外・順序・返り値を変えない。独自保存ロジックで代用しない。使った観測／代替方法を記録する。
- native event発生と本番処理の結果の両方が必要。制御テストだけで元設計の実ブラウザ条件を完了にしない。仕組み上安全に観測できなければ未達を保持し、試行と次に必要な環境を報告する。
- 実ブラウザでの119/120ms精密境界やBroadcastChannel単独経路を新たな必須条件にはしない。119/120msは既存設計どおり仮想時計で検証する。

## 受入台帳を一本化する

次のスライス開始時に`docs/storage-s1-acceptance.md`を作る。元設計の各箇条書きを失わず以下の親IDの下へ子IDで展開する。親と子を二重に数えない。各行に条件、実入口、期待値、証拠（test/assertionまたは操作記録）、代替境界、判定を付ける。

| 親ID | 必須範囲 |
| --- | --- |
| DET-1 | storage参照・別名・未対応経路、正常入力の非誤検出 |
| DET-2 | helper定義・全参照用途・キー／領域契約 |
| DET-3 | 本番と同じ全検査経路での反例、新規候補探索、Pages照合 |
| INV-1 | 全reader/writer、領域・操作・呼出元、失敗経路の実コード照合 |
| BEH-1 | slot保存／再読込／削除、他slot、revision、失敗 |
| BEH-2 | 実loadのworkspaceあり／なし／破損とlegacy fallback |
| BEH-3 | 仮想時計のdebounce・119/120ms・flush・二重保存なし |
| BEH-4 | 実persistStateの正常／session／live／legacy失敗 |
| BEH-5 | 複数context、clean／dirty／stale、Lock代替範囲 |
| BEH-6 | 破損slot・旧形式の実移行と生データ書戻し |
| BEH-7 | 計算／敵／DPSの保存・削除失敗、メモリ・UI・再読込 |

判定は「達成／部分／静的確認のみ／未検証／阻害」のいずれか。実行が必要な条件を静的確認で達成にしない。条件の分割で進捗を水増しせず、最初に分母を固定する。変更する場合は理由と旧新対応を明記する。現時点の総達成数は未再集計であり0達成を意味しない。

既存persistStateテストは保持し、全Storageと通知を共通の観測ログで照合して領域をまたぐ順序、各既存値、revision、通知、返り値／例外の必須assertionが実在するか点検する。不足だけ追加する。

## 実施スライス

1. **受入台帳・検出器・統合反例**（DET-1〜3、INV-1の検査部分）: 条件の再集計、反例の現状再現、D1/D2実装。既存正常ケースを保持し、全検査経路で意図した拒否を確認。終了時点で次の見積もりを改訂する。検出器を一般JS解析へ拡大しない。
2. **実挙動の不足分**（INV-1、BEH-1〜10）: 既存証拠を台帳へ対応させ、不足しているDPS実起動・対象切替、実export/import、保存順序などだけ補う。実入口の判断関数をstub化しない。DOM・時計・通信等の境界代替は明記する。
3. **イベント検証と最終判定**（EVT-1〜3、記録整合）: D3に沿って実施。ブラウザ環境対応で独立した作業が必要なら4番目として切り出し、未達のまま再見積もりする。

各開始前に「作業」「対応ID」を明示。各終了後にSTATUSへ新規達成ID、累計達成子条件数／固定総数、具体的証拠、未検証・阻害、残り見積もりを記載する。3スライス連続で新規達成がほぼなければ追加実装せず再計画案を提示して停止する。暫定3〜4スライス。単なるテスト件数増を進捗に数えない。

## 終了時の検証・引渡し

- 基準テスト2本、全検査入口の変異テスト、変更JSの構文確認、`git diff --check`。依存変更時はlockと隔離クリーン導入も確認する。
- 検査成功だけで完了にしない。正常入力が成功し、全反例が狙った診断で失敗する証拠を残す。
- GOAL、STATUS、台帳、旧設計、ロードマップの現行記述を受入台帳と一致させる。撤回済みの数値・イベント経路断定を復活させない。
- F1はDET/INVの全条件、F2はBEH/EVTの全条件が揃って初めて完了。未達なら成果を保持してS1未完了と報告する。
- Gate A: 実行済みの部分失敗・書込／通知順・暗黙書込・競合と、イベント未検証の影響。Gate B: 実export範囲・旧形式／未知版・破損値・draft/mirrorの扱い。観測と将来の判断を分け、A/B契約を実装者が推測で確定しない。
- 実quota上限、複数キー完全復元、Origin転送は後続範囲。S1の分母に混ぜない。
- 結果・残条件・判断材料を報告して停止。S2、commit/push、自動実行Goal有効化には進まない。
