# datasheet TSV補助skillの出力修正案

作成日: 2026-09-11

状態: 個人skill `trickcal-datasheet-tsv` へ実装・配置済み（2026-09-11）。以下に設計判断を残す。

## 目的

説明文から、現在のdatasheetの列構造に一致する貼り付け用TSVを作る。列の追加・削除・並べ替えに対応し、既存値を保護する。xlsxの直接編集やアプリデータの再生成は対象外。

## 今回確認できた問題

シェルム試験生成時の回答に載せたTSVを、当時の対象シートのヘッダーと照合した。

| 行 | 回答中の実際の位置 | 本来の位置 |
| --- | --- | --- |
| `Sherum_low_e01` の `敵/範囲` | 18列目・条件 | 19列目・効果対象 |
| `Sherum_low_e03` の `自身周囲` | 30列目・Lv8 | 19列目・効果対象 |
| `Sherum_high_e04` の `領域内` | 17列目・適用条件値 | 16列目・適用条件種別 |

`Sherum_high_e04` は当時の必要列数と一致する37列でも内容がずれていた。末尾タブがコピー時に失われる可能性とは別に、回答テキスト自体に中間タブの誤りがある。「内部の列順は正しい」とした前回の報告は訂正する。

生成時の確認は、ヘッダー配列をmapした配列の長さを比較しており、シリアライズしたTSVの読み戻し検証ではなかった。また、ツールで生成したTSVと最終回答のTSVが一致していない。現在のskillにはヘッダー準拠・列数確認の指示はあるが、検証対象を実際の成果物へ固定する仕組みが不足している。

## 1. 読み取ったヘッダーを列定義とする

- 対象シートごとに現在のxlsxからヘッダーの名前・順序・実列位置を読み取る。列数 `N` はその列範囲から求める。10列・37列などの固定値をskillや生成処理へ埋め込まない。
- 書式だけ付いた右端のセルは列数に含めない。表のヘッダー範囲を使い、範囲が明示されていなければ最後の名前付きヘッダーまでを候補にする。範囲外にデータがあるなど曖昧な場合は、範囲を確定してから生成する。
- 途中の空ヘッダーを除去して左詰めしない。重複・空ヘッダーで列名との対応が一意にならない場合は、その位置を報告して確認する。
- 出力する値は列名で指定し、読み取った順序で配列化する。ヘッダーにない項目を黙って捨てたり、勝手に列を追加したりしない。
- ブックにアクセスできない場合は、ユーザー提供のヘッダーを列定義として使用し、その旨を示す。既存行差し替えには現在の対象行も必要。

## 2. 生成と検証を小さな補助スクリプトへ集約する

skill内に `scripts/render_tsv.py` を追加する案とする。説明文の解釈はエージェントが担当し、タブの組み立てと列対応の検証はスクリプトが担当する。

入力は「対象シート・操作種別・対象キー・列名と値」。ヘッダーは実行時に取得する。生成処理はxlsxをread-onlyで読み、TSVと貼り付け案内だけを今回専用の出力先へ作る。

手順:

1. 最新ヘッダーと既存対象行を取得し、列定義を確定する。
2. 既存行へ指定変更を適用するか、新規行を組み立てる。
3. 空欄・中間列・末尾列を保持し、TSVライターで文字列に変換する。
4. 実際に書き出したファイルをTSVパーサーで読み戻す。
5. 全行の列数が `N` であること、各列の値が生成前の期待値と一致することを確認する。
6. 成功したファイルと、読み戻した内容に基づくプレビュー・案内を提示する。

列数だけでは合格にしない。タブ・改行・引用符・Excel用テキスト化を処理した場合は、明示した変換後の期待値と比較する。数値セルを調整して列数を合わせたり、空欄を0で埋めたりしない。

## 3. ファイルとチャットの内容を一致させる

- 貼り付け用TSVファイルは列数によらず標準で作成し、UTF-8 BOM付きとする。ファイルはヘッダーなしのデータ行を既定とし、既存表への貼り付け用途を維持する。
- 確認用プレビューには列名を表示する。ヘッダー付きTSVを求められた場合は、ヘッダーを含むことと、貼り付け対象からヘッダー行を除く必要があることを明示する。
- チャットへ貼り付け用コードブロックを併記する場合は、検証済み成果物の文字列をそのまま用いる。タブを数え直して再作成しない。値を修正したら生成・読み戻し検証からやり直す。
- チャットのコピー結果が未検証なら、Excel貼り付けまで検証済みとは報告しない。ファイルもテキスト経由のコピーで末尾空欄が保たれることを保証するものではないため、取り込み・セル範囲コピー時の対象範囲を案内する。

前回の「ファイルは常にヘッダー付き」という提案は、貼り付け用データと確認用表示を区別する上記案へ変更する。

## 4. 追加と差し替えを操作単位で分ける

- `e01`かどうかでは判定しない。基礎設定は `id + skillId`、効果行は `id + skillId + effectId` など、そのシートのキーと既存ブックを照合して操作を決める。
- 新規追記と既存行差し替えは別のファイル・コードブロックにする。追加キーの衝突、差し替え先の不在・重複は確認事項にする。
- 差し替え対象が飛び飛びの行にある場合、連続して貼れると案内しない。連続範囲ごと、または対象行ごとに分ける。既存の他使徒行は出力対象に混ぜない。
- 案内には対象シート、操作、対象キー、貼り付け開始セル、読み取った列範囲・列数、データ行数、ヘッダー有無を含める。行番号は読み取り時点の情報であり、貼る直前に対象キーを確認する。
- 既存行は指定されていないLv値・条件・硬直などを保持し、元の行との差分も検証する。明示的な削除と未提示を区別する。

## 5. 形式検証と内容の確定を区別する

- 報告例は「形式確認: 読み取ったN列に全行一致、各列の値も一致。内容: 未確定項目あり」とする。
- 原文や既存対象行にない倍率・参照元などは推測しない。今回の原文にはシールド量の参照元がなく、`最大HP`と確定していた点も訂正対象。
- 不明値は下書きの確認事項へ残し、形式検証に成功したことを計算・DPS対応完了と扱わない。skillの形式検証ツールが成功したことも、生成TSVやExcel貼り付けの成功とは区別する。

## 修正対象

| 対象 | 変更案 |
| --- | --- |
| `SKILL.md` | 動的な列定義、補助スクリプトの利用、検証済み成果物を起点とした出力手順 |
| `references/conversion.md` | 読み戻し照合、追加/差し替えの判定、既存値保持、貼り付け範囲、未確定事項の扱い |
| `scripts/render_tsv.py`（新規） | ヘッダー取得、列名から行生成、TSV出力・読み戻し検証、操作別の出力と案内 |

生成器skill、xlsx、アプリの計算実装は修正対象に含めない。

## 完了条件

- 列の追加・削除・並べ替え後も、その時点で読み取ったヘッダーどおりに出力される。削除された列への入力は検出される。
- 中間タブがずれた行は、列数が同じ場合も列名と値の照合で検出される。今回のシェルムの誤出力を検証例にする。
- 中間/末尾空欄、明示的な0・FALSE、引用符、日本語を含む行が、読み戻し後も期待したセルに存在する。
- 既存のLv15だけを変更する例で、Lv1～14・条件などの既存値が維持される。
- 追加キーの衝突、存在しない差し替え先、非連続行を一括上書きする案内を防ぐ。
- 検証済み成果物と提示内容が一致する。Excel貼り付けを実施した場合は、その対象と確認範囲を報告する。未実施なら未実施と記載する。

## 実装・検証結果

- `SKILL.md` と `references/conversion.md` を更新し、`references/output.md`、`scripts/render_tsv.py`、`scripts/test_render_tsv.py` を追加。個人skillディレクトリへ配置した5ファイルが検証済み作業コピーと一致することをSHA-256で確認した。
- 補助スクリプトは最新ヘッダーから列を配置し、UTF-8 BOM付きTSVと `report.json`、`paste-guide.txt` を作成する。データ行のみが既定。非連続差し替えを分割し、既存出力ディレクトリを上書きしない。
- 一時ブックを用いた6テストが成功。列追加/削除/並べ替え、同列数のセルずれ、末尾空欄、引用符/改行、0/FALSE、既存値・数式保持、不正ヘッダー、未知列、キー衝突、差し替え先不在/重複、明示的な空欄化、非連続範囲、ユーザー提供データ、出力先衝突を確認した。
- 実datasheetをread-onlyで読み、シェルムの既存2行差し替え案・追加1行案で読み戻し検証が成功した。この時点の実測列数は37だが、処理に固定値として使用していない。この部分的な検証用下書きはシェルムの完成データではない。
- インストール先のskill形式検証と、インストール済みスクリプトによる成果物の再検証が成功。実際のExcel取り込み・貼り付け操作は未検証。xlsx・アプリ生成データは変更していない。
