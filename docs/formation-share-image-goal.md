# 編成画像＋URL共有：Luna向け実装Goal

更新日: 2026-09-12。状態: 現行スコープの実装・ローカルHTTP検証完了、`file://`利用時の案内を追加、画像＋URL共有UIは一時凍結、共有ページ側の画像操作を追加。実機／Discord受信は後続確認。実装メモは末尾に記録。

## 目的と範囲

GitHub Pagesの静的運用を維持し、編成共有モーダルから同じ編成のPNG画像と共有URLを用意する。利用者がDiscord等へ画像とリンクを投稿して相談できる状態を目指す。投稿そのものは利用者が行う。

既存の[共有URL格納仕様v1](formation-share-url-format.md)を維持する。サーバー、画像アップロード、短縮URL、動的OGP、Bot・Webhook、Discord認証、実投稿、取り込み、commit・push・公開は対象外。datasheet・生成データ・計算ロジックは変更しない。

## 表示・操作

既存の編成共有モーダルを拡張する。画像プレビューと操作のためのサイズ調整は可。受信ページの上バー等の再設計はしない。

| 操作 | 挙動 |
| --- | --- |
| 画像＋URLを共有 | 一時凍結。将来再開できるよう処理は残すが、現行UIには表示しない |
| 画像をコピー | PNGのみクリップボードへ。非対応・拒否時は画像保存へ案内 |
| URLをコピー | 既存のリンクコピーと失敗時の手動選択を維持 |
| 画像を保存 | PNGをダウンロード。非対応端末でも利用できる基本経路 |

PC向けに「画像を貼り付け、その後URLをコピーして同じ投稿に貼り付ける」程度の短い案内を添える。画像とテキストの複合クリップボードで両方が貼られることを前提にしない。「Discordへ投稿しました」とは表示しない。操作列は通常幅で画像系を左、URLコピー・閉じるを右に置き、狭幅では2段へ折り返す。

受信側の`formation-share.html`にも固定下部バーを置く。画像生成は利用者の操作で開始し、生成後に画像コピー・画像保存を有効化する。URLコピーは画像生成前から利用できる。受信ページの下部バーや上バーはPNGへ含めず、既存の`#share-content`だけを画像化する。

画像内容は現行の共有本文を正とする。配置、使徒、遺物、スペル、権能、★、A段階、はんだ、枚数、コスト、選択された全体%補正を含める。Lv・Rank・ALv・SLv・任意タイトル・共有メモは復活させない。上バー、操作ボタン、URL入力、URL文字列、QRコードは画像に含めない。

出力は幅1200px・内容に応じた高さのPNG。端末幅やdevicePixelRatioによって出力サイズを変えず、スマホでは同じ画像を縮小プレビューする。大量スペルは縦へ伸ばし、表示要素を黙って省略しない。テーマは生成時の共有プレビューと揃え、不透明な背景を明示する。テーマはURLに追加せず、URL受信側のテーマ一致は保証対象外。

## 既存接続先と責務

- formation-share-create.js：取得・URL生成・モーダル操作。更新時に一度だけスナップショットを取得する。
- formation-share.html / formation-share.js：共有URLを復元する現行描画。画像対象は原則 #share-content。現行の配置、画像、枠、★、ソートを再利用する。
- formation-share-prototype.css：既存共有ページの配色・配置。出力用の固定幅スタイルは通常閲覧に漏らさない。
- stat-dashboard.htmlと既存モーダルCSS：ボタン、プレビュー、進行・失敗表示。
- formation-share-codec.js / formation-share-catalog.js：既存v1を利用する。形式・辞書・IDを変更しない。
- PNG変換補助と対象テストは必要なら小さな独立ファイルへ分離。キャッシュ参照は実変更に応じて更新する。

URLを固定してその復号結果を描画・画像化する。同じURLから出力するために育成や全体補正を再取得・再計算しない。閲覧者の保存値を参照せず、保存データを書き換えない。

DOM/CSSを再利用する画像化方式を優先する。Lunaが小さな出力検証で方式を選定し、追加依存の版・ライセンス・容量を記録する。依存追加時はローカル同梱し実行時CDNへ依存しない。別の手描きcanvasレイアウトを並行維持する方式へ独断で拡大しない。

## 生成・共有の不変条件

1. 更新ごとに世代番号を割り当て、URL・描画・PNGを紐付ける。古いiframe loadや変換完了が新しい結果を上書きしない。
2. 更新・全体補正切替・テーマ変更でPNGを無効化する。生成中は画像操作を無効にし、新URLと旧PNGを組み合わせない。旧プレビューを残す場合は更新中と分かるようにする。
3. iframeのloadだけを画像準備完了とせず、当該世代の描画、画像decode、フォント準備を待つ。待機は有限にし、欠落画像は既存の代替表示、その他の失敗は明示エラーとする。
4. 同一世代のPNG Blobをコピー・保存・共有で再利用する。閉じる・更新時に不要な参照とObject URLを解放し、遅い完了結果を破棄する。
5. 同一世代のPNGを画像コピー・保存へ渡す。ネイティブの画像＋URL共有処理は将来再開できるよう保持するが、現行UIには表示しない。未対応時にも保存・URLコピーは使える。
6. キャンセル、権限拒否、未対応、生成失敗を区別する。共有メニュー終了を実投稿成功とみなさない。失敗してもモーダルと既存URLは利用可能にする。
7. canvas面積・高さ・PNGサイズの安全上限と待機期限を実装時の検証で定め記録する。超過時は切り捨て・白紙画像の保存をせず理由とURLコピー経路を示す。通常のゲーム内最大編成は出力できることを確認する。

| ID | 受入条件 |
| --- | --- |

| C2 | 幅1200pxのPNGに本文全体が入り、両テーマで使徒／カードサイズ、★、A段階、はんだ、コスト、枚数、補正値が判読できる。画像の欠落・切断・不要UIなし |

| C4 | ネイティブの画像＋URL共有は現行UIで凍結し、画像保存／画像コピーとURLコピーの個別操作で利用者が投稿を続けられる。実機・Discord受信は未確認として記録し、将来再開時に別途検証する |

## 実装スライス

| 順 | 次の1スライスで行うこと | 対応条件・終了根拠 |
| --- | --- | --- |
| 1 | 現行共有本文の固定幅PNG出力。方式の小検証、同一URLの描画、準備完了待ち、両テーマ・多数スペルの画像確認 | C1・C2・C5。実PNGと選定理由、安全上限を記録 |
| 2 | 共有モーダルへ画像プレビュー・保存・画像コピーを接続。URLコピー維持、世代管理、PNG再利用、失敗・更新・閉じる処理 | C1・C3・C5。正常／失敗／競合操作の対象テストと画面確認 |
| 3 | 個別操作と代替案内を接続。ネイティブ共有は凍結し、対象回帰・仕様・STATUSを整備 | C3〜C6、C1〜C5の最終確認。検証済み／未検証の一覧 |

各開始前に実施内容と対応完了条件を利用者へ宣言する。各終了時にSTATUSへC1〜C6の充足状況、達成度、根拠（テスト・画像・環境）、残りスライス見積もりを記録する。3スライス連続で実質的に進まなければ、局所作業を続けず再計画案を提示する。

## 検証範囲・停止条件

代表ケースは空編成、1／6／9人、空き位置の遺物、少数／全スペル、重複枚数、異なる育成、全権能、全体補正ON／OFF／不明、欠落画像。モーダルは360／390／430／1280pxと両テーマで確認し、PNGは実ファイルを開いて別途検査する。

既存 tools/test-formation-share-codec.js、変更JSの構文、追加した生成・操作の対象テスト、git diff --checkを基本とする。計算を触らない本GoalでDPS全回帰を無条件には実行しない。

PCの実ブラウザでコピー・保存を確認する。スマホ相当の幅エミュレーションをネイティブ共有の実機検証の代わりにしない。スマホ実機やDiscord受信の確認ができない場合は利用者へ検証を依頼し、C4未検証として残す。外部への投稿は明示許可なしに行わない。

DOM方式で重要な枠・★・画像の再現ができない、通常最大編成が安全に出力できない、サーバーやURL形式変更が必要と判断した場合は、根拠と代替案を示して再計画する。画像コピー非対応そのものは設計済みの代替操作で対応し、実装全体の停止理由にしない。

API確認先：[Web Share](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share)、[Clipboard.write](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/write)。実装時に対象ブラウザの現行仕様を確認する。

## 実装メモ（2026-09-12）

- 追加依存なしで、既存の共有URLを専用iframeへ読み込み、`#share-content`を幅1200pxに固定してSVG `foreignObject`からcanvasへ描画する方式を採用した。出力専用iframeは通常プレビューへ影響しない。
- `formation-share-image.js`に、iframe load後の画像・フォント準備待ち、2フレームのレイアウト安定待ち、12秒の待機上限、12000px高さ・2,400万px面積・12MB PNG上限、世代番号による古い結果の破棄を実装した。画像インライン化、HTML void要素のXML化、data SVG URLを用い、実ブラウザのcanvas汚染を回避している。
- `formation-share-create.js`へ画像プレビュー、PNG保存、画像コピー、URLコピーを接続した。画像＋URL共有の処理は保持するが現行UIでは非表示とし、生成中は画像操作を無効化して共有プレビューのテーマ変更を画像へ反映する。
- 生成する共有URLにはページ資材用の固定`v`クエリを付け、共有状態を保持するfragment形式は変更しない。内部の画像生成用`_sharePreview`クエリは公開URLには付けない。
- 全体補正表示は5列グループ（HP／攻撃／防御／会心／抵抗）へ変更した。攻撃・防御・会心・抵抗は各グループ内に2項目を収め、通常幅で表示高さを抑え、800px以下では2列へ切り替える。
- ローカルChromeで通常編成のPNG生成（1200×777px）、5グループのDOM、ライトテーマ、画像コピーの成功表示、保存操作を確認した。外部への共有・投稿は行っていない。
- 全スペル35枚・9人・権能2件の代表URLでもPNG生成（1200×1083px、645,280 bytes）を確認した。生成後に出力iframeが残って見えるCSS上書きも修正し、PNGプレビューだけが表示されることを確認した。
- 生成URLへページ資材版`?v=20260912a`を付け、古いHTMLキャッシュが現行共有描画を再利用しないようにした。`formation-share-codec.js`のfragment生成仕様は変更していない。
- 一時検証ページで正常生成、`maxHeight`超過の`height-limit`、即時`cancel()`の待機終了を実ブラウザで確認した。状態表示は画像外へ置き、PNG内容の最下部を隠さないようにした。
- 非対応端末向けの個別操作（画像保存／コピー＋URL貼り付け）をモーダルに案内し、デスクトップ幅でボタンと共存することを確認した。
- `formation-share.html`へ`formation-share-page-actions.js`を追加し、下部バーから手動のPNG生成、画像コピー、画像保存、URLコピーを行えるようにした。画像生成中のキャンセル、編成変更・テーマ変更後の再生成要求、生成前の画像操作無効化を実装し、バーは画像化対象外とした。
- 列見出しの達成人数表示を`後列 3/3`のように整理した。グループ名を削除し、列名の直右に少し強調した`n/3`チップを置く。共有本文とPNGは同じDOM／CSSを使うため、公開表示と生成画像へ同時に反映し、ページ資材と生成URLのキャッシュバスターを更新した。
- テーマ切替後の再生成では、共有モーダルを開く際に現在のダッシュボードテーマをプレビューへ同期し、画像生成へ採用テーマを明示する。画像変換iframeには生成世代ごとの内部クエリを付け、同一URLの旧テーマ状態を再利用しない。`light→dark`の閉じる／再共有経路でダークPNGになることを確認した。
- 700px以下では共有ダイアログ全体を縦スクロール可能にし、短い画面高で下部操作が隠れないようにした。実機幅の目視は未検証として残す。
- `file://`で開いたダッシュボードは、ブラウザのローカルファイル制限により画像用iframeのDOM／画像取得を安全に完了できないため、PNG生成を12秒待たずにHTTP利用の案内へ切り替える。生成された`file://` URLは他人への共有先にならないため、ローカル確認時もHTTPサーバー経由で開く。
- 端末幅のCSS対策、全スペル、上限・キャンセル、非対応時の案内、連続更新経路のローカル確認を完了した。実端末とDiscord受信はこの環境では未検証として記録する。
