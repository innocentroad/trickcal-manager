# 特殊マス育成コスト比較 仕様書

## 1. 目的

次に伸ばしたい全体ステータスを指定し、未解放の特殊マスについて、現在の使徒育成状態から取得までに必要な総コストを比較する。

特殊マス単体の費用だけでなく、次をすべて含める。

- 対象までの経路上にある通常・上級マス
- 上位ボードへ進むためのゲート
- ゲートに必要な★1共同教団証または使徒証
- ボード解放条件を満たすためのスターアップ
- スターアップに必要な使徒証とゴールド

「どの使徒の、どの特殊マスを次に塗ると安いか」を比較する機能であり、複数マスをまとめて最適化する機能は初期範囲に含めない。

## 2. 前提データ

### 2.1 使徒状態

- 使徒ID
- 初期レア度
- 現在の★
- 現在ボード1～3の解放済みマス
- 予定ボード1～3の解放予定マス
- 所持している当該使徒証の数（任意）
- 所持している★1共同教団証の数（任意）

### 2.2 ボード行

既存ボードデータの次の列を使用する。

- `ボード階層`
- `X_pos`、`Y_pos`
- `マス_type`
- `効果`、`数値`
- `ゴールド`
- `下級`、`中級`、`上級`、`特級`
- `★1共同教団証`、`使徒証`

### 2.3 スターアップ費用

[育成必要リソース台帳](growth-resource-ledger.md)の段階別費用を使用する。

| 遷移 | 使徒証 | ゴールド |
|---|---:|---:|
| ★1→★2 | 12 | 40,000 |
| ★2→★3 | 20 | 150,000 |
| ★3→★4 | 25 | 300,000 |
| ★4→★5 | 50 | 700,000 |

特殊マス取得のために必要なスターアップは、ボード解放条件までに限定する。アサイド目的の★5やアサイド強化費用は加えない。

## 3. 対象ステータス

初期実装では特殊マスを次の5系統で指定する。

| 選択項目 | 対象となる特殊マス |
|---|---|
| HP | 全体HP |
| 攻撃力 | 全体物理攻撃力、全体魔法攻撃力 |
| 防御力 | 全体物理防御力、全体魔法防御力 |
| 会心系 | 全体会心、全体会心DMG |
| 会心抵抗系 | 全体会心抵抗、全体会心DMG抵抗 |

物理・魔法、会心・会心DMGなどを個別指定する詳細フィルターも用意できる構造にする。初期表示では既存のボード集計と同じ5系統にまとめる。

## 4. 比較基準状態

次の2種類を切り替えられるようにする。

| 基準 | 内容 |
|---|---|
| 現在 | 保存済みの現在ボードから追加コストを計算 |
| 予定込み | 現在＋予定ボードを取得済みとみなし、その続きから計算 |

予定込みの場合、予定で既に追加されているマスの費用は候補コストへ再加算しない。スターアップの予定状態が将来保存される場合も同じ基準へ含める。

## 5. 候補の定義

対象ステータスに一致する未取得の特殊マスを、1マスずつ候補にする。

候補には次を保持する。

```text
candidateId
apostleId
apostleName
boardLayer
tileKey
statGroup
effectName
effectValueP
requiredStar
requiredRows[]
routeRows[]
gateRows[]
starUpSteps[]
boardCosts{}
starUpCosts{}
totalCosts{}
shortageCosts{}
warnings[]
```

同じ使徒に同系統の特殊マスが複数ある場合も、それぞれ別候補として扱う。

## 6. 必要経路の計算

### 6.1 ボード内経路

既存のボード経路探索を再利用する。

1. 現在または予定込みの解放済みマスを起点にする
2. 上下左右で接続された経路だけを探索する
3. 対象特殊マスまでに新しく塗る必要があるマスを取得する
4. 同じマスを重複計上しない

現行仕様との互換性を保つため、経路候補はまず追加ゴールドが少ないもの、同額なら追加マス数が少ないものを採用する。

将来は経路比較基準を「特級優先」「所持不足優先」へ切り替えられるよう、探索時のコスト比較関数を分離する。

### 6.2 上位ボードのゲート

| 対象 | 必要な前提 |
|---|---|
| ボード1 | なし |
| ボード2 | ★3以上、ボード1ゲート |
| ボード3 | ★4以上、ボード1・2ゲート |

前階層ゲートが未解放なら、そのゲートまでの経路とゲート費用も候補へ加える。

ボード3解放用のボード2ゲートは通常「使徒証5枚」だが、初期★1使徒は「★1共同教団証5枚」とする既存例外を維持する。

### 6.3 スターアップ

候補ボードに必要な★へ現在★が届いていない場合、必要段階までのスターアップ費用を累積する。

例：現在★2からボード3の特殊マスを取る場合

```text
★2→★3: 使徒証20、150,000ゴールド
★3→★4: 使徒証25、300,000ゴールド
合計: 使徒証45、450,000ゴールド
```

ゲート自体の証5枚は、このスターアップ費用とは別に加える。

初期★1使徒のスターアップ証は★1共同教団証として扱う。初期★2・★3使徒は個別の使徒証として扱う。

## 7. コスト集計

### 7.1 内訳

```js
totalCosts = {
  gold,
  lowerCrayon,
  middleCrayon,
  upperCrayon,
  specialCrayon,
  sharedCertificate,
  apostleCertificate
};
```

画面では次の3段階に分けて表示する。

- 特殊マス本体
- 経路・ゲート
- スターアップ

最終行に3つの合計を表示する。

### 7.2 所持数と不足数

所持リソースを入力または保存できるようになった場合、次を計算する。

```text
不足数 = max(0, 必要数 - 所持数)
```

使徒証は使徒ごとに別リソースとして扱い、他使徒の証と合算しない。所持数未設定時は不足数を表示せず、必要数だけを表示する。

## 8. 「安い」の判定

ゴールド、くれよん、使徒証を無理に1つの点数へ換算しない。初期仕様では次の比較方法を提供する。

### 8.1 標準：優越候補

ある候補が別候補に対して、すべての主要リソースで同額以下かつ1種類以上で安い場合、その候補を優位とする。どの候補にも完全には負けない候補を「安い候補」として先に表示する。

これは複数リソースのパレート比較であり、証は安いが特級くれよんは高い、といった候補を勝手に除外しない。

### 8.2 並び替え

- 特級くれよんが少ない順
- 使徒証が少ない順
- ゴールドが少ない順
- 総追加マスが少ない順
- 効果1%あたりの特級くれよん順
- 効果1%あたりのゴールド順
- 所持不足の種類が少ない順

同値時は、スターアップ不要、低いボード階層、追加マス数、使徒名の順で安定ソートする。

### 8.3 効果効率

特殊マスの効果値が異なるため、絶対コストとは別に1%あたりの効率を表示する。

```text
特級効率 = 特級くれよん総数 / 特殊マス効果(%ポイント)
ゴールド効率 = ゴールド総額 / 特殊マス効果(%ポイント)
```

「次の1マスを最安で取る」と「同じリソースで効果を大きく伸ばす」は別順位として扱う。

## 9. 表示案

配置候補は全体ボードの集計画面内とする。既存の達成率・残りコストを利用しているため、別ページを増やさず「次に塗る特殊マス」セクションとして折りたたみ表示する。

### 9.1 条件欄

- 対象ステータス
- 現在／予定込み
- 全使徒／編成中／お気に入り等の使徒範囲
- ボード1～3
- 並び替え
- 所持数を考慮するか

### 9.2 候補カード

```text
[使徒画像] アヤ  B2  全体攻撃力 +4%
推奨: スターアップ不要 / 経路3マス

特級 4  ゴールド 342,000  下級 18  中級 6
使徒証 0  ★1共同教団証 0

[内訳] [このマスを予定へ追加]
```

初期実装では仕様確認用に「このマスを予定へ追加」は置かず、候補表示だけでもよい。実装する場合は既存の予定ボードへ対象経路を追加し、通常の保存操作へ合流させる。

## 10. 再計算

次の変更時に候補を再計算する。

- 対象ステータス変更
- 現在／予定込み切り替え
- 使徒範囲変更
- ボード保存・予定変更
- ★変更
- リソース所持数変更

候補を予定へ追加した後は、その候補の経路が次候補の起点になるため一覧を再計算する。操作した候補は既存のソート追跡と同様にスクロール追跡・ハイライトする。

## 11. 注意事項

- 魔女型の一部マスはlow/highの値と費用の対応が逆転しているため、値から費用を推測せず各ボード行の実データを使う。
- 現在塗られている不要な経路を解除して資源を流用する最適化は行わない。
- ボードリセットによる返還は初期範囲外とする。
- 使徒証を教団証へ換算した値、エリーフ、ガチャ期待値は別の資源換算機能として扱う。
- 同じ経路を共有する複数特殊マスの一括最適化は、単一候補比較の精度を確認した後の拡張とする。

## 12. 実装分割案

1. 純粋関数で1候補の必要経路・スターアップ・費用を計算
2. 全使徒から対象特殊マス候補を列挙
3. 優越判定と各種ソートを追加
4. 全体ボードへ読み取り専用一覧を追加
5. 予定ボードへの追加操作を接続
6. 所持数・不足数と複数マス最適化を追加

最初の検証では、B1取得済み・B2ゲート未解放・現在★2など、スターアップとゲートが同時に必要になるケースを優先する。
