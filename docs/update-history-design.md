# 更新情報 設計案

更新日: 2026-09-03<br>
状態: 設計のみ・未実装

## 目的

利用者が、アプリに最近追加された機能・改善・データ更新を短時間で確認できるようにする。

これは開発者向けのコミット履歴ではなく、利用者向けの「何が変わり、何ができるようになったか」を伝える更新情報とする。

## 基本方針

- 公開した更新単位で、関連する変更を一つの記事にまとめる。
- 新しい順に表示し、最新の更新を最初に目立たせる。
- 説明は利用者が得られる結果を先に書く。
- タイトルと本文はスマホ幅でも省略しない。
- 内部ID、ファイル名、コミット番号、ブランチ名、キャッシュ更新、テスト結果は表示しない。
- 技術的な原因は、利用者の操作や注意事項に関係するときだけ短く載せる。
- Gitのコミットメッセージをそのまま表示せず、公開前に人が利用者向けに要約する。

## 入口

### 推奨

独立した「更新情報」ページを作り、通常の主タブは増やさず、共通ヘッダーの補助操作エリアから開く。

- デスクトップ: noteリンクと再読み込みボタンの近くに「更新情報」リンクを置く。
- スマホ: 履歴アイコンまたは「更新」の短い表示にして、主タブの横幅を使わない。
- 敵ステータス画面など共通ヘッダーを持たない画面にも、同じページへの小さなリンクを置く。
- 更新情報を自動ポップアップして、計算中の画面や入力状態を遮らない。

独立ページにすることで、履歴が増えても既存の計算画面の高さや下バーを変えず、URLを直接共有できる。

## 画面構成

```text
[戻る]  更新情報

[最新の更新]
  2026/09/03  [データ更新] [DPSβ]
  ギデオンのアサイドに対応
  ・A3選択時もDPSβを利用できるようになりました
  ・アサイド効果を反映したDPSを計算できます
  ・一部の特殊な発動条件は手動設定が必要です

これまでの更新
  2026年9月  ▾
    更新カードを新しい順に縦表示
  2026年8月  ▸
```

- 全体は一列の縦方向レイアウトにする。
- 最新項目は通常の更新カードより少し目立たせる。
- 各項目は日付、分類タグ、タイトル、短い要約、箇条書きの変更内容で構成する。
- 古い項目が増えた場合は月単位の `details` で折り畳む。
- 初版では分類タグを表示するが、タグによる絞り込みは履歴が増えてから追加する。
- ダークモードとライトモードの両方で、日付・タグ・本文のコントラストを確保する。

## 分類タグ

表示名は次の5種類に固定する。

- 新機能
- 改善
- 不具合修正
- データ更新
- DPSβ

一つの更新に複数のタグを付けてもよい。タグは検索用の内部キーではなく、利用者が内容を把握するための補助情報とする。

## 掲載データの形式

更新情報は、静的ページで読み込める利用者向けデータとして管理する。1件の推奨構造は次のとおり。

```js
{
  id: '2026-09-03-gideon-aside',
  date: '2026-09-03',
  title: 'ギデオンのアサイドに対応',
  categories: ['データ更新', 'DPSβ'],
  summary: 'ギデオンをアサイド込みのDPS比較で確認できるようになりました。',
  items: [
    'A3選択時もDPSβを利用できます。',
    'アサイド効果を反映したDPSを計算できます。'
  ],
  notice: '一部の特殊な発動条件は外部イベントなどの手動設定が必要です。',
  links: []
}
```

### 文面ルール

- タイトルは「何が使えるようになったか」「何が改善されたか」で書く。
- 箇条書きは2〜4件を目安にする。
- 利用者が操作上知る必要のある制限だけ `notice` に書く。
- 未確定のゲーム内挙動を断定しない。
- 「実装しました」「テストしました」ではなく、「利用できるようになりました」と書く。
- 内部用語が必要な場合も、先に利用者向けの言い換えを置く。

## 未読表示

初版から、最新の更新をまだ開いていない場合に入口へ小さな未読ドットを付ける。

- 未読判定は最新記事の `id` とブラウザ内の既読IDを比較する。
- 更新情報ページを開いた時点で最新IDを既読にする。
- 内容を強制表示するポップアップや通知音は使わない。
- ブラウザのデータを消した場合は、再度未読として表示される。

## 初期掲載候補

最初から細かいコミット単位に分けず、利用者に意味のあるまとまりで掲載する。

- 2026-09-03: ギデオンのアサイド公開とDPSβ対応、関連データ更新
- 2026-09-02: DPS詳細、ダメージ推移、比較表示の改善
- 2026-08-30: 敵ステータス表示とボードプレビューの改善
- 2026-08-29: DPS外部イベントと比較表示の修正

## 実装時の単位

設計を実装するときは、次の単位を基本とする。

- `updates.html`: 更新情報ページ
- `updates.css`: 更新情報ページの表示とレスポンシブ対応
- `updates.js`: データの描画、月折り畳み、未読処理
- `update-history-data.js`: 利用者向け更新データ
- 共通ヘッダー: 更新情報への入口
- キャッシュ設定: 更新情報ページとデータを公開時に確実に更新する参照

更新データの追加時には、記事IDの重複、日付順、空のタイトル・本文、許可されていない分類タグを検査する簡易テストを用意する。

## 完了条件

- ダメージ計算、ステータス管理、敵ステータスの各画面から更新情報を開ける。
- スマホ・デスクトップのどちらでも横方向のはみ出しがない。
- タイトルと変更内容が省略されず、長い本文は自然に折り返される。
- 最新記事と過去記事の区別がつく。
- 更新情報を開いても、計算条件・保存状態・下バーの高さに影響しない。
- 表示内容に内部ID、開発者向け用語、コミット情報が漏れない。
- ダークモードとライトモードで読みやすい。
