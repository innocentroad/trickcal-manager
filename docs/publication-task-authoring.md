# 公開に関する指令作成要綱

指令・引き継ぎ文を作る担当向け。Luna/Sol等のモデル名ではなく役割で使い分ける。
この文書や指令作成依頼は、実装・commit・push・公開・承認代行の実行許可ではない。

## 書く内容

- 目的と対象：今回の変更・レビュー範囲と対象外を短く指定する。モデル・effortは利用者指定と適用されるAGENTS.mdに従い、作成者の判断で承認範囲を広げない。
- 作業場所：最新の[公開手順](publication-runbook.md)で固定sourceを確認する。現行は `D:/Games/etc/trickcal/trickcal-manager`、branch `release-source`。指令にも実際の絶対パスとbranchを書く。別cloneを作らせない。未コミットのツール・文書は別環境に存在する前提にしない。
- 許可範囲：利用者の実際の依頼に基づき、実装／レビュー／対象限定commit・push・公開／通常deployment承認代行のどこまでかを明記する。共通の承認解釈は適用されるAGENTS.mdを参照し、未承認の操作を足さない。意味が変わる曖昧さだけ確認する。
- 参照先：適用されるAGENTS.mdと公開手順を指定する。コマンド列・配信先・承認条件を全文複製せず、配信先と移行状態は `tools/publication-targets.json` に従わせる。「毎回必ず新旧両方」と固定せず、指令作成を理由に設定を変更しない。
- 再開情報：途中作業なら、確認済みのsource/artifact commit、bundle・receipt・公開履歴の場所、run ID/URL、完了工程と残作業を必要な分だけ渡す。未確認は未確認、未作成は未作成と書き、値を推測しない。既存runがある場合はその追跡・取り込みを指定する。
- 検証と停止：同一入力への完了済み生成・検査を理由なく繰り返さず、変更リスクに対応する検証と公開手順の境界照合を維持する。照合失敗・ロック・起動結果不明・承認不可は公開手順に沿って停止／復旧させ、迂回や再起動を指示しない。公開担当を並列に増やさない。
- 完了条件：実装のみ／レビューのみ／公開までを区別する。公開が許可されている場合は、許可範囲内の有効な配信先のdeploy成功・identity一致まで。最後は実施内容・検証結果・残作業と、再開に必要な記録だけを簡潔に報告させる。

## 短いひな型

必要な欄だけ具体化して渡す。角括弧の未記入欄や選択肢をそのまま実行指令に残さない。

```text
[モデル・effort]で、[対象と目的]を行ってください。
作業場所：[確認した絶対パス]、branch：[確認したbranch]。
適用されるAGENTS.mdとdocs/publication-runbook.mdに従ってください。
今回の許可範囲：[利用者が許可した操作]。対象外：[必要な制限]。
再開情報：[既存記録の場所・完了工程・残作業。新規なら省略可]。
配信先・移行状態は現在の設定に従い、完了済み工程を理由なく繰り返さないでください。
不一致・競合・権限不足では手順に従って停止し、設定変更や承認迂回をしないでください。
完了条件：[今回の許可範囲に合う条件]。結果と残作業を簡潔に報告してください。
```
