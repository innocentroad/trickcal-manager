# 固有状態基礎設定シート仕様（V1・設計段階）

## 目的

`固有状態基礎設定`は、使徒自身が内部的に保有する固有状態の性質を定義するマスターシートである。主な対象は、スタックを数える固有リソース、行動を切り替えるモード、回数を数えるカウンターである。

このシートでは状態の**定義**だけを扱う。状態をいつ獲得・消費するか、どの効果を発動するか、どの時点で条件を判定するかは、各スキルなどの効果行で定義する。

初期段階ではピラの`富豪`だけを参照対象とする予定であり、シートを作成しても、ただちに生成器・通常計算・DPS計算がこのシートを読むことは要求しない。

## 適用範囲と既存データとの関係

対象は、原則として「所有者（使徒）単位」で維持される内部状態である。

| 対象にする例 | 対象にしない例 |
|---|---|
| ピラの富豪のような自己保有リソース | 敵へ付与する毒・呪い・糸爆弾 |
| 所有者の行動を変える固有モード | 味方・敵へ付与する一般的な攻撃力増加・被ダメージ増加 |
| 攻撃回数や使用回数を数える固有カウンター | シールドなど対象ごとに耐久値を持つ通常の状態効果 |

毒、呪い、糸爆弾など、対象に付与され、持続時間・付与者・スタック集約を管理する状態効果は、引き続き[`tools/status-effect-master.tsv`](../tools/status-effect-master.tsv)で管理する。これはバフ・デバフ・状態異常など、付与対象を持つ共通状態効果のマスターである。

スキル・アサイド・愛用品などの効果行における発動条件、処理順、状態付与、持続時間などは、引き続き[`docs/datasheet-effect-schema.md`](datasheet-effect-schema.md)の書式に従う。`固有状態基礎設定`は同書式を置き換えず、効果行から参照される固有状態の台帳となる。

## V1の列構造

列順は以下で固定する。必須列は空欄不可、推奨列はV1では空欄を許容するが、対象状態の仕様が判明しているなら記入する。任意列は表示・調査用であり、計算処理の前提にしない。

| # | 列名 | 区分 | 定義 | V1の許容値・記入規則 |
|---:|---|---|---|---|
| 1 | `stateId` | 必須 | 固有状態を一意に参照するID | ASCII英大文字・小文字、数字、`_`。原則`<使徒ID>_<英語状態名>`。例: `Pira_wealth` |
| 2 | `id` | 必須 | 所有者となる使徒ID | 使徒基礎設定の`id`と完全一致 |
| 3 | `状態名` | 必須 | 画面・資料で表示する日本語名 | 例: `富豪` |
| 4 | `状態カテゴリ` | 必須 | 値が表す状態の種類 | `固有リソース` / `固有バフ` / `モード` / `カウンター` |
| 5 | `値形式` | 必須 | 状態値の表現形式 | `整数` / `実数` / `真偽` / `列挙` |
| 6 | `管理単位` | 必須 | 状態値をどの範囲で共有するか | `所有者単位` / `対象単位` / `味方全体` / `召喚物単位`。V1の使徒固有状態は通常`所有者単位` |
| 7 | `初期値` | 必須 | 戦闘開始時の値 | `値形式`に適合する値。整数・実数では数値、真偽では`真`/`偽`、列挙では定義済み値 |
| 8 | `最小値` | 必須 | 数値型の下限 | `整数`・`実数`は数値、その他は`-` |
| 9 | `最大値` | 必須 | 数値型の上限 | `整数`・`実数`は数値、上限なしは`-`、その他は`-` |
| 10 | `増減単位` | 必須 | 数値型で一回の通常操作が取り得る最小刻み | 正の数値。整数型では通常`1`。数値型以外は`-` |
| 11 | `上限時処理` | 推奨 | 上限を超える獲得・加算時の既定処理 | `上限で打ち止め` / `上限へ丸める` / `再設定` / `要調査` |
| 12 | `下限時処理` | 推奨 | 下限を下回る消費・減算時の既定処理 | `下限で打ち止め` / `下限へ丸める` / `発動しない` / `再設定` / `要調査` |
| 13 | `解除区分` | 推奨 | 一般的な解除処理との関係 | `解除不能` / `解除可能` / `対象外` |
| 14 | `保持期間` | 推奨 | 特段の効果がない場合の状態の保持範囲 | `戦闘中` / `行動中` / `ラウンド中` / `即時` / `要調査` |
| 15 | `変化イベント基準` | 推奨 | 状態変化を契機とする効果を、実値変化と操作試行のどちらで発火させるか | `実際の増減時` / `増減試行時` / `要調査` |
| 16 | `計算対応段階` | 推奨 | 現在の計算実装上の対応範囲 | `未対応` / `表示のみ` / `単発対応` / `DPS対応` / `一部対応` / `将来対応` |
| 17 | `検証状態` | 推奨 | データ根拠・実挙動の確認状況 | `済` / `暫定` / `途中` / `未` / `要検証` |
| 18 | `備考` | 任意 | 例外、未確定点、実装上の注意 | 自由記述。実行時条件や数式の唯一の定義には使わない |
| 19 | `出典URL` | 任意 | 検証に用いた情報源 | URL。複数ある場合は改行区切り |

### ヘッダー行

```text
stateId	id	状態名	状態カテゴリ	値形式	管理単位	初期値	最小値	最大値	増減単位	上限時処理	下限時処理	解除区分	保持期間	変化イベント基準	計算対応段階	検証状態	備考	出典URL
```

## V1の入力検証規則

1. `stateId`はシート内で一意とし、`id`の値と対応する接頭辞を用いる。例外的な共有状態は将来仕様ができるまで登録しない。
2. `id`は使徒IDとして存在しなければならない。V1では空欄を許容しない。
3. `状態カテゴリ`、`値形式`、`管理単位`、`上限時処理`、`下限時処理`、`解除区分`、`保持期間`、`変化イベント基準`、`計算対応段階`、`検証状態`は、上表の語彙のみを使用する。
4. `値形式`が`整数`の場合、`初期値`、`最小値`、`最大値`、`増減単位`は整数とする。`最大値`が数値の場合は`最小値 <= 初期値 <= 最大値`かつ`増減単位 > 0`を満たす。
5. `値形式`が`実数`の場合、数値の小数表記を許可する。`最小値`・`最大値`が数値なら、初期値はその範囲内とする。
6. `値形式`が`真偽`または`列挙`の場合、`最小値`、`最大値`、`増減単位`は`-`とする。列挙の候補値は、必要になった時点で別の定義列またはマスターを追加するまで、`備考`に記録する。
7. `上限時処理`・`下限時処理`が`要調査`の状態は、確率計算や時系列シミュレーションで確定動作として扱わない。
8. `保持期間`は既定の保持範囲である。特定スキルによる即時消費・リセット・行動終了時消失は、この列でなく効果行に書く。
9. `備考`の文章だけを根拠に生成・計算の分岐を実装しない。実装対象の挙動は構造化列へ追加してから利用する。

## 上限時の「実際の増減時」と「増減試行時」

`変化イベント基準`は、状態の獲得・消費をきっかけに別効果を発動する場合の既定意味を定める。

| 状態値 | 加算操作 | `実際の増減時` | `増減試行時` |
|---:|---:|---|---|
| 29 / 最大30 | `+1` | 29→30となるため、状態変化イベントを発生させる | 操作試行イベントを発生させる |
| 30 / 最大30 | `+1` | 30→30で実値が変わらないため、状態変化イベントを発生させない | 実値が変わらなくても操作試行イベントを発生させる |

富豪獲得時のパッシブのような効果は、この差異を明示しなければならない。初期案としては、上限で値が変わらない獲得では発動させない`実際の増減時`を推奨する。ただし、実ゲームで上限時の獲得試行も効果が発生することが確認された場合は、当該状態を`増減試行時`へ変更する。

## ピラ「富豪」のV1例

```text
Pira_wealth	Pira	富豪	固有リソース	整数	所有者単位	0	0	30	1	上限で打ち止め	要調査	解除不能	戦闘中	実際の増減時	未対応	暫定	強化攻撃・高学年終了時の消費不足処理は要調査	
```

| 項目 | 意味 |
|---|---|
| 最大値30 | 高学年強化の判定しきい値でもある。ただし「最大値」と「高学年強化条件」は別概念として扱う。 |
| 下限時処理=要調査 | 強化攻撃・高学年終了時のランダム消費が所持数を超えた場合の挙動が未確定である。 |
| 変化イベント基準=実際の増減時 | 30スタック中に基本攻撃で獲得を試みても、富豪獲得時パッシブを発動させない初期仮説である。 |
| 計算対応段階=未対応 | V1のシート作成時点では、生成器・通常計算・DPS計算は未参照であることを示す。 |

## 効果行に残すデータ

状態マスターにスキル固有の挙動を入れない。次の情報は、`スキル効果`などの効果行に保持する。

| データ | 配置理由 | ピラでの例 |
|---|---|---|
| 獲得・消費・設定操作 | どの行動が状態を変えるかは状態共通の性質ではない | 基本攻撃命中時に富豪を1獲得 |
| 操作量 | スキル・レベルごとに変化し得る | 富豪を1獲得、ランダム量を消費 |
| `randomId` | 乱数の範囲・重みは個別操作に属する | 強化攻撃時の消費、高学年終了時の消失 |
| 発生タイミング・処理順 | action start、命中、skill endなどの時点は効果ごとに異なる | 高学年終了時に富豪を失う |
| 条件評価時点 | 状態値をいつ固定・再評価するかは個別効果の規則 | 高学年開始時に30スタックを判定して通常版／強化版を固定 |
| しきい値条件 | 状態の上限と、特定スキルの発動条件は独立している | 富豪30で高学年の物理ダメージ・会心増加を強化 |
| 状態変化を契機とする派生効果 | 付与対象・値・持続・スタックは個別効果である | 富豪獲得時、後列の味方の攻撃力増加 |

## 将来の効果側参照列案

既存の効果新書式を拡張する際は、少なくとも以下の構造化列を効果行側へ追加する案とする。列名・生成キーは実装時に既存生成器の命名規則と照合して確定する。

| 将来列案 | 目的 | ピラでの利用例 |
|---|---|---|
| `stateId` | 操作・条件の対象となる固有状態を参照 | `Pira_wealth` |
| `状態操作` | `獲得` / `消費` / `設定` / `リセット`などを表す | 基本攻撃では`獲得`、高学年終了時は`消費` |
| `randomId` | 乱数定義を参照 | `pira_wealth_high_end_loss` |
| `条件評価時点` | `行動開始時` / `効果発生時` / `行動終了時`など | 高学年強化判定は`行動開始時` |

操作量は既存の値・レベル列を使用することを基本とし、専用の固定値列を追加する場合も、値分類・生成器との重複を避けて設計する。

### 将来の生成形（非拘束の設計案）

実装時の生成データは、状態定義を使徒ごとの配列または辞書として保持し、効果行は`stateId`参照を持つ形を想定する。以下はキー名を確定するものではない。

```js
{
  stateId: 'Pira_wealth',
  ownerId: 'Pira',
  name: '富豪',
  category: 'resource',
  valueType: 'integer',
  scope: 'owner',
  initialValue: 0,
  minValue: 0,
  maxValue: 30,
  step: 1,
  capBehavior: 'cap',
  floorBehavior: 'investigate',
  dispelPolicy: 'undispellable',
  retention: 'battle',
  changeEventBasis: 'actualChange'
}
```

効果行側は、既存の`processGroupId`、`processOrder`、`triggerType`、`triggerValue`、`triggerSourceId`、`conditionType`、`conditionValue`を維持した上で、例えば`stateId`、`stateOperation`、`randomId`、`conditionEvaluationTime`を持つことを想定する。これは設計案であり、V1作成時点の生成キーやJavaScript APIではない。

## 段階的な導入手順

1. Excelへ`固有状態基礎設定`シートを追加し、ピラの富豪をV1行として登録する。
2. V1の入力規則を用いて状態定義をレビューする。この段階では生成器・生成済みJavaScript・計算ロジックを変更しない。
3. ピラのスキル効果行へ、必要な状態操作・乱数参照・評価時点の列を設計して入力する。
4. 生成器にシート読込と効果側参照列のマッピングを追加する。
5. 通常計算では、固有状態の前提値を明示的に選べるようにするか、未解決条件として手動選択させる。
6. DPS計算では、実際の時間順に獲得・消費・上限・開始時スナップショットを処理する。
7. ピラで検証後、同種の固有状態（魔弾など）を移行する。

## ピラで未解決の仕様

- 強化攻撃時の富豪消費量の範囲・確率分布
- 高学年終了時に失う富豪の範囲・確率分布、および強化攻撃と同一分布か
- 所持数を超える消費要求時の挙動
- 富豪が0でも3回目の強化攻撃が発生するか
- 富豪30中の獲得試行で、富豪獲得時パッシブが発動するか
- 富豪獲得時の後列攻撃力増加の値、持続時間、スタック上限、再付与時の更新方法
- 「後列の味方」にピラ自身が含まれるか
- 強化攻撃の名刺2枚が単体ボスへともに命中するか
- 名刺2枚による被ダメージ増加が2回スタックするか、1回のみ付与されるか

## 実装状態

この文書は設計仕様である。現時点では、`固有状態基礎設定`のワークブックシート、生成器の読込、生成済みJavaScript、通常計算、DPS計算のいずれにも実装は存在しない。実装時は本書と[`docs/datasheet-effect-schema.md`](datasheet-effect-schema.md)を併せて更新し、実際に採用した列名・生成キー・検証規則を確定させる。
