# DPS・行動タイムライン基礎設計

## 1. 目的

使徒ごとの普通攻撃、低学年スキル、高学年スキルをフレーム単位で再現し、次の値を求める。

- 行動ごとの発動回数、命中回数、合計ダメージ
- 行動ごとの回転寄与DPS
- 使徒の総合DPS
- 将来的な編成全体DPS

初期段階では単体の使徒、固定された敵ステータス、固定されたバフ・デバフ条件を対象にする。移動、索敵、射程、敵の行動による中断、手動操作による発動遅延は別段階で扱う。

移動・配置を扱わない間は、対象が常に攻撃可能範囲におり、移動による攻撃不能時間は発生しないものとする。敵サイズや配置でヒット数が変わる攻撃は、ヒット数プリセットまたは手動指定で吸収する。

## 2. 時間単位

シミュレーター内部はゲーム内時間を基準とし、60Fをゲーム内1秒として扱う。普通攻撃間隔の実測値には0.1F単位が生じるため、内部では1Fを10tickへ分割した整数tickで保持する。

- フレームから秒: `seconds = frames / 60`
- 秒からフレーム: `frames = round(seconds * 60)`
- DPS: `damage / (durationFrames / 60)`
- 内部tick: `ticks = round(frames * 10)`

浮動小数の秒をイベント判定に使わない。画面表示時だけ秒へ変換する。

戦闘タイマーを実時間60fpsで計測した結果、戦闘速度`▶`では約1.3倍、`▶▶`では約1.69倍、`▶▶▶`では約1.95倍でゲーム内時計が進行する。`▶▶`は`▶`へさらに1.3倍を掛けた値と一致するが、`▶▶▶`は1.3の3乗ではない。

| 戦闘速度 | 計測区間 | 録画F | 1戦闘秒あたり | 実効速度 |
|---|---:|---:|---:|---:|
| ▶ | 03:00→00:00 | 8307F | 46.15録画F | 約1.300倍 |
| ▶▶ | 03:00→01:30 | 3196F | 約35.51録画F | 約1.690倍 |
| ▶▶▶ | 03:00→01:00 | 3692F | 約30.77録画F | 約1.950倍 |

`▶`の短区間では46Fと47F、`▶▶`では35Fと36F、`▶▶▶`では30Fと31Fが混在する。これは1戦闘秒が整数録画フレームにならないためであり、長区間の平均では上記倍率へ収束する。

普通攻撃間隔の `全体(F)` は`▶`の動画を60fpsとして手動計測した値であり、`モーション(F)` と `発生(F)` はゲーム内時間側のフレーム値である。このため補正対象は普通攻撃間隔だけとする。

```text
normalAttackIntervalFrames = measuredNormalAttackIntervalFrames * 1.3
motionFrames = sourceMotionFrames
eventFrame = sourceEventFrame
```

速度倍率は生成時の変換規則として管理し、元の実測値と計測時の戦闘速度も残す。`▶`は1.3、`▶▶`は1.69、`▶▶▶`は1.95を使用する。倍率の精度が更新された場合は生成し直せるようにする。

アメリアの現在値は次のとおり。

| 行動 | TSV値 | シミュレーション値 |
|---|---:|---:|
| 普通攻撃間隔 | 140F（実時間計測） | 182F |
| 低学年 | 130F | 130F |
| 高学年 | 240F | 240F |
| 普通攻撃_基本 | 120F | 120F |
| 普通攻撃_強化 | 150F | 150F |

## 3. 時間概念の分離

普通攻撃には「次の普通攻撃を開始できる時刻」と「現在のモーションが終了する時刻」の2種類がある。両者を同じ硬直値として扱わない。

- `normalAttackIntervalFrames`: 普通攻撃の開始間隔。現在の `基礎攻撃速度 / 全体(F)` に相当し、最終的な行名は `普通攻撃間隔` とする。
- `motionFrames`: 行動開始からモーション終了までの占有時間。
- `nextNormalAttackFrame`: 最後の普通攻撃開始フレームに攻撃間隔を足した時刻。
- `actionEndFrame`: 現在の行動開始フレームにモーションフレームを足した時刻。

普通攻撃のモーションが先に終了しても、`nextNormalAttackFrame` までは次の普通攻撃を開始しない。この待ち時間はモーションとは別のアイドル時間として記録する。

### 3.1 戦闘開始時の初動遅延

戦闘開始時は画面外から配置位置まで移動するため、戦闘時計の開始と最初の行動開始は一致しない。初期値はゲーム内1秒の60Fとする。

```text
0F     戦闘時計・SP回復周期・高学年CT開始
0～60F 配置位置への移動
60F    最初の行動を開始可能
```

初動遅延は行動開始だけを禁止する。移動中も毎秒SP回復、周期効果、高学年CTなどの戦闘時計は進行する。60F時点で複数行動が可能なら、通常の同一フレーム優先規則を使用する。

攻撃射程、初期配置、移動速度で実測値が変わるため、`initialActionDelayFrames` を使徒別datasheet値または手動設定で上書き可能にする。未設定時は60Fを使用する。

## 4. datasheetの推奨構造

列名は変更可能だが、生成後のキーは固定する。日本語の列名変更は生成スクリプトの別名マッピングで吸収する。

### 4.1 行動タイミング基礎設定

1行を1使徒・1行動とする。現在のTSVを拡張する場合の候補列は次のとおり。

| 列候補 | 生成後キー | 用途 |
|---|---|---|
| id | `apostleId` | 使徒ID |
| skillId | `skillId` | スキル基礎設定との結合キー |
| 動作名 | `actionType` | 普通攻撃間隔、普通攻撃_基本、低学年など |
| 普通攻撃間隔(F) | `measuredNormalAttackIntervalFrames` | 実時間60fpsで計測した普通攻撃開始間隔 |
| モーション(F) | `motionFrames` | ゲーム内時間基準の行動占有フレーム |
| 初動(F) | `initialActionDelayFrames` | 戦闘開始から最初の行動を開始できるまで。未設定時60F |
| 発動優先度 | `priority` | 通常はシステム側既定値を使用 |
| キャンセル区分 | `interruptPolicy` | キャンセル不可、終了待ち、即時キャンセルなど |
| 備考 | `notes` | 調査状態、例外、出典 |

現在の `全体(F)` は普通攻撃間隔行では実時間計測値、各行動行ではゲーム内時間のモーション値となる。意味が異なるため、datasheetへ統合する段階では `普通攻撃間隔(F)` と `モーション(F)` に列を分ける。

### 4.2 時間変換規則

普通攻撃間隔の計測基準だけを変換する。モーションと発生フレームには倍率を適用しない。

```text
id                              multiplier  target
measured_wall_to_game_time      1.3         normalAttackInterval
identity                        1.0         motion,event
```

内部では0.1Fを保持し、画面表示時の丸めとイベント時刻の丸めを分離する。

### 4.3 ダメージイベント設定

モーション全体フレームだけでは、多段攻撃の各ヒット時刻、短時間バフとの重なり、シミュレーション終了直前の発生ダメージを判定できない。最終的な精度を上げるには、スキル効果とは別にダメージ発生点が必要になる。即時発動モードでキャンセル後のヒットを除外する場合にもこの情報を使用する。

| 列候補 | 生成後キー | 用途 |
|---|---|---|
| skillId | `skillId` | 対象スキル |
| effectId | `effectId` | スキル効果行との結合キー |
| eventOrder | `eventOrder` | 同一スキル内の順序 |
| 発生F | `eventFrame` | 行動開始からダメージが発生するフレーム |
| ヒット数 | `hitCount` | そのイベントで発生するヒット数 |
| 倍率配分% | `coefficientShareP` | スキル総倍率のうち、そのイベントへ配る割合 |
| 対象数 | `targetCount` | 単体DPSと総ダメージの区別に使用 |

未調査時は「全倍率がモーション終了時に1回発生」として暫定計算し、結果に推定フラグを表示する。

### 4.4 可変モーション区間

条件によって攻撃回数とモーション長が同時に変わる行動は、固定の `motionFrames` ではなく区間構造として保持する。

| 項目 | 用途 |
|---|---|
| `startupFrames` | 行動開始から最初の反復区間まで |
| `loopFrames` | 1反復が占有するフレーム |
| `recoveryFrames` | 最後の反復後から行動終了まで |
| `loopCountSource` | 固有リソース、効果値、手動設定など反復数の参照元 |
| `minLoops` | 最小反復数 |
| `maxLoops` | 最大反復数 |

総モーションは原則として次で求める。

```text
motionFrames = startupFrames + loopFrames * loopCount + recoveryFrames
```

ヒットイベントは `startup`、`loop`、`recovery` のいずれかと、その区間内フレームを指定する。`loop` に属するイベントは各反復へ複製する。ゲーム上の区切りがこの3区間で表せない場合は、同じ構造を複数区間の配列へ拡張する。

未調査時は固定モーションへ戻さず、反復数と総モーションを手動指定できる暫定モードを使う。これにより、ヒット数だけ増えて行動占有時間が変わらない誤計算を避ける。

コア処理はTSVやExcelの列名を直接参照せず、生成済みの標準形だけを受け取る。

  measuredNormalAttackIntervalFrames: 140,
  normalAttackIntervalFrames: 182,
  actions: {
    basicAttack: {
      skillId: "Amelia_normal_basic",
      motionFrames: 120,
      timingQuality: "measured",
      damageEvents: []
    },
    enhancedAttack: {
      skillId: "Amelia_normal_enhanced",

    },
    lowSkill: {
      skillId: "Amelia_low",

実際の `skillId` はdatasheetの値を使用し、`動作名`だけでスキルを結合しない。

## 6. 行動状態

使徒ごとに次の状態を持つ。

```js
{
  frame: 0,
  currentAction: null,
  lastNormalAttackStartFrame: null,
  nextNormalAttackFrame: 0,
  currentSp: 0,
  lowSkillQueued: false,
  lowSkillReadyFrame: null,
  highSkillMode: "disabled",
  highSkillQueued: false,
  highSkillReadyFrame: 0,
  buffs: [],
  counters: {},
  totals: {}
}
```

`currentAction` は開始、終了、未発生のダメージイベントを持つ。現行対象の高学年オート発動はモーション終了を待つため途中キャンセルしない。将来の即時発動モードでは、キャンセル後の未発生ダメージイベントを破棄する。

## 7. 行動決定規則

### 7.1 普通攻撃

1. 使徒が行動中ではない。
2. 低学年スキルが以前のフレームから待機中ではない。
3. 高学年オート発動が待機中ではない。
4. 現在フレームが `nextNormalAttackFrame` 以上である。

SPが必要値へ到達したフレームと普通攻撃開始可能フレームが同一の場合は、3の「以前のフレームから待機中」に該当しないため普通攻撃を優先する。

以上を満たした時に普通攻撃を開始する。開始時に次を設定する。

```text
nextNormalAttackFrame = startFrame + effectiveNormalAttackIntervalFrames
actionEndFrame = startFrame + selectedAttackMotionFrames
```

基本攻撃と強化攻撃のどちらになるかは開始時に決定する。確率発動の場合、モーション長も異なるため、単純にダメージ倍率だけを期待値化すると低学年の発動時刻がずれる可能性がある。

### 7.2 低学年スキル

- SPが必要値以上になった時点で `lowSkillQueued = true` にする。
- SPが必要値へ到達したフレームを `lowSkillReadyFrame` に記録する。
- 行動中なら現在モーションの終了まで待つ。
- モーション終了時は `nextNormalAttackFrame` を無視して低学年スキルを優先する。高学年オート発動も待機中なら低学年を先に発動する。
- 行動していない待機時間中にSPが到達した場合は、そのフレームで発動するものとして暫定実装する。
- SP到達フレームと普通攻撃開始可能フレームが同一なら普通攻撃を優先する。低学年は待機状態のまま、その普通攻撃のモーション終了後に発動する。
- SPは低学年スキル開始時に0へリセットする。
- 低学年スキル終了時は、それ以前の `nextNormalAttackFrame` を破棄して終了フレームを次の普通攻撃開始可能時刻にする。
- 低学年が普通攻撃をどの時点でキャンセル・差し替えた場合でも、低学年モーション終了後は即座に普通攻撃を開始する。

待機時間中に低学年と高学年が同時に発動可能なら、オートでは低学年を優先する。

#### 低学年発動時のSP検証メモ（2026-08-04）

1.3倍速で動作しているゲーム画面を実時間60fpsで確認し、次を観測した。

| frame | 動作 | SP |
|---:|---|---|
| 1 | 普通攻撃途中 | 毎秒SP回復で300到達 |
| 48 | 普通攻撃途中 | 回復周期候補。上限300のため表示変動なし |
| 63 | 普通攻撃終了 | 300 |
| 64～65 | 低学年開始 | 0 |
| 132 | 低学年終了 | 0 |
| 133 | 普通攻撃開始 | 0 |
| 163 | 普通攻撃途中 | 毎秒SP回復 |
| 210 | 普通攻撃途中 | 毎秒SP回復 |

低学年開始時にSP表示が300から0になり、低学年モーション中に毎秒SP回復が加算されない。

この検証内ではframe 1→48とframe 163→210がともに47Fとなる。さらにframe 48から低学年開始まで約16F、低学年終了後からframe 163まで約30～31Fで、合計約46～47Fとなる。この使徒・条件では、SP回復タイマーが低学年中に停止し、終了後に残り時間から再開すると判断できる。

```text
低学年外で進んだ回復タイマー
約16F + 約30～31F = 約46～47F
```

低学年終了時に周期を最初からリセットする場合や、低学年中も周期が進む場合ではframe 163と一致しない。

SPがframe 1で上限300へ到達した後も周期が進み、frame 48付近で次周期へ移っていると考えると、低学年後のframe 163と整合する。したがって、上限中も周期イベントを進行させ、回復適用量だけを0へ丸める。

#### 戦闘開始からSP300までの追加検証（2026-08-05）

検証に使用した次元の衝突には、シーズン固有のステージルール「1秒毎のSP回復量30%増加」が設定されていた。カード等による追加回復は含まないが、この戦闘環境補正を含む結果として次を観測した。

| 使徒 | 基礎回復量 | ルール適用後 | 必要回数 | SP300到達 |
|---|---:|---:|---:|---:|
| エピカ | 20 | 26 | 12回 | 565～567F |
| コミー | 30 | 39 | 8回 | 375～376F |

```text
エピカ: ceil(300 / (20 * 1.3)) = 12回
コミー: ceil(300 / (30 * 1.3)) = 8回
```

この結果は回復回数を説明するが、SP300到達フレームを回数で割って回復周期を求めてはならない。到達フレームには、戦闘開始基準と初回回復判定の位相が含まれるためである。

戦闘タイマーの長時間計測から、戦闘時計の1秒は`▶`で `60 / 1.3 = 約46.15録画F` と確認できた。整数録画フレーム上では46Fと47Fが混在する。その後の味方・敵SP長期計測から、SPは60戦闘F待機を速度ごとの更新フレーム単位で切り上げ、実行時点から次周期を数える方式と判断する。

シミュレーターではSP回復周期と回復量を分離する。周期は `spRecoveryIntervalBattleFrames`、基礎回復量は使徒データ、シーズンルールの30%増加は戦闘条件の回復量倍率として適用する。

```js
battleContext: {
  contentType: "dimensionalClash",
  seasonId: null,
  stageRules: {
    spRecoveryAmountMultiplier: 1.3
  }
}
```

この補正は次元の衝突の恒常ルールではない。対象シーズンまたは対象プリセットに明示された場合だけ適用し、計算詳細へ適用中のステージルール名と補正値を表示する。

#### エピカ2巡目の追加計測

同条件のエピカで2回目の低学年開始まで計測し、初回回復を除く回復回数を「11回 + 12回」、2回目のSPリセットを1085録画Fで観測した。

この値を周期へ変換するには、1085Fが録画開始からの絶対フレームか、初回回復からの経過フレームかを区別する必要がある。また、回復イベント数とイベント間の区間数は一致しない。23イベントの最初から最後までは22区間となる。

仮に1085Fが23個の回復イベントの最初から2回目リセットまでの経過値で、途中に約67～68録画Fの低学年モーション停止が1回含まれるなら、次の値となる。

```text
(1085 - 67～68) / 22 = 約46.23～46.27録画F
```

これは `60 / 1.3 = 約46.15録画F` に近い。ただし、初回回復を区間の始点に含めず、その後に23区間あるという数え方なら結果は変わる。確定には、初回回復、各SP加算、1回目低学年の開始・終了、2回目低学年開始の絶対録画フレームを並べて再計算する。

#### マエストロMK2の長期SP回復計測

同じく戦闘速度`▶`、次元シーズンの毎秒SP回復量30%増加ルール下で、マエストロMK2を複数回の低学年発動まで計測した。低学年外で連続して可視化されたSP回復は大部分が47録画F間隔で、一部46Fまたは48Fとなった。

```text
可視回復43区間の合計: 約2020録画F
平均周期: 2020 / 43 = 約46.98録画F
戦闘タイマー1秒: 約46.15録画F
```

長期平均が約47録画Fへ収束しており、SP回復の実行間隔は戦闘タイマーの表示上の1秒と完全には一致しない。`▶`では `ceil(60 / 1.3) = 47録画F`、`▶▶`では `ceil(60 / 1.69) = 36録画F`となるため、60戦闘F待機を更新フレーム単位で切り上げ、実行フレームを起点に次の60F待機を始める方式で観測値を説明できる。後述の`▶▶▶`と敵SPの連続計測により、真の61F周期および理論時刻へ加算する累積方式は採用しない。

SP300到達後も47Fごとの周期は継続している。表示上は回復しないが、1226→1273、2172→2219、3118→3165録画Fに非表示の周期判定があったと仮定すると、その後の低学年開始と次回復を同じ規則で説明できる。

| 低学年開始 | 直前の周期判定 | 開始まで進んだ時間 | 残り周期 | 次回復 | 推定停止時間 |
|---:|---:|---:|---:|---:|---:|
| 329 | 328 | 1F | 46F | 495 | 120F |
| 804 | 777 | 27F | 20F | 944 | 120F |
| 1279 | 1273（非表示） | 6F | 41F | 1441 | 121F |
| 1755 | 1723 | 32F | 15F | 1890 | 120F |
| 2230 | 2219（非表示） | 11F | 36F | 2386 | 120F |
| 2705 | 2668 | 37F | 10F | 2836 | 121F |
| 3181 | 3165（非表示） | 16F | 31F | 3332 | 120F |

```text
推定停止時間 = 次回復 - 低学年開始 - 残り周期
```

全周回で120～121録画Fとなるため、次の挙動を強く支持する。

1. SP上限中も周期タイマーは進む。
2. 低学年開始時に周期タイマーをリセットしない。
3. 低学年モーション中は周期タイマーを停止する。
4. 低学年終了後は開始時点の残り時間から再開する。

#### 戦闘速度▶▶での追試

同じ使徒・条件を戦闘速度`▶▶`で計測した。戦闘タイマーは03:00の1録画Fから01:30の3197録画Fまで90戦闘秒で3196録画F進み、実効速度は約1.6896倍となった。`▶▶`は1.69倍として確定する。

SP回復は可視54区間で約36.02録画Fへ収束した。

```text
60F待機を周期ごとに切り上げ: ceil(60 / 1.69) = 36録画F
61F待機を周期ごとに切り上げ: ceil(61 / 1.69) = 37録画F
ただしゲーム側の時間蓄積・比較・実行順により境界は1F前後し得る
```

観測値は、次回目標を前回の理論時刻へ60F加える累積方式ではなく、実際に回復を実行した更新フレームから次の待機を始める方式を強く支持する。基礎値は文言どおり `spRecoveryIntervalBattleFrames = 60` とし、速度ごとの更新フレーム量子化と次周期の起点を別設定として再現する。

低学年中の周期停止時間も各周回で93録画Fとなり、`93 * 1.69 = 約157.2戦闘F`で、`▶`計測から得た約157戦闘Fと一致する。戦闘速度が変わっても、低学年モーション中の停止と残り周期からの再開規則は維持される。

#### 戦闘速度▶▶▶での追試

同条件を戦闘速度`▶▶▶`で計測した。戦闘タイマーは03:00の1録画Fから01:00の3693録画Fまで120戦闘秒で3692録画F進み、実効速度は約1.9502倍となった。`▶▶▶`は1.95倍として確定する。

SP回復は可視37区間で合計1147録画F、平均31.00録画Fとなった。

```text
60F待機を周期ごとに切り上げ: ceil(60 / 1.95) = 31録画F
61F待機を周期ごとに切り上げ: ceil(61 / 1.95) = 32録画F
```

観測がほぼ完全に31録画F周期となったため、基礎周期は60戦闘Fで、速度ごとの更新フレームへ切り上げ、実際に回復した更新フレームを次周期の起点にする方式と判断する。

低学年中の周期停止時間も80～81録画Fとなる。`80～81 * 1.95 = 156～157.95戦闘F`で、`▶`・`▶▶`から得た約157戦闘Fと一致する。

#### 敵SPの連続計測

低学年発動による周期停止やSP上限表示を挟まない敵SPを、`▶`と`▶▶▶`で連続計測した。

| 速度 | 回復イベント | 区間数 | 平均録画F | 主な分布 |
|---|---:|---:|---:|---|
| ▶ | 62回 | 61区間 | 約46.98F | 47Fが48区間 |
| ▶▶▶ | 120回 | 119区間 | 約31.01F | 31Fが110区間 |

`▶`では60Fの累積方式なら平均約46.15録画Fとなるはずだが、実測は約46.98Fへ収束した。`▶▶▶`でも60F累積方式の平均約30.77Fではなく、周期ごとに切り上げた31Fへ収束した。

また、戦闘タイマー03:00から02:00までに確認できた敵SP回復回数は`▶`で58回、`▶▶▶`で59回だった。低学年停止を含まない同じ60戦闘秒でも速度により回復回数が変わるため、更新フレーム量子化が実際の戦闘進行へ影響することを確認した。

したがって、SP周期は次の式で再現する。

```text
recordingFramesPerSpTick = ceil(60 / combatSpeed)
effectiveBattleFramesPerSpTick = recordingFramesPerSpTick * combatSpeed
```

単発の30F・32F、45F・48F・49Fなどは、表示確認の誤差または録画フレームと画面更新の境界差として扱う。長期平均と最頻値を周期判定に使用する。

#### 戦闘速度による量子化差

60戦闘F待機を速度ごとの更新フレームへ切り上げ、実行時点から次周期を開始する場合、外部から見た周期は速度ごとにわずかに異なる。

| 戦闘速度 | 更新倍率 | 60F到達に必要な録画F | 実効戦闘F周期 |
|---|---:|---:|---:|
| ▶ | 1.3 | 47F | 61.10F |
| ▶▶ | 1.69 | 36F | 60.84F |
| ▶▶▶ | 1.95 | 31F | 60.45F |

この方式により、長時間ではSP回復回数、低学年発動時刻、普通攻撃との同時判定が速度により変化する。DPSシミュレーターでは戦闘速度を戦闘条件へ保持し、次の2モードを分離する。

- `ideal`: 60戦闘F周期で速度非依存。設計・比較用。
- `gameUpdate`: 速度ごとの更新単位へ切り上げ、実行時点を次周期の起点にする。実ゲーム再現用。

速度変更時は、それまでに経過した周期時間を保持するのを暫定規則とし、実測でリセットが確認された場合だけ変更する。

現行使徒は低学年開始後にすべてSPが0となり、最大SPと発動条件の関係から固定値消費との差を観測できない。このため、観測結果をそのまま表す `reset` を標準方式とする。

```js
spOnLowSkillStart: {
  policy: "reset",
  value: 0
}
```

将来、残存SPを持つ使徒が追加された場合だけ `consume` または `set` をスキル単位で指定できるようにする。シミュレーター内部では方式を切り替え可能にするが、現行データへ未確認の「300消費」という意味は持たせない。

シミュレーション規則は `低学年開始時にSPを0へリセット`、`低学年中は周期タイマーを停止して残り時間を保持`、`SP上限中も周期を進める` とする。上限中に内部の回復コールバックまで実行されるかは不明だが、シミュレーション上は周期が進行する点だけ再現すればよい。

### 7.3 高学年スキル

現行シミュレーションで選べる設定は次の2種類とする。

- `disabled`: 高学年を発動しない。
- `auto`: クールタイムが完了したら発動待機状態にし、現在モーションの終了後に発動する。

オート発動では普通攻撃、低学年、高学年のモーションを途中キャンセルしない。クールタイム完了時に行動していなければ、そのフレームの行動決定で高学年を開始する。ただし、SPが必要値へ到達して低学年も発動可能な場合は低学年を優先し、高学年は低学年モーション終了後まで待機する。

再発動クールタイムは高学年スキルのモーション開始時を起点とする。イードは高学年開始1録画FでCT表示が発生し、同じ次元の衝突内で1753録画Fに再使用可能となった。`▶`換算で約37.96秒となり、設定CT38秒と一致する。モーション終了時を起点にする場合に加算される320戦闘Fの遅れは観測されない。初回クールタイムは戦闘開始時を起点とする。

将来検討として `immediate` を残す。このモードはクールタイム完了または手動命令のフレームで現在行動をキャンセルして高学年を開始する。正確に計算するには各攻撃のヒット発生フレームが必要なため、現行UIと標準DPS計算にはまだ含めない。

#### 次元の衝突における初回クールタイム

イードの高学年スキルは設定クールタイム38秒で、戦闘速度`▶`において次を観測した。

| 条件 | 起点 | 発動可能 | 録画F差 | 戦闘秒換算 |
|---|---:|---:|---:|---:|
| 次元の衝突・2回目以降 | 1F | 1753F | 1752F | 約37.96秒 |
| 次元の衝突・戦闘開始時 | 1F | 878F | 877F | 約19.00秒 |

次元の衝突では、少なくともこのシーズン・イードの初回高学年クールタイムだけが50%になり、2回目以降は設定値どおり38秒へ戻る。

戦闘条件では初回クールタイムと再発動クールタイムを分離する。

```js
highSkillCooldown: {
  recurringSeconds: 38,
  initialMultiplier: 0.5,
  recurringMultiplier: 1,
  initialAnchor: "battleStart",
  recurringAnchor: "skillStart"
}
```

他使徒でも初回半減とみられる挙動を確認しているため、対象シーズンでは味方使徒全体へ適用するステージルールとして暫定採用する。次元の衝突の恒常ルールへは固定せず、`initialMultiplier = 0.5`、`recurringMultiplier = 1`として適用する。

### 7.4 条件で反復数が変わる行動

シオン低学年のような行動は、行動開始時の状態から反復数を1回だけ解決し、開始・反復・終了区間を具体的なイベント列へ展開する。

```text
行動開始
  → 固有リソースの獲得
  → 反復数を解決
  → 必要ならリソースを予約・消費
  → startup
  → loop × N
  → recovery
  → 行動終了
```

獲得、反復数決定、消費の順番は効果ごとに明示する。途中で状態が変わっても、開始時に確定した反復数は原則変更しない。途中終了や高学年によるキャンセル時は、未発生の反復イベントを破棄する。

計算設定は `自動／固定／OFF` ではなく、行動固有の `反復数: 自動／固定値` を持たせる。自動で必要な固有リソース仕様が未調査の場合は固定値を標準にして、結果へ手動仮定を表示する。

## 8. 同一フレームのイベント優先順位

暫定的に次の順で処理する。

1. 高学年クールタイム完了、毎秒SP回復、周期SP回復
2. 現在行動のダメージ、回復、バフ付与イベント
3. モーション終了
4. 以前のフレームから待機している低学年の発動判定
5. そのフレームでSPが必要値へ到達し、普通攻撃も開始可能な場合の普通攻撃開始判定
6. そのフレームでSPが必要値へ到達した低学年の発動判定
7. 高学年オート発動判定
8. 通常の普通攻撃開始判定

5と6が同時に成立する場合は普通攻撃を開始し、低学年は次のモーション終了まで待機する。この場合、高学年も低学年より先には発動しない。以前のフレームから低学年が待機している場合は4で処理されるため、普通攻撃と高学年より低学年が先になる。

将来の即時発動モードを有効にする場合だけ、高学年命令を1より前に処理し、キャンセルされた行動の未発生イベントを破棄する。

既存の `sp-engine.js` は整数秒を跨いだ時にSPを増やしている。SP回復量の計算ロジックは再利用し、タイムライン側の基礎周期は60戦闘F、更新フレームへの切り上げと実行時点からの再待機を速度設定に応じて処理する。

## 9. 攻撃速度と加速

基礎値はフレーム数で保持し、攻撃速度補正後の普通攻撃間隔を別途求める。

```text
effectiveNormalAttackIntervalFrames = attackSpeedFormula(normalAttackIntervalFrames, totalAttackSpeedModifier)
```

攻撃速度倍率が影響するのは普通攻撃間隔だけとする。基本攻撃、強化攻撃、低学年、高学年のモーションフレームには適用しない。

モーションへ影響する補正は加速だけとし、TSVのゲーム内モーションフレームへ適用する。普通攻撃間隔の1.3倍変換とは独立させる。

```text
effectiveMotionFrames = accelerationFormula(baseMotionFrames, totalAccelerationModifier)
```

攻撃速度と加速の正確な除算式、適用順、丸め位置は未確定なので、初期実装で式を固定しない。両方を差し替え可能な関数にし、基礎値、補正合計、補正後フレームを詳細表示する。

## 10. 確率行動

基本攻撃と強化攻撃でモーション長が異なる場合、期待ダメージだけでなく行動時間も分岐する。段階的に次の方式を用意する。

1. `固定`: 常に基本、常に強化、調査した順序を指定する。検証用。
2. `期待値近似`: 確率でダメージとモーションを平均化する。高速だが、SP到達とモーション終了の前後が不正確になる場合がある。
3. `反復試行`: 固定シードで多数回シミュレーションし、平均DPSと範囲を出す。最終的な標準方式。

同じ入力とシードで同じ結果を再現できるようにする。

## 11. ダメージ計算との接続

現在の `calculateDamage(context)` は画面要素と選択状態に依存している。DPS計算では、行動イベントごとに呼べる純粋な計算関数へ段階的に分離する。

```js
calculateActionDamage({
  attackerStats,
  defenderStats,
  skillEffect,
  actionCategory,
  activeEffects,
  frame
})
```

初期実装では戦闘中に変化しない条件を前提に、各行動の通常・会心・期待値を開始前に1回計算してキャッシュできる。時限バフ、スタック、敵デバフをタイムラインへ組み込む段階で、命中フレームの状態を渡して再計算する。

## 12. DPSの定義

「各スキルのDPS」は回転内での寄与を主表示にする。

```text
actionContributionDps = actionTotalDamage / simulationSeconds
apostleTotalDps = allActionDamage / simulationSeconds
```

補助値として次も出す。

- 1回あたり期待ダメージ
- 完遂1回あたりのモーション占有DPS: `damagePerCast / motionSeconds`
- 発動回数、完遂回数、キャンセル回数
- ヒット数
- 総ダメージに対する構成比
- 最初の発動フレーム、平均発動間隔

`普通攻撃DPS + 低学年DPS + 高学年DPS + 状態異常DPS = 使徒総合DPS` となるよう、すべてのダメージイベントを必ず1つの発生元へ帰属させる。

編成全体を扱う時は使徒総合DPSの単純加算だけでなく、共有バフ・敵デバフの時系列を1つの戦闘タイムラインで処理し、`編成総合DPS` として区別する。

## 13. 出力

### 13.0 試験実装の集計方針

単一seedのタイムラインは、行動順、SP、ランダム分岐を再現する検証機能として残す。標準の寄与度表示は、指定時間を同じ条件・連続seedで反復した平均を使用する。

```text
actionContributionDps = 全試行の行動別期待ダメージ合計 / (試行数 * 計測秒数)
damageShareP = 全試行の行動別期待ダメージ合計 / 全試行の総期待ダメージ
```

初期実装では16、64、256seedを選択できる。乱数で行動順が変わる強化攻撃やスキル分岐は試行し、会心など後続状態を変えない乱数は単発ダメージ計算の期待値を使用する。

現在は各行動開始前に、現行ダメージ計算から静的な行動ダメージプロファイルを作成している。時限バフ、スタック、敵デバフがタイムライン中に変化する段階では、ヒットイベント時評価器へ差し替える。

常時、無条件、対象性格一致など行動に依存しないスキル効果は、単発ダメージ計算のトグル状態を全行動のプロファイルで共有する。発動条件の「低学年使用時」などはバフを得る契機であり、効果の適用先とは分けて扱う。適用先を行動別に制限するのは、攻撃タイプ列、対象スキル列、または「普通攻撃ダメージ量増加」のような値の種類で明示された場合とする。

時限バフをまだ時系列評価しない段階では、現在選択中の行動で汎用バフがONなら「発動後の静的状態」として全行動へ適用し、OFFなら全行動から除外する。例えばネルの「低学年使用時 / 味方全体 / 与ダメージ量増加」は、ON時に全行動へ適用する。持続8秒の実稼働率は時限効果実装後に置き換える。

DPS画面の「行動別適用効果」では、基本攻撃、強化攻撃、低学年、高学年ごとに静的効果のON/OFFを一覧表示する。詳細には行動1回の期待ダメージ、効果値、適用または除外理由を出し、DPSプロファイルへ何が入ったかを追跡できるようにする。速度データが未登録でも4行動の静的監査は生成し、DPS、発動回数、タイムラインだけを未計算として表示する。これは現在状態の監査表示であり、将来の時限効果はヒット時評価と効果稼働率を別途表示する。

複数ダメージ効果の発生フレーム・倍率配分が未調査の場合は、判明している効果を終了時に暫定合算し、確認事項として表示する。未調査の配分を推測して確定値として扱わない。

設定比較では、基準保存時の計測時間、高学年モード、初動、開始seed、試行数を固定し、基準と変更後へ同一seed群を割り当てる。総DPS、行動別DPS、平均発動回数の差を表示し、乱数条件ではなく設定変更による差を確認する。攻撃使徒を変更した場合は、異なる行動モデルの誤比較を避けるため基準を解除する。

## 14. アメリアの受け入れテスト

攻撃速度補正なし、初期SP 0、毎秒SP 30、必要SP 300、最初の普通攻撃を0F開始と仮定する。

### 基本攻撃のみの場合

- 実時間計測140Fを1.3倍し、普通攻撃間隔は182Fとする。
- 普通攻撃開始: 0F、182F、364F、546F
- 基本攻撃モーション: 各開始から120F
- 各攻撃後に62Fの待機が発生する。
- 理想戦闘時計上ではSPが60Fごとに30増える。実ゲーム再現モードでは速度別の更新フレームへ切り上げる。
- 546F開始の普通攻撃は666Fに終了する。
- 低学年は600Fで待機状態になり、666Fに開始する。
- 次の普通攻撃予定728Fを無視して低学年を優先する。
- 低学年は766Fにヒットし、796Fに終了する。
- 普通攻撃可能時刻728Fを過ぎているため、796Fに次の普通攻撃を開始する。

### 強化攻撃の場合

546Fの攻撃が強化攻撃なら終了は696Fとなり、低学年開始も696Fまで遅れる。この差があるため、強化確率をダメージ倍率だけで期待値化しない。

### SP到達と普通攻撃が同一フレームの場合

SPが300へ到達するフレームと普通攻撃開始可能フレームが一致した場合は、普通攻撃を先に開始する。低学年は待機状態となり、開始した普通攻撃のモーション終了後に発動する。

### 高学年オート発動

高学年のクールタイムが600Fで完了しても、546F開始の普通攻撃はキャンセルしない。基本攻撃なら666F、強化攻撃なら696Fのモーション終了時に高学年を開始する。同じ時点で低学年も待機している場合は高学年を先に発動する。`disabled` モードでは高学年を発動せず、通常どおり低学年へ進む。

### 将来の高学年即時発動

`immediate` モードを追加する場合は、600Fで普通攻撃をキャンセルして高学年を開始する。600F以後に予定されていた普通攻撃のヒットは破棄するが、600Fより前に発生済みのヒットは残す。この境界判定にはヒット発生フレームの調査が必要になる。

## 17. 効果設定と特殊効果台帳

通常の行動条件と、戦闘中に状態が変動する効果を分離する。

### 17.1 行動条件

低学年使用時、普通攻撃時、特定攻撃分類などの条件は、各行動について `自動／ON／OFF` を設定できるようにする。標準は自動とし、ON/OFFは検算・例外設定として保存する。

行動評価時は現在の画面選択を変更しない。戦闘条件スナップショットと行動記述から、カード、本人スキル、編成スキル、アサイド、敵弱点を再判定する。

### 17.2 時系列効果

毎秒増加、N回ごと、持続時間、スタック、リセット、固有CT、SP回復などは、行動条件のトグルではなくランタイム状態として管理する。設定は `自動／固定／OFF` とする。

例として竜光剣は、1秒ごとの攻撃速度スタックと低学年使用時のリセットをイベントとして処理する。固定モードでは指定スタック数を常時適用し、検算に使用する。

持続時間付きスタックは個別期限方式とする。各スタックを `{ startTick, expireTick, value, sourceEventId }` として保持し、新規付与時に既存スタックの期限を更新しない。期限到達ごとに該当スタックだけを削除し、その時点の有効数から補正を再計算する。

例として、残り4秒のスタック1がある時点で持続10秒のスタック2を追加した場合、4秒間は2スタック、その後6秒間は1スタックとなり、最後に効果が終了する。

同一フレームで付与と期限切れが重なる場合の優先順は、ゲーム挙動の確認までは「期限切れ処理後に新規付与」を暫定規則とする。

### 17.3 個別効果

個別効果の分類、実装状態、未確定事項は [DPS特殊効果台帳](dps-effect-inventory.md) で管理する。個別仕様が共通規則として確認できた時点で、本設計書へ昇格する。
