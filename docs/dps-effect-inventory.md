# DPS特殊効果台帳

## 1. 目的

DPS計算へ影響するカード、スキル、アサイド効果を、実装方式と調査状態で分類する。個別効果の仕様はこの台帳へ追加し、共通ルールとして確定した内容だけを `dps-simulation-design.md` へ反映する。

この台帳は全効果の説明一覧ではない。単発ダメージ計算だけでは扱えない効果、行動ごとに適用範囲が変わる効果、戦闘中に値が変動する効果を優先して記録する。

## 2. 処理分類

| 分類 | 意味 | 例 | 初期実装 |
|---|---|---|---|
| `static` | 戦闘中に変化しない補正 | 戦闘開始時の攻撃力増加 | 行動評価前に適用 |
| `action` | 選択行動により適用可否が決まる | 低学年ダメージ増加 | 行動ごとに自動判定 |
| `timed` | 一定時間だけ有効 | 低学年使用後6秒間攻撃速度増加 | 開始・終了イベント |
| `periodic` | 一定周期で発生または増減 | 1秒ごとにSP回復 | 周期イベント |
| `stack` | 回数や時間で蓄積する | 普通攻撃3回ごとに攻撃速度増加 | 状態変数と上限 |
| `reset` | 特定行動で蓄積状態を戻す | 低学年使用時に竜光剣リセット | リセットイベント |
| `cooldown` | 効果固有の再発動待ち | 2回ごと発動、CT6秒 | 次回発動可能時刻 |
| `random` | 確率・範囲・分岐を持つ | アリスのランダム効果 | 固定シード試行 |
| `resource` | SPや固有リソースを変化させる | 攻撃命中時SP回復 | 命中イベント後に反映 |
| `segmented` | 開始・反復・終了でモーション長が変わる | シオン低学年 | 反復数から行動を展開 |
| `external` | 敵行動、HP、撃破など外部状態が必要 | HP40%以下、撃破時 | 固定仮定または将来対応 |
| `spatial` | 移動、射程、索敵、配置、敵サイズが必要 | 突進、範囲内の敵数 | 原則除外または手動仮定 |
| `summon` | 召喚物が独立行動する | モモの召喚獣、自爆 | 独立アクター |
| `battleRule` | コンテンツ・シーズン・ステージが戦闘全体へ与える補正 | 次元シーズンの毎秒SP回復量30%増加 | 戦闘条件として事前適用 |

1つの効果が複数分類を持ってよい。竜光剣は `periodic + stack + reset` となる。

## 3. 計算設定

### 3.1 行動条件

行動条件は行動ごとに次の3状態を持つ。

| モード | 動作 |
|---|---|
| 自動 | datasheetの攻撃分類・条件から判定 |
| ON | その行動では強制適用 |
| OFF | その行動では強制除外 |

上書きがないことと、明示的な自動指定を同じ意味として扱う。保存キーは表示名ではなく `effectId + actionKey` を使用する。

### 3.2 時系列効果

時系列効果は次の3状態を持つ。

| モード | 動作 |
|---|---|
| 自動 | タイムラインで発動・終了・スタック・リセットを処理 |
| 固定 | 指定スタック数または指定値を戦闘中固定 |
| OFF | 効果を発生させない |

固定は検算と特定瞬間の比較用であり、標準DPSは自動を使用する。

### 3.3 個別期限を持つスタック

持続時間付きスタックは、スタック数に共通の残り時間を1つ持たせない。付与されたスタックごとに独立した開始時刻と終了時刻を保持する。

```text
0秒  stack[1] 付与 / 終了予定10秒
6秒  stack[2] 付与 / 終了予定16秒
6～10秒  2スタック
10秒 stack[1] 終了
10～16秒 1スタック
16秒 stack[2] 終了
```

新しいスタックの付与では、既存スタックの有効期限を更新しない。現在スタック数は、そのフレームで有効なスタックインスタンス数から求める。

```js
activeStackCount = stacks.filter(stack =>
  stack.startTick <= currentTick && currentTick < stack.expireTick
).length;
```

固定モードでは個別期限を進行させず、指定スタック数を計測期間中維持する。

### 3.4 外部条件

敵HP、撃破、被弾、シールド破壊など、現在の単体攻撃タイムラインだけでは確定できない条件は次から選ぶ。

- 自動判定可能
- 常時成立と仮定
- 不成立と仮定
- 発生時刻・発生回数を手動指定
- 未対応として除外

### 3.5 移動・空間条件

初期DPS計算では、移動距離、移動速度、索敵、射程、敵との間合い、ノックバック、敵サイズ、範囲内の敵数をシミュレーションしない。

- 対象は常に攻撃可能範囲にいるものとする。
- 移動による攻撃不能時間は0とする。
- 移動そのものの所要時間やDPS損失は計上しない。
- 開幕の配置移動だけは、座標計算をせず `initialActionDelayFrames` の固定遅延として計上する。初期値60Fで使徒別・手動上書き可能とする。
- 敵サイズ・配置でヒット数が変わる場合は、ヒット数プリセットまたは手動値を使用する。
- 対象数で総ダメージが変わる場合は、単体DPSと複数対象総ダメージを分ける。
- 移動後に得るバフなど、効果部分だけ独立して評価できる場合は固定条件としてON/OFFできる。

将来対応する場合も、座標シミュレーションを標準DPSへ直接混ぜず、移動時間や有効ヒット数を供給する別モジュールとして扱う。

### 3.6 コンテンツ・シーズン・ステージルール

コンテンツの恒常ルールと、シーズンまたはステージごとに変わるルールを分離して戦闘条件へ取り込む。敵自身のバフ、使徒の効果、カード効果としては扱わない。

- 次元の衝突の6年生固定、スペル使用不可、遺物数制限はコンテンツの恒常ルールとする。
- 「1秒毎のSP回復量30%増加」のような可変ルールは、対象シーズンまたは敵プリセット側で明示する。
- 可変ルールをコンテンツ定義へ直接固定し、別シーズンにも自動適用しない。
- SP回復量補正とSP回復周期補正は別項目にする。文言が回復量増加なら周期は変更しない。
- 適用中のルール名、補正前値、補正後値、出典プリセットを計算詳細へ表示する。

```js
stageRules: {
  spRecoveryAmountMultiplier: 1.3
}
```

## 4. カード効果の初期台帳

| カード | 効果 | 分類 | DPS上の扱い | 状態 |
|---|---|---|---|---|
| 竜光剣 | 1秒ごとに攻撃速度増加、低学年使用時リセット | periodic, stack, reset | 攻撃間隔を時間ごとに更新 | 要実装 |
| ヴィヴィの銀色の指揮棒 | 普通攻撃ごとに防御力増加、最大時追加効果 | stack | 防御側DPSで命中ごとに更新 | 要実装 |
| ティグの燃え盛る剣 | 普通攻撃3回ごとに攻撃速度増加、最大スタックあり | stack | 普通攻撃回数を計数 | 要実装 |
| エレナの強化ドローン | 低学年使用後6秒間攻撃速度増加 | action, timed | 低学年開始で付与、6秒後終了 | 要実装 |
| シュパンの魔法リュック | 普通攻撃2回ごと、持続6秒、固有CT | stack, timed, cooldown | 回数・持続・CTを同時管理 | 要調査 |
| リスティの模造グローブ | 普通攻撃6回ごとに会心率、持続12秒 | stack, timed | 発動後の命中だけ会心率変更 | 要実装 |
| 起源の聖杯 | 通常攻撃命中時SP回復 | resource | ヒット後にSP加算 | 保留中 |
| キャロットのサトウキビ | 戦闘開始時に同列の毎秒SP回復増加 | static, resource | 編成対象へSP周期量を加算 | 一部対応 |
| 癒やしのペンダント | 1秒ごとに毎秒SP回復量増加 | periodic, resource | 文言上の増加方式を要確認 | 要調査 |
| 古木のダガー | 1秒ごとに毎秒SP回復量増加 | periodic, resource | 文言上の増加方式を要確認 | 要調査 |
| 狂気の仮面 | 1秒ごとに周辺へ最大HP参照ダメージ | periodic, external | 敵数・範囲の仮定が必要 | 要調査 |
| 暗殺者の秘伝書 | 普通攻撃5回ごとに目くらまし、持続2.5秒 | stack, timed | 命中回数と敵状態を管理 | 要実装 |
| アリスのデタラメな呪術 | 5秒ごとにランダムHP/SP回復 | periodic, random, resource | 分岐を1回の抽選として扱う | 要実装 |
| リニュアのタイムパラドックス | ウェーブ開始後30秒間与ダメージ増加 | timed | 0F付与、30秒後終了 | 実装容易 |
| ライフジェム | HP40%以下でHP回復 | external | HP推移がない間は仮定設定 | 後段階 |

カードの同効果非スタック・同一使徒非スタックは、タイムラインへ入る前に現行の重複規則で効果インスタンスを確定する。

## 5. スキル・アサイド効果の初期台帳

| 使徒・効果 | 分類 | DPS上の論点 | 状態 |
|---|---|---|---|
| アリスの低学年・高学年 | random | 低学年で選ばれた分岐と高学年の対応関係 | 試作対応 |
| アメリアなどの強化攻撃 | random, action | 強化確率でモーションとダメージが変化 | 試作対応 |
| アヤ低学年 | external | 敵サイズ・配置でヒット数が変化 | 手動プリセット予定 |
| モモの召喚獣・自爆 | summon, external | 本人行動と別タイムライン、破壊時発動 | 後段階 |
| アレット高学年 | external | シールド破壊時ダメージで即時ダメージではない | 除外対応済み |
| ジェイドの翡翠玉 | stack, resource | 高学年・強化攻撃・低学年で固有スタック連携 | 要設計 |
| シオン低学年の魔弾 | segmented, stack, resource | 魔弾獲得・消費、所持数による攻撃回数と総モーション変化 | 要調査 |
| シストの基本攻撃命中時CT減少 | cooldown | 命中ごとに高学年残りCTを変更 | 要実装 |
| リニュア高学年 | timed | 全行動速度の徐々の加速・減速 | 要調査 |
| エピカ、シスト、ヒルデ等の速度バフ | action, timed | 付与時点、持続時間、対象を管理 | 要実装 |
| シオンA2の低学年ダメージ増加 | action | 低学年だけ自動ON、高学年はOFF | 現行判定あり |
| ティグ高学年の普通攻撃増加 | action, timed | 高学年後の普通攻撃だけに適用 | 要時系列化 |
| リムの苦痛敵攻撃時攻撃力スタック | stack, external, timed | 敵状態、命中、持続、最大数 | 要調査 |
| ロレットの変異 | random, resource | 低学年命中時の分岐とSP回復中断 | 要設計 |
| 状態異常の火傷・毒・苦痛・凍傷 | periodic, external | 付与、更新、持続、独立倍率 | 後段階 |

アサイド、愛用カード、通常スキルは保存場所が異なっても、生成後は同じ効果モデルへ正規化する。

## 6. 生成後に必要な標準項目

```js
{
  effectId,
  ownerId,
  sourceType,
  target,
  modifiers,
  trigger: {
    type,
    actionCategories,
    intervalFrames,
    hitCount,
    probability
  },
  durationFrames,
  cooldownFrames,
  stack: {
    max,
    initial,
    change,
    durationFrames,
    expirationPolicy
  },
  reset: {
    triggerType,
    actionCategories
  },
  motion: {
    model,
    startupFrames,
    loopFrames,
    recoveryFrames,
    loopCountSource,
    minLoops,
    maxLoops
  },
  runtimeMode,
  implementationStatus
}
```

未設定値と0を区別する。未設定は規則不明、0は効果なし・待ち時間なしを意味する。

## 7. 優先して確認する仕様

1. 攻撃速度が途中で変化した際、進行中の普通攻撃待ち時間へ即座に反映されるか。
2. 竜光剣の時間スタック上限と、低学年開始・ヒット・終了のどこでリセットされるか。
3. 同一フレームの周期増加とリセットの優先順。
4. 持続効果の再付与が、更新・加算・重複のどれか。
5. CT減少が残り時間だけに作用するか、次回以降の基礎CTにも作用するか。
6. 普通攻撃「回数」が開始・ヒット・完了のどこで加算されるか。
7. シオン低学年の魔弾獲得・消費順、攻撃回数との対応、各区間のフレーム数。
8. スタック上限時に新しいスタックを得た場合、無効・最古置換・最短期限置換のどれになるか。

## 8. 更新規則

- 個別効果を発見したら本台帳へ追加する。
- 共通動作が確認できたら `dps-simulation-design.md` の規則へ昇格する。
- 推測は「要調査」と明記し、確定仕様と混在させない。
- 実装済みでも検証未完了なら「要検証」とする。
- datasheet列を追加する場合は、先に標準項目との対応を本台帳へ記録する。
