# 公開サイトの将来設計・P5/P6概略

2026-09-13。軽量な設計メモ。利用者が確定した主要URLは`/manager/`と`/calc/`。ルート/API詳細は[URL台帳](public-url-design.md)と[Gate C補足](public-url-gate-c-design.md)、配信先は[配信契約](storage-release-contract.md)を参照する。

## 入口の使い分け

| URL | 当初の役割 | 将来の拡張 |
| --- | --- | --- |
| / | 当面は`/manager/`への静的転送 | 将来は各ページへ遷移するトップページへ差し替え |
| /manager/ | 育成・使徒・カード・編成管理 | 管理機能を既存画面内で追加 |
| /calc/ | 通常ダメージ計算・DPS | 同じ計算ページ内のモードとして拡張 |
| /data/ | 敵・ボードへの小さな一覧 | 閲覧ページが増えたらリンク追加 |
| /data/enemies/ | 敵データ | 既存preset queryを維持 |
| /data/boards/ | 使徒別ボード | 既存apostle/zoom queryを維持 |
| /share/ | 編成共有 | 短いURLと既存payload互換を維持 |
| /transfer/ | データ移行 | 通常ナビから独立した移行導線 |

`manager`／`calc`の名称、`/`の当面の静的転送、`/data/`の一覧ページを確定した。`/data/`一覧は保存状態を持たず、主要ページと同じ上部バー構造・主要導線を維持する。将来のポータル化はhomeの同一論理ID・URLを保ったまま`/index.html`を差し替えて行う。

## トップページへ切り替えるとき

homeとmanagerは別の論理IDにする。「管理」は常にmanager、「計算」は計算ルートを参照し、ホームだけhomeを参照する。計算の論理IDは既存設計のdamageを保持してもよいが、公開URLは/calc/に統一する。ファイル名formation-damage-calc.htmlの改名は不要。

将来のトップページは管理・計算・データへのリンクと短い説明を中心にする。共有URLは編成へ直接到達させ、トップページを経由させない。トップページ表示だけで保存データを書き換えたり、重い管理・計算処理を起動したりしない。

当面の`/`は`/index.html`から`/manager/`へ転送する。将来ポータル化する場合も`/manager/`以下、保存キー、共有payloadは維持する。旧版の転送HTMLがcacheに残る場合の更新確認を行う。以前の`/`が管理画面queryを受けていた場合は、登録済みの管理画面用queryだけmanagerへ接続する互換分岐を残し、未知queryを一律に管理へ送らない。

計算が将来増えても/calc/は既存ダメージ計算の入口として維持する。独立性の高い新計算だけ/calc/<用途>/を検討し、先行して空の階層や汎用ルーターを作らない。管理機能の細分化も実際に別ページが必要になってから判断する。

未公開の旧案/damage/や/calc/damage.htmlは互換URLとして新設しない。実際に公開・告知していた事実がある場合だけaliasへ追加する。

## 実装・公開の進め方

| 段階 | 作業 | 出口 |
| --- | --- | --- |
| P5a：公開物の準備 | manifest・生成・旧HTML互換・リンク/資材/Worker/画像の接続・SW更新 | 新旧baseの生成物をHTTPで直接開き、共有URL/画像・主要画面・query/hash・版整合を確認 |
| P5b：配信準備 | 成果物専用リポジトリ、権限、DNS/Pages、配信記録と停止手順 | 期待したreleaseの新サイトを配信し、旧側の移行案内はまだ有効にしない |
| P6：利用者向け移行確認 | 実Originのルート、保存・転送/ファイル代替、共有、スマホ、cache更新 | 必須確認後に移行案内を有効化。失敗時は案内を停止してデータ保持 |

P5aはソース配置の全面変更を避け、必要な公開物を生成する方式。生成後の内容に対して版を確定し、依存順・自己参照回避を実装前に既存共有資材生成と照合する。旧URL表と新URL表を人手で二重管理しない。

P5bは検査済み成果物を配信し、sourceCommit/profile/releaseを照合できるようにする。新側配信の失敗で旧側を転送させない。外部設定と公開の実施は別の着手指示で行う。

P6はiOS Safari/Android Chromeで代表確認し、デスクトップ狭幅の検査で代用しない。旧側保存データを残したまま転送・ファイル復元を確認する。配信rollbackでは保存データを戻さず、旧版が現在の保存形式を読める場合だけ旧成果物へ戻す。読めない場合は移行案内停止と救出を優先する。
