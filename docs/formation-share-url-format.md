# 編成共有URL 格納仕様 v1

状態: 設計確定、製品v1実装・再計測済み。PNG出力・取り込み・公開は対象外。2026-09-10。

共有対象・バイト形式について本書を正とする。旧設計書のALv/SLv、共通育成、方式の自動選択、計測用TCSB形式より優先する。計測用URLは未公開の実験形式であり製品互換の対象にしない。

## 共有対象

URLと画像は同じ固定済みスナップショットを使う。使徒Lv・Rank・ALv・SLvは抽出、格納、共有表示のすべてから除外する。表示切替や技能レベル欄も設けない。アサイド段階A1〜A3は維持する。

| 対象 | 保持する情報 |
| --- | --- |
| 使徒 | 固定9位置、永続ID、★、アサイド段階 |
| 遺物 | 固定27位置、永続ID、★、はんだ |
| スペル | 永続ID、★、はんだ、枚数。同一ID・同一育成だけ集約 |
| 権能 | 永続IDの列 |
| 全体強化 | アサイド・特殊マス由来の全体%補正合計。内訳・固定値強化は除外 |

任意タイトルは設けず、タイトル用のステージID・敵ID・自由入力文字列も格納しない。共有メモ・現在/予定の独立フラグ・日時・全セーブ・計算結果は格納しない。全体%補正の表示は初期ON。OFFならセクションそのものを送らず、受信側では未受信の情報をONにできない。

## 型と不明値

正規化データでは不明をnullとし、0・空き・対象外と混同しない。保存値の欠落を最大値や0へ補完しない。仕様上の既定値であることを既存保存形式が保証する場合だけ、その値として取り出す。

| 項目 | 正規化値 | ワイヤ値 |
| --- | --- | --- |
| ★ | 1〜5、null | 1〜5、0。不正な6〜7は拒否 |
| アサイド | 0〜3、null、対象外 | 0〜3、4、5。6〜7は拒否 |
| はんだ | 0〜2、null | 0〜2、3 |
| 空き位置 | null | 使徒IDまたは遺物参照の0 |
| 全体%補正 | 非負の十進数、null | スケール付き整数、不明マスク |

アサイド対象外は参照版マスターで確認する。対象使徒の未発現は0。未知はA?、未知の★やはんだは?等で示し、未発現にはA0や説明文を常時表示しない。カード★が不明でコストを確定できなければ総合コストも未確定とし、推定合計を確定値として表示しない。

## 外側と基本型

URLは`formation-share.html#1.z.<payload>`。payloadは、下記バイト列にCRC32を付けてDEFLATE raw圧縮したものの、パディングなしBase64url。製品v1はZのみを生成・受理する。

符号化に使用する圧縮実装・版・設定は一つに固定する。標準APIと環境別実装を切り替えて生成しない。同じ正規化内容と参照版なら同じURLを生成する。製品v1はformation-share-codec.jsへ同梱した依存なしの決定的DEFLATE raw実装（固定ハフマンブロック、同梱LZ77符号化）を使う。ブラウザ標準API、Node zlib、外部ライブラリへ実行時に切り替えない。ファイルサイズは実装時点で34,734 bytes、第三者ライセンス依存はない。

- u8: 1バイト。
- u32v: 最短表現のunsigned LEB128、0〜4,294,967,295、最大5バイト。過長表現、オーバーフロー、終端欠落を拒否。
- フィールドをまたぐビット詰めは行わず、予約ビットは必ず0。

## バイト順序

| 順序 | 格納内容 |
| --- | --- |
| 1 | ASCII `TCSP` の4バイト、形式版u8=1、表示マスター参照版u32v |
| 2 | flags u8。bit0=全体%補正あり。bit1〜7は予約0 |
| 3 | 使徒9枠。各枠は使徒ID u32v。0なら終了、それ以外は状態u8が続く |
| 4 | 遺物辞書件数u32v、各項目は遺物ID u32vと状態u8 |
| 5 | 遺物参照27件をu32vで格納。0は空き、1〜辞書件数は参照 |
| 6 | スペル項目数u32v、各項目はスペルID u32v、状態u8、枚数u32v |
| 7 | 権能件数u32vと各権能ID u32v |
| 8 | bit0があれば全体%補正セクション |
| 9 | ここまでの全バイトに対するCRC-32/ISO-HDLCをlittle-endianの4バイトで追加 |

CRCは反転多項式0xEDB88320、初期値0xFFFFFFFF、最終XOR 0xFFFFFFFF。認証や改ざん防止には使わない。

使徒状態はbit0〜2が★、bit3〜5がアサイド、bit6〜7は0。カード状態はbit0〜2が★、bit3〜4がはんだ、bit5〜7は0。共通育成・直接列挙との自動切替・差分符号化は製品v1に導入しない。

枠順は保存モデルの後列・中列・前列、各列内0〜2。遺物は対応使徒枠順に各3位置。使徒が空きでも遺物参照は保持する。

遺物辞書は27位置の走査における初出順。同一ID・★・はんだだけまとめ、未使用辞書項目は作らない。スペルは元編成の初出順で集約し、集約後の順序を共有表示の正とする。権能の順序は元編成を保持する。

## 全体%補正

全体%補正はHP・物攻・魔攻・物防・魔防・会心・会心DMG・会心抵抗・会心DMG抵抗・SP回復の10項目固定。スケールu8（0〜3）、10bit不明マスクu32v、既知項目だけu32vを順番に格納する。マスクの上位ビットは0。既知0も必ず格納する。

値は607なら607%とする。最大3桁の十進小数を損失なく表す最小共通スケールを採用し、整数化した値はu32範囲内とする。全項目不明または整数ならスケール0。入力の十進表現を基準に変換し、単純な浮動小数乗算の整数判定に依存しない。3桁超や範囲外は明示エラーとし丸めない。実装時に現行データが収まるか確認し、収まらない場合は公開前に形式を見直す。

## 辞書・検証・互換性

永続IDは種別別に追記専用で管理する。番号を再利用・並べ替え再採番しない。表示マスター参照版には名前、画像識別、レア度、愛用品対象、★別コスト、アサイド対象有無など表示に必要な情報を保持する。内容更新時は参照版を増やし、公開済み版を保持する。生成時は最新版、受信時は指定版だけを使う。

受理前に次を確認する。これらは製品v1の受入条件であり、現行ハーネスで検証済みという意味ではない。

- URLデータ部分はBase64url文字数16,384以内。復号前に長さと文字種・正規表現を検証。
- 展開後はCRC込み65,536バイト以内。展開の途中で上限を適用。
- 形式版、参照版、予約ビット、CRC、末尾余剰、IDの存在と種別を確認。CRCが正しくても内容検証を省略しない。
- 使徒9枠、遺物27参照、遺物辞書0〜27件。スペル項目・権能項目はそれぞれ0〜256件、スペル各枚数は1〜65,535、合計も65,535以下。これは通信形式の安全上限でありゲーム内合法編成の判定ではない。現行の選択制限は送信側で維持する。
- 未知の育成値は許容するが、未知IDはエラー。破損時にサンプル表示へ切り替えたり、保存状態から値を補完したりしない。
- 正規化データとの往復一致に加えて、元の保存形式から抽出した意味が一致することを確認。閲覧者の保存状態に読み書きしない。

受入ケースは空編成、1/6/9人、空き使徒位置の遺物、重複スペル、同一カードの異なる育成、全体補正ON/OFF/0/不明/小数、★・A段階・はんだの未知、対象外、範囲外ID・別種別ID・未知版・予約ビット違反・末尾余剰・破損・展開上限超過を含める。抽出時にタイトル・ステージID・敵ID・ALv・SLvを含めないことも確認する。

## 製品への接続設計

責務は次の4つへ分ける。ファイル名は実装時に既存構成へ合わせてよいが、依存方向は維持する。

| 部分 | 入力と責務 |
| --- | --- |
| 表示マスター | 種別別の永続IDと版固定の表示情報。codecと描画へ渡す |
| 共有スナップショット抽出 | 編成画面の作業中状態を明示引数で受け取り、共有対象だけをコピー。保存・DOM・URL生成はしない |
| codec | 正規化データと表示マスターから符号化・検証・復号。ブラウザ保存や最新ゲームマスターを参照しない |
| 共有UI | 固定データを描画し、作成側でコピー、受信側で復元。試作の画像・配置・配色を継承 |

正規化データのアサイド対象外は文字列`notApplicable`、不明はnullとする。IDは抽出後に参照版の整数へ解決する。種別は各フィールドで決まり、同じ整数が別種別にも存在すること自体は不正ではない。種別違反テストには、そのフィールドの辞書には存在しない番号を使用する。

### 作成側のデータ取得

編成画面の「共有」を押した時点の作業中状態を利用する。未保存編集を含め、編成・使徒育成・カード育成を同一時点で固定する。各ファイルのローカル保存を後から別々に読む方式にしない。参照するcurrent/planned側は画面で選択されている側と一致させ、反対側の値で欠損補完しない。側の区別がない既存項目は共通値を使う。

`formation.rows`の位置、`formation.spells`の採用列、`formation.masterPowers`、対応する使徒・カード状態を取り出す。現在の保存形式はカードIDごとの育成が共通であるため、それを各採用位置へ適用する。受信仕様は将来や他入力に備えて同一カードの異なる育成も保持する。

全体%補正は共有時点の作業中育成に対して、既存の全体効果集計を利用し一度だけ取得する。共有のための独自計算式を作らない。各使徒に複製されたstatSnapshotsを合算・平均・最大値選択しない。既存の圧縮保存値を読む必要がある場合は既存復元処理を利用し、取得元・側・鮮度を確認できない値は不明とする。共有UIで取得できない旨を示し、更新または全体%補正OFFで共有できるようにする。個別バフや編成シナジーを全体強化へ追加しない。

試作の`getCardState`等の既定値補完、`Number(...) || 0`、current→plannedの自動フォールバックは共有抽出へ流用しない。旧保存形式の既定値適用は既存保存仕様で証明できる項目だけに限定し、抽出テストへ根拠を残す。

### 作成・受信の画面

作成プレビューは編成画面内で固定スナップショットから開く。全体%補正のON/OFF、リンクをコピー、最新の編成で更新、閉じるを提供する。ON/OFFは保持した固定値から送信対象を選ぶだけで、元の保存状態を書き換えない。コピー対象のURL文字数を表示する。

受信ページ`formation-share.html`はfragmentだけから復元する。fragmentなしはリンク未指定、未知版・破損・過大入力は対応するエラー表示。保存値・サンプル・queryのタイトル等へ切り替えない。ブラウザ保存を参照せず、テーマ初期値はOS設定、手動切替はページ内だけで保持する。

作成プレビューと受信ページは同じ描画処理を使う。表示は使徒と遺物、スペル、権能、全体%補正。権能は受信した全件を表示し、総合コストへ各件30を加算する。画像欠落は名前等で代替し、未知IDとは区別する。アサイド未発現や対象外の説明、Lv/Rank/ALv/SLv、タイトル、試作説明は出さない。不明な必要値だけ?等で明示する。

コピーはユーザー操作から実行し、Clipboard API失敗時は生成済みURLを選択できる欄を出す。コピー成功は成功後にだけ表示する。生成URLは現在のアプリ配下の`formation-share.html`を基準にし、既存query/fragmentを引き継がない。ローカル確認時も同じ相対配置で動く。

### 公開前の互換性・検証

初期永続IDの割当結果と表示マスターv1をファイルとして固定し、以降の追加は追記のみ。旧版を既存マスターから再生成して上書きしない。公開済み版の画像識別先は保持し、画像だけ欠落した場合は代替表示で育成数値を残す。

圧縮処理はformation-share-codec.jsの同梱実装へ固定した。外部依存はなく、ブラウザとNodeが同じコードパスで固定ハフマンDEFLATE rawを生成・復号する。展開は各リテラル・一致コピーごとに65,536 bytes上限を適用し、受信前にpayload長も検証する。製品v1の生成物はこの実装の固定ブロックだけで構成し、動的ハフマンブロックは受理しない。Node zlibの展開結果との一致をテストしているが、Node zlibは製品ランタイムの依存ではない。

符号化と復号だけが同じ誤りを共有するのを避けるため、CRC既知ベクトル（ASCII 123456789→0xCBF43926）、手で確認可能な状態バイト・varintの期待値、固定URL復元fixtureを含める。欠損・除外項目・側の違いは実際の保存形式のfixtureから検証する。

本番マスターのID幅、最大装備、全スペル、重複、育成のばらつき、全体補正の未知・小数を含めURL全体長を再計測する。代表例と形式上限ケースを分け、「最大」は何の上限か併記する。PNG保存は次のGoalへ分け、今回の画面に未動作の保存ボタンを出さない。
