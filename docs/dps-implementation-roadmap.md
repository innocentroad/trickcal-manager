## 次の実装予定

優先度は「単体DPSの検証精度」と「後から編成全体へ拡張しやすいこと」を基準にする。

計算負荷の改善は[DPS計算軽量化設計](dps-performance-design.md)に分離して管理する。不要な記録停止・debounce・決定的条件のseed短縮、Worker化、待機区間の高速化、生成物・周期効果・時限効果・行動待機・基礎SP・外部イベント・行動内イベントの次回時刻キュー化まで試験実装済み。次は待機区間に残る旧式の保険判定を整理し、旧方式との長時間・多seed比較で差分と速度効果を確認する。

## 実装優先と要検証の切り分け

現段階では、ゲーム内でしか確定できない差異が残っていても、DPSの基本構造・データ変換・表示・比較・回帰テストを止めない。未確定値は暫定規則として実装し、フレーム規則台帳へ要検証事項を残す。

### ブロッカーとして扱う項目

次のいずれかが発生した場合だけ、後続実装を止めて修正する。

- 生成データの欠落・壊れた参照・生成スクリプトのエラー
- DPS計算が停止する、結果が`NaN`・無限大になる、またはタイムラインが生成できない
- 同じ効果が単発計算とDPSの両方で二重適用される
- 明示された発動条件を無視して、対象外の行動・使徒・敵へ効果が発動する
- 既存の確定済み単発ダメージ計算を変更してしまう

### 実装を先行してよい項目

- 実測値が未確定でも動作するイベント・効果・生成物のデータ構造
- 発生元、対象行動、効果分類、`eventOrder`、`processGroupId`、`stackGroupId`の受け渡し
- 未調査値を終了時補完・未発動・外部待ちとして扱う安全なフォールバック
- 行動別内訳、効果監査、基準比較、要検証表示、回帰テスト
- Worker、キャッシュ、待機キューなどの計算経路整理

### ゲーム内検証後に確定する項目

- `ideal`／`gameUpdate`のSP周期と速度変更時の位相
- 攻撃速度・加速の式、適用順、丸め位置
- 同一フレームの期限切れ・再付与・本体・生成物の厳密な順序
- 多段攻撃の実測発生F、倍率配分、敵サイズ・対象数分岐
- 被弾回数、シールド破壊、撃破、HP閾値など外部イベントの発生条件
- 即時高学年発動時のキャンセル対象と、発射済み生成物の存続

要検証項目は精度差の原因を追跡できるよう、結果に暫定・補完・外部待ちの区分を残す。検証完了後にだけ台帳の状態を「実測確定」へ更新する。

1. **行動倍率補正カテゴリの分離**（実装済み・2026-08-25）
   - datasheetへ`ダメージ補正区分`を追加し、`damageAmount`・`actionMultiplier`・`special`・`other`を生成する。
   - 単発計算へ`actionMultiplierBonusP`系キーを追加し、基礎行動倍率・補正値・補正後行動倍率を詳細表示する。
   - DPSの基礎プロファイル、ヒット時評価、効果監査、比較スナップショットへ同じカテゴリを通す。
   - シオンA2など明確な候補から移行し、`ダメージ量増加(その他倍率)`の矛盾行は自動変換せず監査TSVへ出す。明示区分がある行は旧来の`(その他倍率)`文面推定を通さない。
2. **発生タイミングの品質表示**（実装済み・2026-08-23）
   - 実測ヒット、終了時補完、生成物ヒット、DoT tickを集計表示する。
   - DPSの数値が暫定モーションに依存している範囲を画面上で確認できるようにする。
   - 単一seedの累積ダメージをCanvasで表示する。平均DPSは既存の集計欄で表示する。
3. **多段・生成物の発生イベント精度向上**（一部実装済み・2026-08-25）
   - 発生F、倍率配分、対象数、生成個体ごとの攻撃をdatasheetから正規化する。
   - 同一フレーム内の発生順を`eventOrder`として保持し、スキル本体・生成物生成・生成直後の攻撃の順序を再現する。
   - 残りは対象数・敵サイズ分岐、未調査倍率配分、可変ループの実測値反映。
4. **攻撃速度・SP・CTの丸め検証**
   - 速度変更中、周期イベントと行動開始が同一フレームになる場合の順序を固定する。
   - 端末・戦闘速度変更時の量子化を検証する。
5. **外部イベント入力**
   - 周期型とイベント駆動型（シールド破壊、被弾、HP閾値、撃破、状態遷移など）を分類し、非周期イベントを間隔推定で処理しない。
   - シールド破壊、被弾、撃破、敵状態終了などを手動入力／プリセット入力で再現する。
   - スノキー、ヴィヴィ、リムなどの条件を対象にする。
6. **ランタイム効果の重複・同列判定の整理**
   - 効果ソース、同一使徒非スタック、同列スタックを一意なインスタンスとして管理する。
   - 竜光剣の二重加算のような重複を監査ログで検出する。
7. **敵側タイムライン**
   - 敵バフ、デバフ、状態異常、敵SP、高学年スキルを同一時計へ追加する。
8. **複数使徒の編成全体DPS**
   - 味方全員を同じ戦闘時計で進行し、共有バフ・敵状態・対象数を統合する。

## 現時点の注意事項

- 速度データがない行動はDPSを計算せず、行動別適用効果だけを表示する。
- ヒット発生Fが未調査の場合は、原則としてモーション終了時に全倍率を発生させる。
- 敵サイズ、配置、移動、索敵、被弾・撃破イベントはプリセットまたは手動条件が必要。被弾・シールド破壊・HP閾値などのイベント駆動条件を、普通攻撃間隔やスキルCTへ置き換えて発生させない。
- 時系列効果は単発ダメージのON/OFFとは別管理し、同じ効果を二重適用しない。
- 「試験実装済み」はコード上の処理がある状態であり、ゲーム内実測で確定したことを意味しない。

各項目の詳細と個別効果の進捗は、[DPS特殊効果台帳](dps-effect-inventory.md)と[DPS・行動タイムライン基礎設計](dps-simulation-design.md)を正とする。
