# ステータス管理・複数タブ保存設計

## 1. 目的

複数のステータス管理タブとダメージ計算タブを同時に開いても、次を保証する。

- 別タブで保存したスロットを古いタブから巻き戻さない。
- 各タブの未保存編集を別タブから自動変更しない。
- 同じスロットの同時編集を黙って後勝ちにしない。
- ダメージ計算へ同期される作業状態の出所を一意にする。
- 既存の保存スロットを移行時に失わない。

## 2. 現状の問題

現在は作業中状態、保存スロット、表示中スロットを `trickcal_stat_prototype_v1` の1キーへまとめ、各タブが `appState` 全体を保存している。

`syncRevision` は保存ごとに増えるが競合判定には使われておらず、ステータス管理側には `storage` イベント監視もない。古いタブが後から保存すると、別タブで更新した保存スロットまで古い内容へ戻す可能性がある。

## 3. 状態を3つに分離する

### 3.1 共有する保存スロット

`localStorage: trickcal_stat_slots_v2` には保存スロットだけを格納する。

- 一覧全体に `storeRevision` を持つ。
- 各スロットに `slotRevision`、`savedAt`、`savedBy`、`snapshot` を持つ。
- 保存・削除直前に必ず最新ストアを読み直す。
- 対象スロットだけを差分更新し、古い一覧全体を書き戻さない。

### 3.2 タブごとの作業状態

`sessionStorage: trickcal_stat_workspace_v2` に次を格納する。

- `workspaceId`
- `activeSlot`
- 読込時の `baseSlotRevision`
- 未保存の `draft`
- 選択使徒など、作業状態に含まれる表示対象

`activeStateSlot` と未保存編集はタブ間で共有しない。リロードでは同じタブのドラフトを復元する。タブ自体を閉じるとsessionStorageのドラフトは破棄されるが、共有保存スロットには影響しない。

ページ実行ごとの `tabInstanceId` はメモリ上で毎回新規生成し、sessionStorageから復元しない。ブラウザの「タブを複製」でsessionStorageがコピーされても、2タブが同じ送信元IDにならないようにする。複製されたドラフトは同じ `baseSlotRevision` を持つため、片方を保存した後のもう片方は通常の競合判定へ入る。

### 3.3 ダメージ計算用ライブ状態

`localStorage: trickcal_stat_live_v2` はダメージ計算との同期専用にする。

- `revision`
- `sourceTabInstanceId`
- `sourceSlot`
- `publishedAt`
- `snapshot`

最後に操作された前面のステータス管理タブを同期元とする。背景タブはドラフトを保持するがライブ状態を更新しない。タブが `focus` または `visibilitychange` で前面になった時、そのタブの状態を公開する。

## 4. 保存時の競合判定

保存ボタンを押した時点で最新スロットを読み直す。

- 最新 `slotRevision` と読込時 `baseSlotRevision` が同じなら保存する。
- 異なるなら別タブ更新ありとして通常保存を止める。
- 現在内容と最新内容のハッシュが同じなら、最新Revisionを採用して保存済みに戻す。

競合時は現在内容で上書きするか確認する。キャンセルした場合は編集を保持したまま保存UIへ戻り、別スロットへの保存または最新内容のロードを選べる。

現在内容と最新内容が実質的に同じ場合は確認を省略し、最新Revisionを採用して保存済みに戻す。

## 4.1 ボード・編成内の保存との境界

個別ボード、全体ボード、編成の各「保存」は、そのタブの作業状態へ確定する操作として扱う。これらは共有スロットを直接更新しない。

そのため、別タブのボード確定や編成保存で現在タブの編集中内容が変わることはない。セーブ／ロード欄から状態スロットへ保存する時だけ `slotRevision` を検査し、同じスロットへの競合を止める。

## 5. 外部更新を受信した時

`BroadcastChannel('trickcal-stat-sync-v2')` を主経路、`storage` イベントをフォールバックにする。

| 外部更新 | 現在タブ | 動作 |
|---|---|---|
| 別スロットを保存・削除 | 任意 | スロット一覧だけ更新 |
| 同じスロットを保存 | 変更なし | 最新内容へ自動更新して通知 |
| 同じスロットを保存 | 未保存変更あり | 編集を保持して「別タブ更新あり」 |
| 同じスロットを削除 | 変更なし | 現在内容を未保存の新規状態として保持 |
| 同じスロットを削除 | 未保存変更あり | 編集を保持して削除競合を表示 |

未保存変更があるタブへ外部スナップショットを自動適用しない。

## 6. UI状態

保存UIは次を区別する。

- 保存済み
- 未保存変更あり
- 別タブ更新あり
- 別タブで削除済み
- 競合解決後・保存済み

「別タブ更新あり」では保存ボタンから通常保存せず、競合解決ダイアログを開く。

## 7. Undo / Redo

- Undo / Redo履歴はタブローカル。
- 未保存編集中に外部更新を受信しても履歴を維持する。
- 外部更新を自動適用した時は履歴をクリアする。
- 外部内容を読み込む競合解決操作を新しい履歴起点にする。

## 8. v1からの移行

1. `trickcal_stat_prototype_v1.savedStates` をv2スロットへコピーする。
2. 現在作業状態をworkspaceとliveへコピーする。
3. 各 `slotRevision` を1として開始する。
4. 少なくとも1リリースはv1読込をフォールバックとして残す。
5. v2が存在する場合はv1の古い内容を上書きに使わない。

## 9. 実装順

1. 保存スロットを共有キーから分離する。
2. 保存・削除を最新読込＋対象スロット差分更新へ変更する。
3. `slotRevision` による競合拒否を追加する。
4. BroadcastChannelとstorage受信を追加する。
5. 作業ドラフトと表示状態をsessionStorageへ分離する。
6. ダメージ計算用live状態と前面タブ所有権を追加する。
7. v1移行と複数タブ検証を行う。

## 10. 必須テスト

- タブAとBで異なるスロットを保存しても両方残る。
- AとBで同じスロットを開き、A保存後にB保存すると競合になる。
- 同じスロットのBが未変更ならA保存後にBへ自動反映される。
- Bが未保存編集中ならA保存後もBの編集内容が変わらない。
- Aがスロットを削除してもBの未保存編集を失わない。
- 背景タブの遅延保存が前面タブの新しい保存を巻き戻さない。
- ダメージ計算は最後に操作した前面タブのライブ状態だけを読む。
- タブをリロードしてもそのタブの未保存ドラフトを復元する。
