## P0で必ず決めること

設計の成果物は「検討事項の一覧」ではなく、次を決定した実装契約とする。

| 契約 | 決める内容 | 既存成果・確認が必要な点 |
| --- | --- | --- |
| A1 保存API | 通常書込・削除の返り値、失敗通知、同期／非同期、終了時flushとの接続 | 実保存順と例外境界を利用。同期flushと非同期排他の両立方法を明記 |
| A2 排他と世代 | 全writerへの適用範囲、復元中・古いタブの書込拒否、非対応環境の復元可否 | フラグ確認だけでは排他保証としない。導入前の旧タブは終了／再読込が必要な運用を定義 |
| A3 復元・復旧 | ジャーナル、commit点、各失敗後の次状態、再起動時の処理順 | local成功/session失敗、退避不能、復旧書込失敗を別々に決める |
| B1 対象データ | 全キーの必須／任意／除外、保存slotと現在ドラフト、正データとmirror | 他タブの未保存編集は取り込めない範囲として明示。欠損／空／削除／不正を区別 |
| B2 形式・互換 | 外側形式版、内部schema、validator/converter、未知版、生データ救出 | 既存slot exportとは別形式。新側のみの設定の保持／削除を項目別に固定 |
| B3 一貫性・容量 | 現タブ入力確定、他タブ更新時の取得やり直し、ファイル／展開上限 | 既存fixtureと全slot・設定を含む代表データで実測し、上限根拠を記録 |
| C 配信 | 新公開用リポジトリ、成果物受渡し、ルート、資材版生成順、停止操作 | ドメインは確定済み。必要な資格情報と公開許可は実装の前提と区別して一覧化 |

契約が成立しなければ「追加調査」全般へ戻さず、未決の決定を一つと、それを決める最小の検証を示す。API／排他／復元境界の新方式をLunaが推測して補わない。外部サービスの設定・対応環境はC確定時と実施時に公式情報で確認する。

## P1の限定した出口

1. 実`persistState`へつないだ仮想時計を用意し、実イベントを新しいcontextで個別実行する。pending有無、119/120ms、hidden/visible、flush後の二重保存なしを確認する。
2. 正常、session書込失敗、live読込失敗、live書込だけ失敗、legacy書込だけ失敗を区別する。領域・キー・操作で注入し、共通ログ、残存値、メモリ／保存revision、通知、戻り値を確認する。
3. 共通検査でコメント追加は成功、実アクセス追加は違反となることを確認する。既存の領域／operation／access site／Pages不一致など元必須反例を同じ入口へ接続し、各反例の狙った診断をassertする。簡略validator成功を全入口の証拠にしない。既存parserを利用し、新しい構文対応を増やさない。
4. P2/P3で変更する実入口の変更前証拠を確保する。DPS起動と対象切替、既存export/import、起動時のfallback・旧形式・他領域不変は、旧テストの不足だけを補う。手動確認を使った場合は操作・入力・結果を残す。

1〜3は検査ツールの限定修正一単位。4の実ページ確認は別単位で見積もる。「全部あと1スライス」とは扱わない。対象入口の証拠が取れなければ、その入口を変更する工程だけ止め、P0や配信設計は進められる。

実quota上限、複数キー復元、Origin転送は41条件に足さずP3/P4の製品条件として管理する。IndexedDB不導入の静的確認をnative実行へ拡大するなど、本番の保護に結び付かない追加検証は行わない。

## 残量・変更管理

現在はP0〜P6の7工程が残る。P1〜P5はそれぞれ複数の変更単位になり得る。これは7回の作業で公開できる約束ではない。最初の見積もり更新点はP0終了、次はP3の復元リハーサル終了とする。

レビュー指摘は、データ消失・誤成功表示・互換性・未保護writer・必須証拠不足なら該当出口で修正する。非機能的な磨き込みは後続へ記録する。新しい条件を加える場合は具体的リスクと適用工程を明示する。3スライス連続停滞なら停止するが、設計判断が未決と分かった時点で早めに判断へ戻す。
