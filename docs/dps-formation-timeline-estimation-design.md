# 編成内使徒タイムライン推定 設計

## 1. 目的

単体DPS計算では選択中使徒だけを正確な行動主体として扱う。編成内の別使徒が持つ時限バフ・デバフについて、本人の発動タイミングを推定し、選択中使徒のDPSへ反映できる試験モードを追加する。

標準設定は`off`とする。未調査データを自動近似して通常結果へ混ぜない。

完全な支援時計を有効化する前段として、編成から軽量なイベント候補を抽出し、利用者が選んだ候補だけを外部イベントへ追加できるようにする。候補は編成・育成・効果設定からDPS入力を作る時に一度だけ生成し、seed試行内では再計算しない。

## 2. モード

| モード | 表示名 | 処理 |
|---|---|---|
| `off` | 編成行動を推定しない | 常時・戦闘開始時・ウェーブ開始時・共通周期だけ反映。本人行動が必要な効果は外部待ち |
| `supportEstimate` | 支援効果のみ推定 | 別使徒の行動時計を生成し、バフ・デバフ・SP・CT・状態付与の発生だけ共有時計へ投入 |
| `fullFormation` | 編成全体DPS | 将来用。別使徒の攻撃ダメージも集計する |

初期実装では`off`と`supportEstimate`だけを対象とする。

## 3. 推定する状態

編成使徒ごとに独立して次を保持する。

- 普通攻撃間隔、基本・強化攻撃の通算回数
- SP、毎秒SP回復、低学年発動待ち
- 高学年CTと発動モード
- 現在行動、終了予定、行動内effectId発生時刻
- 本人の攻撃速度・加速・固有リソース
- 生成物のうち支援効果発生に必要なイベント

選択中使徒と敵状態は共有戦闘状態に置き、別使徒が発生させたバフ・デバフ・状態異常だけを共有イベントキューへ送る。

## 4. 高学年の扱い

編成推定をONにしても、別使徒の高学年は標準で`disabled`とする。高学年はプレイヤー操作やコンテンツ条件の影響が大きいため、次から明示選択する。

- 発動なし
- オート発動
- 初回のみ発動
- 指定秒で発動（将来）

選択中使徒の高学年設定とは分離する。DPS画面の既存「高学年」設定を編成全員へ流用しない。

## 5. データ不足時の方針

| 不足データ | 推定 |
|---|---|
| 普通攻撃間隔なし | その使徒の行動推定を停止 |
| モーションのみ、発生Fなし | モーション終了時発生として明示的に近似 |
| 発動元effectIdの発生Fなし | 固有状態・生成物等は発動させない |
| SP回復量なし | 低学年を発動させない |
| 高学年CTなし | 高学年を発動させない |
| 移動・射程なし | 初動だけ共通設定を利用し、移動差は警告 |

推定不能な効果を選択中使徒の同種行動へ接続しない。

## 6. 効果分類

### 推定モードなしでも反映

- 常時編成効果
- 戦闘開始時
- ウェーブ開始時
- 共通戦闘時計の`n秒ごと`

### 支援タイムラインが必要

- 普通攻撃・強化攻撃・低学年・高学年の使用、終了、命中
- 生成物生成、攻撃、命中、帰還、消滅
- 固有状態・リソースの獲得、消費、終了

### 外部イベントが必要

- 被ダメージ、HP閾値
- 味方戦闘不能、敵撃破
- シールド破壊
- 攻撃対象や配置に依存する条件

支援推定をONにしても、外部イベント条件は自動成立させない。

## 7. UI

DPS計算設定へ「編成行動推定」を追加する。

- 初期値: OFF
- ON時: `推定`バッジと警告を常時表示
- 別項目として「編成高学年」を表示し、初期値は発動なし
- 行動別適用効果では`外部待ち`、`推定待ち`、`推定ON`を区別
- タイムラインには発動者名を表示
- 比較基準には推定モードと編成高学年設定を保存

### 7.1 イベント候補（実装済みの前段機能）

- 「外部イベント（手動）」内の「編成から追加」に候補を表示する
- 同じ編成使徒・同じ行動条件に属する複数効果は1候補へまとめる
- 追加前はDPSへ反映しない。追加後は通常の外部イベントと同様に開始秒・間隔・回数を編集できる
- 高学年はCT、低学年は必要SPと毎秒SP、普通攻撃は調査済み間隔から簡易推定する
- 低学年の行動待ち・モーション、強化攻撃周期など未計上要素は推定根拠へ明記する
- 候補イベントから攻撃速度、時限ダメージ補正、SP回復を発火できる
- 周期化できない候補（被弾、HP閾値、撃破、状態遷移、生成物、リソース／回数など）は、発動者のCT・普通攻撃間隔へ置き換えず、`event`候補として発生秒を手動入力する。低学年／高学年スキル効果発生や固有状態付与などでも、発動元行動を解決できるものは`periodic`候補として行動周期の予測値を初期入力する
- 候補追加後も`timingMode`、イベント分類、`once`／`repeatable`／`counted`、発動元・条件値を保存し、ランタイムの外部トリガー照合へ渡す
- 候補配列と手動イベント配列をキャッシュキーへ含め、候補抽出自体はseedごとに走らせない

### 7.2 DPS外部イベント採用候補リスト

対象は、編成内の別使徒が選択中使徒へ与える攻撃力、攻撃速度、与ダメージ量、会心系、敵防御低下、SP、クールタイム等の補正である。別使徒自身の攻撃ダメージ、召喚物ダメージ、回復や防御だけの効果は、現在の単体DPSへ直接加算する候補には含めない。

#### A. 既存候補として扱えるトリガー（簡易推定）

発動者の行動時計を開始秒・間隔・回数で表せるもの。候補追加後は推定であることを表示し、初期値を確定値として扱わない。

| トリガー | 現行データの対象例 | 推定方法 | 状態 |
|---|---|---|---|
| `低学年スキル使用時` | エピカ、ウイ、ネル、ローネ | 必要SPと毎秒SP | 実装済み |
| `高学年スキル使用時` | リニュア、スピッキー、ヒルデ、ローネ | 高学年CT | 実装済み |
| `普通攻撃使用時` / `普通攻撃命中時` | 今後の味方対象バフ・SP・CT効果 | 普通攻撃間隔 | API対応済み・該当データ要確認 |
| `強化攻撃使用時` / `強化攻撃命中時` | 今後の味方対象バフ・SP・CT効果 | 普通攻撃間隔を暫定利用 | API対応済み・強化発生周期は未計上 |
| `低学年スキル終了時` / `高学年スキル終了時` | ピラA2などの終了後会心DMG補正 | 現在は使用時刻へ近似 | 候補化可能・終了時刻は要改善 |

`使用時`と`命中時`は同じ行動時計へそのまま置かず、命中フレームを取得できる場合だけ別候補として扱う。現在の簡易候補は行動開始時へ寄せるため、推定根拠に近似であることを残す。

#### B. 効果の発動元を解決できれば採用したい候補

次の効果は実データ上、選択中使徒のDPSへ影響し得る。ただし、行動名だけでは発動時刻を決められず、`triggerSourceId`またはskillmotionの発生フレームが必要である。

| トリガー | 現行データの例 | DPSへの影響 | 追加に必要なもの |
|---|---|---|---|
| `固有状態付与時` | エピカ高学年 `Epica_high_e04/e05` | 周囲の味方の攻撃力 | 高学年CTを周期の初期値として入力し、固有状態付与までの発生フレームは未確定として残す |
| `リソース変化時` | ピラ `Pira_passive_e01/e02`、シストA2、ヘイリーA2 | 味方攻撃力・攻撃速度 | リソース発生元、獲得・消費イベント、対象選択 |
| `状態発動時` | イードA2 `ED_aside_2_e05` | 味方SP回復による次回スキル時刻 | 状態の発動対象と発動回数 |
| `回復時` | ヒルデA2 `Hilde_aside_2_e01/e02` | 回復対象の攻撃速度 | 強化攻撃の回復フレームと対象選択 |
| `低学年スキル効果発生時` | ベニー、ポーシャー | 現行データでは自己効果・回復・敵分岐が中心 | 味方DPS補正の対象確認、効果発生フレーム、分岐結果 |
| `高学年スキル効果発生時` | セリーネ愛用品 | 現行データでは自己効果が中心 | 味方DPS補正の対象確認、高学年内の発生元フレーム |

この区分では、候補を追加するために行動の開始秒だけを流用しない。発動元のフレームがない効果は、引き続き`外部待ち`または`未対応`として表示する。

#### C. 編成全体タイムラインまたは手動外部イベントが必要な候補

発動者の行動だけでなく、対象状態、敵状態、対象数、撃破、味方の戦闘不能、生成物や固有リソースを追跡する必要があるもの。

- `n回ごと`：スノキー等。別使徒の攻撃回数と強化攻撃の発生周期が必要。
- `生成物生成時`、`生成物攻撃時`、`生成物命中時`、`生成物到着時`、`生成物消滅時`：ヘイリー、ロレット、モモ等。生成物の独立時計が必要。
- `状態付与時`、`状態終了時`、`固有状態付与時`、`固有状態終了時`：状態インスタンスと発動元を共有する必要がある。
- `敵撃破時`、`味方戦闘不能時`、`自身HP以下到達時`、`被ダメージ時`、`シールド破壊時`：敵・味方の戦闘状態を外部入力または編成時計から与える必要がある。
- `攻撃対象未撃破時`、対象数・配置・範囲に依存する条件：対象選択と空間条件が必要。

`n秒ごと`と`ウェーブ開始時`は共通戦闘時計で再現できるため、別使徒の外部イベント候補へ重複登録しない。

#### 周期化できないイベントの分類

Aの候補は、発動者の行動周期を使って開始秒・間隔・回数へ近似できる「周期型」である。次の条件は原則として行動間隔から発生時刻を決められないため、「イベント駆動型」として別分類にする。ただし、`triggerSourceId`と行動カテゴリから発動元行動を一意に解決できる状態付与・効果発生は、発動元の周期を暫定初期値にできる。これは発生フレームを確定したものではない。被弾、閾値、撃破、状態終了、生成物、回数・リソース遷移など、発動元行動だけでは決まらないイベントには周期を推測して設定せず、発生した事実または発生時刻を入力する。

| 分類 | トリガー例 | 発生を確定する情報 | 候補の扱い |
|---|---|---|---|
| 戦闘状態・閾値 | `シールド破壊時`、`HP閾値到達時`、`敵撃破時`、`味方戦闘不能時` | 対象ごとのHP・シールド・生存状態の遷移 | 原則一回型。敵・味方タイムライン、プリセット、または明示した発生秒を使う |
| 被弾・被ダメージ | `被弾時`、`被ダメージ時` | ダメージインスタンス、被弾対象、被弾回数 | 反復型。被弾を普通攻撃間隔へ置き換えず、実際の発生イベントまたは明示した発生秒を使う |
| 状態遷移 | `状態付与時`、`状態終了時`、`固有状態付与時`、`固有状態終了時` | 状態の発動元、対象、付与・終了時刻、スタック | 発動元行動を解決できる付与イベントは周期の予測値を初期入力し、発動元フレームがなければ外部待ちまたは手動イベントとする。終了は状態期間を別に扱う |
| 回数・リソース遷移 | `n回ごと`、`リソース変化時`、スタック数到達時 | 行動・命中・リソースのカウンタと消費順 | カウント型。行動周期が分かっていても、回数条件を検証せず一定秒間隔へ丸めない |
| 生成物ライフサイクル | `生成物生成時`、`攻撃時`、`命中時`、`到着時`、`消滅時` | 生成個体の独立時計、生成・攻撃・命中・消滅イベント | 生成個体ごとのイベント型。親スキルの開始時刻だけを発生時刻として流用しない |
| 対象・空間条件 | `攻撃対象未撃破時`、対象数・配置・範囲に依存する条件 | 対象選択、生存状態、配置、範囲、距離 | 対象決定時に評価する。単体行動の候補へ無条件で追加しない |

イベント駆動型には、次の共通ルールを適用する。

- `シールド破壊`、`HP閾値`、`敵撃破`、`味方戦闘不能`は、対象ごとの一回型を基本とする。再発生する仕様が明示されている場合だけ対象・回数を分ける。
- `被弾`、状態付与・終了、リソース変化は反復し得るが、反復回数や発生間隔をデータから確定できない場合は未確定のままにする。
- 候補メタデータには少なくとも、`timingMode: periodic | event`、イベント分類、`once | repeatable | counted`の再発性、発生元の解決状態を保持する。これは候補の表示・入力方式を分けるための分類であり、イベントを自動発動させる許可ではない。
- 周期型、および発動元行動を解決できる一部の効果発生・状態付与候補は、開始秒・間隔・回数へ予測値を初期入力できる。イベント駆動型は発生秒または発生イベントを初期値とし、間隔は利用者が明示した場合だけ使う。複数回の非周期イベントを一つの周期イベントへまとめない。
- `triggerSourceId`や発生フレームを解決できる場合は内部タイムラインへ接続する。解決できない場合は、選択中使徒の行動開始時刻で代用せず、`外部待ち`または`未対応`として監査に残す。

#### 公開候補へ出すための判定

候補生成では、トリガー文字列の部分一致で採用範囲を決めない。少なくとも次を満たす行だけを公開候補にする。

1. 発動者が編成内の別使徒として特定できる。
2. 選択中使徒へ届くDPS関連補正である。
3. トリガーが許可された行動種別である。
4. 周期型なら開始秒・間隔・回数、イベント駆動型なら発生秒・発生回数または発動元イベント／フレームを用意できる。
5. 未計上の強化攻撃周期、対象選択、状態条件を推測で補っていない。

この基準により、`低学年スキルで敵撃破時`や`生成物命中時`を、単に「低学年スキル」「高学年スキル」という文字を含むだけで行動候補へ混ぜない。ギデオンのアサイドも公開候補の通常ルールで判定する。

## 8. 計算結果の区別

推定モードの結果には次を付与する。

```js
{
  formationTimelineMode: 'supportEstimate',
  estimatedActorIds: [],
  skippedActorIds: [],
  estimatedEventCount: 0,
  estimationWarnings: []
}
```

通常の単体DPS結果と推定結果はキャッシュキーを分ける。基準比較でもモードが異なる場合は警告し、自動比較しない。

## 9. 実装順

1. 編成から外部イベント候補を軽量抽出し、選択追加できるようにする（完了）
2. 設定値とキャッシュ・比較キーを追加（標準OFF、設定配線まで完了）
3. 編成使徒ごとの支援時計をWorker内で生成
4. 普通攻撃・低学年起点のバフから対応
5. 高学年オートを別設定で追加
6. 生成物・固有状態・リソースへ拡張
7. 実測と比較し、使徒ごとに推定可否を表示
