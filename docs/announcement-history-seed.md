# 更新履歴の初期原稿

作成日: 2026-09-19。利用者提供のDiscord更新告知（2026-06-05〜2026-09-19）を整理したもの。表示コードには未接続の原稿であり、この文書の追加ではサイト表示・公開内容は変わらない。

## 取り込み・表示方針

- 日付は告知本文の更新日を採用。本文に日付のない8/28は投稿の日付を採用。実際のデプロイ日時を照合した記録ではない。
- `game-data`＝ゲームデータ、`feature`＝サイト機能（改善を含む）、`fix`＝不具合修正。同日・同分類を1件にまとめる。
- 重要枠は既存の `announcements-data.js` の `migration-file-first-20260914` を利用する。既存のprofile別本文・移行導線・IDを保持し、下記履歴で置換しない。9/16はDiscord上の移行告知日であり、固定案内の9/14を訂正する根拠にしない。
- 重要枠をトップ、ゲームデータを最新1件、サイト更新（feature/fix）を最新3件とする試作案。過去分は追加表示し、記録を削除しない。固定案内が履歴の件数制限・絞り込み・既読処理で消えないようにする。バーの既存閉じる操作の変更は別途設計する。
- `id` は固定識別子。文面修正で変えず、同日の追記は該当項目へまとめる。配列は日付降順、同日内は記載順。`items` は展開時の本文。
- `historicalNotes` は「更新当時の注記」として本文と区別して表示する。現在も同じ制限が存在するという判定ではない。仮対応・βの表記を正式対応へ書き換えない。
- 投稿の「関連」「対応」は対象範囲を推測して補わない。不具合の詳細がない場合も創作しない。
- 予告（9/16の性能改善予定）、雑談、投稿タイトル変更、画像抜けの連絡、共有例の長いURLは除外。6/28のnote記事紹介はサイト更新ではないため除外。告知にない変更は追加していない。
- `source` は出典種別を示す内部メタ情報。投稿者名・時刻などは公開文面に含めない。
- 実装時に既存のお知らせAPIへ合わせて取り込む。以下は現在の `validateArticles` にそのまま渡す形式ではない。既存データへの無条件追加や最新1件の自動選択では、移行案内を押し出す可能性があるため、固定案内と履歴を分けて接続する。
