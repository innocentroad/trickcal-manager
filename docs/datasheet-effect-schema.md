# Datasheet効果新書式

## 対象シート

- スキル基礎設定 / スキル効果
- アサイド基礎設定 / アサイド特殊効果
- 愛用カード基礎設定 / 愛用カード効果
- 教主の権能基礎設定 / 教主の権能効果
- カード効果 / カード特殊効果

カード特殊効果だけは移行途中のため、`条件1`・`条件2`など旧列も読み込む。他の効果シートは新書式を標準とする。

## 実行時条件列

| 列 | 意味 |
|---|---|
| 効果処理グループID | 1回の発動でまとめて処理する効果行の識別子 |
| スタックグループID | 同じ状態・バフとして最大数と期限を共有するスタック枠の識別子（任意） |
| 処理順 | 同じ処理グループ内の適用順 |
| 発動条件種別 | 処理を開始するイベント |
| 発動条件値 | 周期、回数、確率、閾値などイベントの引数 |
| 発動元ID | 行動、生成物、状態、別効果などイベント発生元 |
| 適用条件種別 | 発動後に効果が有効か判定する条件 |
| 適用条件値 | 対象、状態、分岐、性格など適用条件の引数 |

発動条件と適用条件を混ぜない。たとえば「普通攻撃命中時、凍傷状態の敵に追加ダメージ」は、発動条件が普通攻撃命中時、適用条件が対象状態=凍傷となる。

`効果処理グループID`は同じ文章の行を一律にまとめるための列ではない。状態付与→持続時間、ダメージ→デバフ付与など、同一イベントで順序付き処理される単位に付ける。持続時間は同じ値の種類、または処理グループ内で効果行の直後にある持続時間行へ結び付ける。

`スタックグループID`は処理順とは独立している。同じ発動処理に属していても別々にスタックする効果には別IDを使い、別スキル・別行から付与されても同じ最大スタック枠を共有する効果には同じIDを使う。空欄時は状態名・スタック可否・最大スタック数からDPS側が既定グループを作る。既存シートとの互換性のため列自体も任意とする。`スタック集約ID`は同じ列の別名として生成時に受け付ける。

## 生成後のフィールド

```text
効果処理グループID -> processGroupId
スタックグループID -> stackGroupId
処理順             -> processOrder
発動条件種別       -> triggerType
発動条件値         -> triggerValue
発動元ID           -> triggerSourceId
適用条件種別       -> conditionType
適用条件値         -> conditionValue
```

スキル基礎設定の発動条件は効果行と名前が重なるため、生成途中では `skillTriggerType` / `skillTriggerValue` として分離する。`apostles.js`のスキル本体では従来互換の`triggerType` / `triggerValue`へ戻す。

## ダメージ補正区分

効果名だけでは「与ダメージ量増加」と「対象行動の倍率補正」を安全に区別できないため、各効果シートへ任意列`ダメージ補正区分`を追加する。生成後は`damageModifierCategory`として保持する。

| datasheet値 | 生成後 | 計算カテゴリ | 基準値・合成方法 |
|---|---|---|---|
| 与ダメージ量 | `damageAmount` | 与ダメージ係数 | 0%基準。攻撃側与ダメージと防御側被ダメージを加減算し、係数下限20% |
| 行動倍率 | `actionMultiplier` | 行動倍率補正 | 0%基準。同カテゴリ内を加算後、`基礎行動倍率 × (1 + 合計/100)` |
| 特殊 | `special` | 特殊係数 | 100%基準。既存`specialP`へ加算 |
| その他 | `other` | その他係数 | 100%基準。既存`otherP`へ加算 |

`攻撃分類`と`対象スキル`は「どの行動へ適用するか」を表し、`ダメージ補正区分`は「どの計算段階へ入れるか」を表す。たとえば`攻撃分類=低学年スキル`かつ`ダメージ補正区分=行動倍率`なら、低学年の基礎行動倍率だけを補正する。追加ダメージは独立した行動として自身の攻撃分類を持ち、その分類に一致する補正だけを受ける。

`攻撃分類=無分類`は空欄と異なり、発生元から分類を推測しない明示値とする。普通攻撃・強化攻撃・低学年・高学年・状態異常の専用補正は適用せず、汎用与ダメージ、攻撃力、防御、会心、属性相性など分類によらない計算だけを適用する。アヤ愛用品の「小さな雪の花」のような独立ダメージに使用し、同時に付与する凍傷のDoTは別の状態異常ダメージとして扱う。

`ダメージ補正区分`は倍率・固定加算など実際にダメージ値を変更する主効果行へ記入する。持続時間、最大スタック、回数、対象数などの補助行は空欄とし、`processGroupId`で結合した主効果から区分を継承する。

判定の優先順は次のとおりとする。

1. `ダメージ補正区分`の明示値
2. 既存生成キーなど、すでに構造化された互換情報
3. 値の種類による旧データ向け暫定推定

暫定推定では、`ダメージ量増加`、`ダメージ量強化`または`与ダメージ`を含む補正を`damageAmount`候補、`ダメージ増加`または`ダメージ強化`を含み`ダメージ量`を含まない補正を`actionMultiplier`候補とする。ただし、会心ダメージ、被ダメージ、実ダメージ行、回復、追加ダメージ本体は先に除外する。`(その他倍率)`は移行前の互換表記として`other`を維持しつつ、検証時に明示区分未設定の警告を出す。

名称推定だけでExcelを自動書き換えない。候補TSVへ`推定区分`と`要確認理由`を出し、確認後にdatasheetへ反映する。特に`ダメージ量増加(その他倍率)`のように名称と旧補足が矛盾する行は必ず要確認とする。

### 初期移行候補

| 効果 | 暫定区分 | 理由 |
|---|---|---|
| シオンA2 低学年スキルダメージ増加 | 行動倍率 | `ダメージ量`を含まず、現在は`(その他倍率)`で別枠化されている |
| アリスA2 スキルダメージ増加 | 行動倍率 | 同上 |
| リムA2 低・高学年スキルダメージ増加 | 行動倍率 | 同上 |
| ティグ愛用Lv1 普通攻撃ダメージ増加 | 行動倍率 | 同上 |
| モモA2 召喚獣の自爆ダメージ増加 | 行動倍率候補 | 自爆専用行動の基礎倍率を補正する想定だが、特殊係数との境界は要実測確認 |
| アメリアA2・ルポA2 普通攻撃のダメージ量増加 | 要確認 | 名称は与ダメージ量枠、旧補足は`(その他倍率)`で矛盾 |
| 状態異常ダメージ弱点 | その他 | DoT tickにだけ既存`otherP`を加算する仕様が確定済み |

カード特殊効果や教主の権能で`値分類=その他倍率`となっている旧行も、`値分類`を計算カテゴリとして流用せず、新列へ移行する。`値分類`は倍率・固定値・持続時間など値の性質を表す列として維持する。

## 検証と生成

通常の再生成は次を実行する。

```bat
tools\generate-all.bat
```

処理内容は、Excel構造検証、既存生成物のバックアップ、3ファイル生成、生成物の読込検証。Excel構造にエラーがある場合はバックアップ・生成前に停止する。旧条件や列ずれ候補は警告として表示し、既存データの生成は継続する。

生成後は、生成前バックアップとの差分を`tmp/generate-change-<timestamp>.log`へ記録する。値はdatasheetの記述をそのまま生成し、`effectId`、名前、スキルID、発動元ID、適用条件値などの変更は`[NOTICE]`、その他の変更は`[CHANGE]`として出力する。特殊な名前を設定する余地を残すため、差分だけでは生成を失敗扱いにしない。

旧条件から新列への移行候補を作る場合は次を実行する。

```bat
tools\review-effect-schema.bat
```

`tmp/effect-schema-review`へ次を出力する。

- 新列を補完した各効果TSV
- `変換候補.tsv`
- `要確認.tsv`
- `変換集計.tsv`

この処理はExcelを直接書き換えない。候補を確認してからdatasheetへ反映する。

## 現在の実行時対応

- `ダメージ補正区分` / `damageModifierCategory` / `actionMultiplierBonusP`は生成器・単発計算・DPSで利用する。列追加前の生成器へ入力しても分類は変わらない
- ダメージ計算の行動別ON/OFF判定へ発動条件・適用条件を使用
- 編成中、対象使徒、対象性格、対象役割、味方/敵性格、敵配置列、攻撃対象・攻撃元を静的判定
- `付与者=自身`と、リッツの所有者付き目標状態（`Leets_target/付与者=自身`）を静的判定
- 未解決のHP、状態、リソース、ランダム、外部イベント条件は推測でONにせず手動切替可能
- DPSの周期秒、n回ごと、行動開始/終了/命中、攻撃速度、時限ダメージ補正、SP回復へ構造化条件を使用
- 状態付与と持続時間は処理グループを優先して結合

個別状態・生成物・ランダム分岐の完全な時系列処理は、各効果の仕様と発生タイミングが確定したものから追加する。
